## 1. 결론 요약

**[확정]** 서버측 결함이 실재했다. 원인은 정적 경로·MIME·자산 누락이 아니라 **HTTP 요청 속도 제한
예산**이다. IP당 정적 서빙 토큰 버킷이 **버스트 60 · 초당 30** 이었고, 클라이언트가 페이지를 열 때마다
내보내는 **고정 프리로드 집합 45 건**을 간신히 담는 크기였다(여유 15건). 같은 IP 에서 로드가 겹치면
수십 건이 `429` 로 떨어졌다.

**[확정]** 수정은 예산을 그 고정 집합에서 역산한 값으로 올린 것 한 가지다 — `httpBurst 60 → 288`,
`httpReqPerSec 30 → 96`. 제한을 끄거나 정적 경로를 예외로 빼지 않았고, env 설정 표면도 늘리지 않았다.
인증 경계·보안 검사·WebSocket 프로토콜은 손대지 않았다.

**[확정]** 정적 경로 해석기(`resolveStaticPath`)에는 결함이 없었다. PNG·WEBP·JSON·HTML·JS 가 모두
MIME 화이트리스트에 있고 코퍼스 45건 전부가 단독 냉시작에서 `200` 으로 나간다 — "라우트 누락" 가설 기각.

## 2. 증상이 "부분 손실"로 보이는 이유

| 고리 | 근거 |
| --- | --- |
| 클라이언트는 로드마다 **정체와 무관한 고정 집합**을 한꺼번에 요청한다 | `demo/index.html` `artPreload()` — 하수인 20종 × `{icon.png, battle.png}` + 왕·동료 2종 × `{icon64.png, battle256.png}`. 정보 은닉 규격 7.10.3 때문에 일부러 전량을 받는다 |
| 예산을 넘으면 **뒤쪽 요청부터** 429 가 된다 | 토큰 버킷이라 앞쪽은 통과하고 소진된 뒤부터 거부된다 |
| 클라이언트는 그 실패를 **그 종의 영구 실패**로 기록한다 | `im.onerror=()=>{if(f==="icon.png") ART.failed.add(dir);}` · 리더는 `ART.loaded` 에 들어가지 못해 `leaderArtDir`/`leaderBattleDir` 가 계속 `null` |
| 그래서 **늦게 요청된 종·리더만** 이모지로 남는다 | 실측에서 429 가 된 예: `water_atk/icon.png`·`water_def/icon.png` (정렬 뒤쪽), 예산을 더 줄인 변이에서는 `lightning_def/battle.png`·`lightning_std/icon.png` — CJ 가 신고한 번개·리더 누락과 같은 모양 |
| 클라이언트에서 원인을 못 찾는다 | `<img>` 의 `onerror` 는 상태 코드를 주지 않아 **429 와 404 가 구분되지 않는다** |

**[확정]** 서버측 고리(2번)는 실HTTP 로 재현했다. **[확정]** 클라이언트 고리(3·4번)는 `demo/index.html`
코드 근거로 확인했고 Mars 진단과 일치한다 — 브라우저 실측은 Mars 소관이며 이 보고서는 서버 응답까지만
직접 관측했다.

## 3. 재현 — 실제 HTTP · 베이스라인 소스 (old-source negative)

### 3.1 하니스

베이스라인 `ff6e87a` 의 `server/server.js` 를 **그대로** 꺼내 `server/` 안에 일회성 사본으로 두고
띄웠다 — `__dirname` 이 같아야 `../demo` 정적 루트·`./security`·`ws` 해석이 베이스라인과 같다.
측정 후 사본은 삭제했고 `git status` 로 잔존물 없음을 확인했다.

```sh
# 1) 베이스라인 소스를 server/ 안에 일회성 사본으로 꺼낸다
git show ff6e87a:server/server.js > server/__tmp201-baseline-server.js
# 2) 하니스 실행 — 인자: 저장소 루트, server/ 안의 사본 파일명
node <harness.js> "$(pwd)" "__tmp201-baseline-server.js"
# 3) 사본 삭제
rm -f server/__tmp201-baseline-server.js
```

하니스 본문은 `server/test-static-load.js` 와 **같은 코드**다 — 코퍼스 조립(`pageLoadCorpus`),
서버 기동(`startServer`, `PORT=0`·`DD_LAN=0`·`DD_ACCESS_CODE` 주입, 기동 로그에서 포트 파싱),
로드 모사(`loadPage`, 소켓 6개 keep-alive), 남발(`limiterStillFinite` 의 16소켓 루프)을 그대로 쓰고
**기동 스크립트 이름만 인자로 받는다**. 장면마다 새 서버를 띄워 버킷을 가득 찬 상태에서 시작한다.
따라서 재현은 저장소 안의 그 파일을 읽어 그대로 만들 수 있다 — 하니스를 저장소에 남기지 않은 이유는
베이스라인 SHA 의존이 `fetch-depth: 1` 체크아웃에서 깨져 CI 상주 테스트로 부적합하기 때문이다.

코퍼스는 하드코딩하지 않고 실제 자산에서 만든다. `demo/assets/minions` 의 **디렉터리 엔트리만**
센다 (`README.md` 는 종 폴더가 아니다) → 20종 × 2 + 리더 2종 × 2 + `index.html` = **45 건**.

### 3.2 관측값 (실HTTP · 장면마다 새 서버)

| 장면 | 수정 전 (`ff6e87a`, 버스트 60 · 초당 30) | 수정 후 (버스트 288 · 초당 96) |
| --- | --- | --- |
| 냉시작 1명 (45건) | 실패 0 | 실패 0 |
| 같은 IP 동시 2명 (90건) | **429 29건** (`water_atk/icon.png` 등) | 실패 0 |
| 같은 버킷 연속 3회 로드 (135건) | **429 74건** | 실패 0 |
| 남발 600건 | 200 62 · 429 538 | 200 311 · 429 289 |

첫 재현(초기 조사, 한 버킷 안에서 연속 장면 · 코퍼스 45건)에서는 동시 2명 90건 중 **429 가 35·39건**,
이어진 새로고침 2회에서 **45·45건**이었다. 버킷을 공유한 측정이라 위 표(장면별 새 서버)보다 크다 —
두 값 모두 실측이며 조건이 다르다는 점을 구분해 남긴다.

**[확정]** 고장은 실재했고, 수정 후 같은 장면이 전부 통과하며, **남발은 수정 후에도 429 로 묶인다**.

**[미확정]** 브라우저가 반복 로드에서 실제로 전량 재요청하는지(`Cache-Control: no-store` 의 실제 효과)는
확인하지 않았다. "연속 3회 로드" 장면은 **서버가 그 요청량을 받아낼 수 있는지**만 보이며 브라우저 캐시
동작을 주장하지 않는다. 브라우저 실측은 Mars 담당이다.

## 4. 수정 내용

### 4.1 예산 산정

```
pageLoadRequests    = 48   // 45 + 부수 요청(favicon.ico · 설명창 portrait) 여유 3
concurrentPageLoads = 6    // 같은 IP 에서 겹칠 수 있는 로드 수
httpBurst     = 48 × 6 = 288   (종전 60)
httpReqPerSec = 48 × 2 = 96    (종전 30) — 초당 전량 로드 2회분이 회복된다
```

상수는 `server/security.js` 의 `STATIC_BUDGET` 에 두었다. **자산이 늘면 같이 커져야 하는 계약**이라
순수 모듈에 두고 회귀 테스트가 실제 자산 수와 직접 대조한다.

### 4.2 유지한 성질 (제한을 끈 것이 아니다)

- **[확정]** 여전히 IP당 유한한 토큰 버킷이다. 한 IP 가 받을 수 있는 정적 파일은 최대
  `288 + 96 × 경과초`이고, 회귀 테스트가 이 상한을 실측으로 확인한다.
- **[확정]** **인증 경계를 건드리지 않았다.** 이 버킷은 비밀 아닌 데모 파일의 정적 서빙만 다룬다.
  WebSocket 업그레이드는 별도 버킷(`upgradeBuckets`, 분당 60)과 `AttemptLimiter`(5분 10회 실패 시 IP
  차단)가 막으므로 **접속 코드 무차별 대입 노출면은 한 건도 넓어지지 않았다**. `test-security.js` 의
  인증·경로·헤더·한도 검증이 전부 그대로 통과한다.
- **[확정]** 메서드(GET/HEAD)·Host·Origin·URL 길이·경로 이탈·이중 인코딩·숨김 파일·확장자·심볼릭
  링크 검사와 보안 응답 헤더는 한 글자도 바뀌지 않았다.
- **[확정]** env 설정 표면을 늘리지 않았다. 두 값은 고정값이다.

### 4.3 범위에서 뺀 것 (승인 대기 항목이 아니다)

아래는 **이번 HotFix 범위를 최소로 잡아 스스로 뺀 선택**이다. 막혀 있는 일도, 누군가의 승인을
기다리는 일도 없다. 필요해지면 별도 안건으로 다루면 된다.

| 뺀 것 | 이유 |
| --- | --- |
| 정적 경로를 속도 제한에서 예외 처리 | 제한이 사실상 무한해진다 — 채택하지 않는다 |
| `DD_HTTP_BURST`·`DD_HTTP_REQ_PER_SEC` env override | 중간 구현에 있었으나 HotFix 범위를 넘는 설정 표면 확대라 **제거**했다. 그 자리를 잃은 old-source negative 는 베이스라인 소스를 직접 띄우는 방식(3장)으로 대체했다 |
| 429 에 `Retry-After` | 중간 구현에 있었으나 제거했다. `<img>` 의 `onerror` 로는 헤더를 읽을 수 없어 지금의 클라이언트에 효과가 없고, 증명된 수정 범위도 아니다 |
| 정적 이미지 캐시 허용(`no-store` 완화) | 예산 조정만으로 재현된 모든 장면이 해소되므로 건드릴 이유가 없었다. 효과를 주장하려면 브라우저 재요청 실측이 필요하고 그건 Mars 담당이며, 응답 헤더를 바꾸는 일은 이 HotFix 와 독립된 판단거리다 |
| 클라이언트 재시도 | Mars 영역이다. 서버에서는 읽기만 했다 |

### 4.4 남은 위험

**[확정]** 클라이언트가 일시 실패를 영구 실패로 승격하는 고리(`onerror` → `ART.failed`)는 그대로다.
예산을 넘기는 상황이 다시 생기면 같은 증상이 재발한다. 한도 있는 클라이언트 재시도(Mars 진행 중)가
두 번째 방어선이고, 서버 쪽에서는 회귀의 "코퍼스 ≤ 선언 예산" 어서션이 자산 증가를 CI 에서 잡는다.

## 6. 신규 회귀 — `server/test-static-load.js`

| 항목 | 내용 |
| --- | --- |
| 예산 계약 | 실제 자산 디렉터리에서 만든 코퍼스(45) ≤ 선언 예산(48) · 동시 로드 ≥ 2 · 예산이 유한 양수 |
| 정상 로드 | 냉시작 1명(45건) · 같은 IP 동시 2명(90건) · 같은 버킷 연속 3회(135건) 전량 `200`. **장면마다 새 서버**(가득 찬 버킷) |
| 남발은 유한 | 버스트 4배(1152건) → `429` 발생 · 전량 통과 아님 · `200 ≤ 버스트 + 초당회복 × 경과초` |
| 결정적 판정 | 시간 인자를 넣은 제품 `TokenBucket`: 수정 전 예산(60·30)은 동시 2명분 90건 중 **22건 거부**, 수정 후(288·96)는 **0건 거부**. 소진된 버킷은 같은 시각 요청을 거부하고 11ms 뒤에는 한 건을 받는다 |

### 6.1 보완 — 비결정적 어서션 제거 (`task_e91749c3626c`)

초기 구현에는 "남발 직후 다음 한 건은 반드시 `429`" 라는 실HTTP 어서션이 있었다. **[확정]** 이는 경합이다 —
마지막 응답과 다음 요청 사이에 `1/96초 ≈ 10.4ms` 만 흘러도 토큰 하나가 정당하게 회복돼 그 요청이 `200`
이 된다(OS 스케줄링에 좌우됨). 같은 성질을 **시간 인자를 직접 넣은 제품 `TokenBucket`** 으로 옮겨
결정적으로 확인하고, 실HTTP 쪽 근거는 집계 상한에 맡겼다. 정상 로드 어서션은 손대지 않았다.

### 6.2 요청 수명 상한 (Saturn P2 · `task_e91749c3626c`)

초기 구현의 `get()` 에는 요청 마감이 없어, 응답이 끊기면 회귀가 무한정 매달릴 수 있었다(런타임 변경은
없음 — 테스트 전용 결함). 요청마다 `timeout: 10000` 을 걸고 `'timeout'` 에서 직접 소켓을 끊으며,
단일 정착 가드(`settled`)로 `response`·`'timeout'`·`'error'` 중 먼저 온 것만 결과가 되게 했다.
마감에 걸린 요청은 조용히 빠지지 않고 **실패(`status 0` · `err:'timeout'`)로 확정**된다 — 빠져 버리면
"실패 0건"이 거짓으로 통과한다.

**[확정]** 배포되는 코드 텍스트를 파일에서 그대로 떼어 내 eval 하고(상수만 400ms 로 낮춤), 연결만 받고
응답하지 않는 침묵 TCP 서버를 상대로 실행했다 → `{status:0, err:"timeout"}` 으로 **410ms 에 정착**.

`server/server.js` 불변 확인) 변이 검출력을 실측했다.

| --- | --- |
| 없음 (제품 `server.js`) | 남발 1152건 0.28s → 200 **314** · 429 838 · 상한 317 → 어서션 3개 **전부 PASS** |
| **M1** — `server.js` 의 HTTP 속도 제한 분기 무력화 | 남발 1152건 0.69s → 200 **1152** · 429 **0** → 어서션 3개 **전부 FAIL** |
| **M2** — `TokenBucket.take` 가 항상 `true` | 결정적 소진 어서션 **FAIL** |

즉 제한을 끄는 변이는 집계 상한에서, 버킷 자체를 무력화하는 변이는 결정적 어서션에서 잡힌다.

모든 자식 서버는 `PORT=0`(임의 포트) + 루프백 바인드로 띄우고 끝나면 닫는다 — 떠 있는 운영
서버(8080)를 건드리지 않는다. **[확정]** 실사용 서버 재시작·설정 변경·자격 증명 노출은 없었다.

## 8. 인수인계

- **[확정]** 서버는 안정 상태다. Mars 의 2브라우저 실측은 `server/` 에서 `npm start`(루프백) 또는
  `npm run start:lan` 으로 띄우면 된다 — 예산 288/96 이 적용돼 있다.
- **Saturn 검수 경로 (READ_ONLY · 파일 쓰기 0)**: `git diff` 로 `server/server.js`(두 상수)·
  `security.js`(`STATIC_BUDGET`)·`package.json`·`README.md` 와 신규 `test-static-load.js` 를 읽고,
  예산 산식은 파일을 쓰지 않는 메모리 검증으로 대조하면 된다 — 예:
  `node -e "const S=require('./server/security');console.log(S.STATIC_BUDGET)"` (의존성 설치 불필요,
  `security.js` 는 `crypto`·`fs`·`path` 만 쓴다). **`npm ci`·테스트 실행·상수 수정은 Saturn 몫이 아니다**
  (`node_modules` 생성·파일 변경이 동반된다). 실행이 필요한 검증은 전부 구현자(Jupiter)가 이미 돌려
  7장에 결과를 남겼고, 추가 실행이 필요하면 Mercury 를 통해 구현자에게 요청한다.
- PD 확인 요청: 6장 CI 상주 negative 를 버킷 수준으로 둔 판단(실서버 옛 예산 기동 경로를 만들지
  않기 위한 선택)과, 4.3 표에서 스스로 범위에서 뺀 항목들이 이번 HotFix 범위로 적절한지.
- Git·GitHub·Notion 기록은 Mercury 소관이다. 이 dispatch 에서는 커밋·푸시·이슈 코멘트를 하지 않았다.
