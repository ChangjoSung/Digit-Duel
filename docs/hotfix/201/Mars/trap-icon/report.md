## 고친 것

종전에는 함정을 이모지 🪤(U+1FAA4)로 그렸다. 이 글리프가 설치 폰트에 없는 환경(실측: Windows 10 19045 · Chrome)에서는 `glyphOk()`가 거짓을 돌려주고 같은 뜻의 **"함정" 글자**로 되돌아갔다 — v0.4.8 README 보드에서 함정만 글자로 보인 원인이 그것이다. 이번에는 그 글자 폴백을 타지 않고 **문서 안에 직접 그린 벡터 도형**을 쓴다. 폰트 커버리지와 무관해지고, 인라인이라 새 HTTP 요청·캐시·실패 경로도 생기지 않는다.

중앙 렌더 경로 하나(`glyphSpan`)에 도형을 물렸으므로 **확정 표시·배치 트레이·추측 격자·추측 목록이 같은 도형**을 쓴다. 한쪽만 이모지로 갈라지는 일이 없다.

| 자리 | 종전 | 지금 |
| --- | --- | --- |
| 보드 · 배치 트레이의 내 함정 (`pcFaceHtml` → `glyphSpan`) | 🪤 또는 "함정" 글자 | 전용 도형 32×32 |
| 상대 말 추측 메모 — 보드 물음표 자리 (`glyphSpan(...,"guess")`) | 🪤 또는 "함정" 글자 | 같은 도형 22×22 · 점선 반투명 유지 |
| 추측 선택 격자의 함정 버튼 (`memoModal`) | 🪤 | 같은 도형 22×22 + 기존 "함정" 라벨 |
| 사이드 패널 추측 목록 (`renderSide`) | 🪤 | 같은 도형 14×14 + 기존 "함정 추측" 문구 |

`MEMO_OPTS`의 기호 어휘(`emoji:"🪤"`)·저장 키·접근성 라벨 문구는 **하나도 바꾸지 않았다**. 바뀐 것은 그 기호를 무엇으로 그리는가뿐이다. 도형이 없는 나머지 7종은 종전 이모지 계약과 #89 글자 폴백을 그대로 쓴다.

### 일부러 범위 밖에 둔 것 (조정자 승인)

튜토리얼 그림의 🪤, `.cell.fx-trap::after`의 연출 이모지, 함정 발동 토스트 문구는 **손대지 않았다**. 조정자가 "board-icon fix"로 범위를 못 박았고, 튜토리얼 본문·사진을 보존하라는 지시가 있었다. 그 자리들에서는 종전 동작(글리프가 없는 환경이면 두부)이 그대로 남는다 — 숨기지 않고 여기 적어 둔다.

규칙·RNG·네트워크·서버·Unity·Roblox는 건드리지 않았다. #201에서 되살린 왕·동료·하수인 아트 복구도 그대로다(아래 3G·5B에서 같은 화면으로 확인).

## 검증

### 헤드리스 (`node demo/test/regression/smoke_trap_icon.js` — 42/0)

- **A 원본↔인라인 일치**: 두 쪽의 `path`·`circle`을 순서대로 뽑아 **좌표와 칠(fill·stroke·stroke-width·linejoin·linecap)** 을 모두 맞춘다. viewBox가 양쪽 다 `0 0 32 32`인지 먼저 확인하고(A2·A2b), 추출값이 빈 문자열이 아닌지 못 박은 뒤(A3b·A3c), 좌표만 바꾼 자산과 **색만** 바꾼 자산이 각각 검사기를 통과하지 못함을 같은 파일에서 증명한다(A5·A5b).
- **B 폰트 독립**: `glyphOk`가 참일 때와 거짓일 때의 마크업이 **완전히 같다**(B3) — 렌더가 폰트 지원 여부를 아예 보지 않는다. 도형이 없는 왕은 종전 글자 폴백 그대로(B5), 폭탄은 종전 이모지 그대로(B6), `memoEmoji("trap")`은 여전히 🪤(B7).
- **C 네 자리 일치**: 보드·배치 트레이·추측 격자·추측 목록이 모두 같은 도형이고, 함정에 HP 정보 행이 생기지 않으며(C2), 접근성 라벨 문구는 종전 그대로(C5).
- **D 은폐 불변식**: 미공개 상대 함정은 물음표이고 그 칸 DOM에 도형·`data-sym`·"함정"이라는 말이 없다. 공개되면 같은 자리에 도형이 나오는 **양성 대조**(D6)로 "아무것도 안 그려서 통과"를 배제한다. 숲(4행) 은폐는 `visibleTo`가 거짓임을 전제로 확인하고(D7a·D7b), 내 말이 인접하면 보이는 양성 대조(D7d)와 "보여도 미공개면 도형이 아니다"(D7e)를 함께 둔다.
- **E 새 요청 없음**: `src=`·`url()`로 심볼 자산을 부르지 않고(E2), 출처는 주석으로만 남긴다(E2b).

기존 스위트 전체도 초록이다: `smoke_memo` 122/0 · `smoke_minion_art` 208/0 · `smoke_online_art` 101/0 · `smoke_turnflow` 203/0 · `smoke_issue146` 212/0 · `smoke_search_packages` 299/0 · `smoke_orientation_audit` 8914/0 · `smoke_ai_completion` 59/0 외 전 파일 0 실패.

### 실브라우저 (`node demo/test/hotfix/201/trap_icon_cdp.js` — 38/0)

내가 띄운 루프백 서버(임의 포트·이 실행 전용 접속 코드)와 내가 띄운 헤드리스 Chrome 임시 프로필에서, 독립된 두 탭이 **실제 로비 입력·버튼 클릭**으로 온라인 매칭에 들어가 로스터 6종 선택·배치를 마치고 보드까지 갔다. 사용자의 서버는 건드리지 않았고 종료 시 내가 띄운 PID와 내가 만든 프로필 경로만 정리했다.

- **2A** 그 브라우저에서 제품 자신의 측정기로 실측한 결과 🪤 글리프가 **실제로 없다**(`glyphOk("🪤")===false`). 💣·👑은 있다(2B) — 문제는 폰트 전반이 아니라 이 글리프 하나였다는 종전 진단이 같은 실행에서 재확인된다.
- **3B~3F** 그럼에도 두 좌석 모두 내 함정 2개가 전용 도형으로 그려졌다. `getBBox`가 27×26으로 0이 아니고 도형 요소 9개가 남김없이 있으며, `display`·`visibility`·`opacity`가 보이는 상태다. '함정' 글자 폴백도 `<img>`도 없다.
- **3C·3C2** 보드는 세로 화면 맞춤으로 `--bs`만큼 축소돼 그려지므로(#122) 절대 픽셀 32를 요구하지 않는다. CSS 상자가 계약값 `32px`이고, 실제 그려진 크기가 **같은 보드의 하수인 아이콘과 정확히 같다**(함정만 크거나 작게 튀지 않는다).
- **4A~4F** 두 좌석 모두 상대의 미공개 함정이 실제로 판에 있는 상태에서(4A), 상대 말 칸 어디에도 도형·`data-sym`·자산 경로·"함정"이라는 말이 없고 보이는 상대 말 14/14가 전부 물음표다. 같은 보드에 **내** 함정 도형은 있다(4F 양성 대조).
- **5A·5B** 기호 자산(.svg·/symbols/) HTTP 요청 0건, 자연 발생한 자산 실패 0건 — 이번 변경이 새 요청을 만들지 않았고 기존 아트 로드도 깨지 않았다. 하수인 아트 6/6 정상(3G).
- **6A** 두 좌석 모두 촬영 전에 배너·연출·토스트가 완전히 걷혔다.
