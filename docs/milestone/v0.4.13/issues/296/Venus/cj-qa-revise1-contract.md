## 0. 한 문단

방송 중계에 비유하면, 이번 수정은 **화면 배치를 고정하는 일**입니다. 지금은 선수를 누를 때마다 자막 버튼이 생겼다 사라져 경기장(말판) 크기가 출렁입니다. 앞으로는 버튼을 **한 자리에 늘 두고** 켜고 끄기만 합니다. 전투 화면은 위쪽 빈 공간 없이 맨 위에 붙고, 두 선수 카드는 같은 모양이 됩니다. 도망 · 포획 · 가방 창은 설명 문단을 빼고 **질문 한 줄 + 실행 버튼 + 그 창 안의 '돌아가기'** 만 둡니다. 싸우기 창도 가방처럼 머리줄 오른쪽 위에 같은 '돌아가기'를 두고, 바깥 '← 뒤로'는 네 창 어디에도 없습니다. 기술표는 메인 화면 하수인 정보 창의 기술표를 **같은 부품으로** 다시 씁니다. 규칙 · 수치 · 확률 · 시계 · 통신은 하나도 바뀌지 않습니다.

- [확정 · 현행 보존] 실제 사용 가능 여부(`battleSlotOk` = 서버 `usable` 우선) · 쿨 · 봉인 · 조건 불가 · 공격 없음(`noAtkShow` → `턴 종료`) · 추가 공격(`inBonus`) · `window.__act(i)` 입력 가드는 그대로입니다. 불가 줄은 짧은 상태 칩(`쿨 N` · `봉인` · `불가`)으로 보이고 긴 사유(봉인 이유 · 다른 속성 판정 · 분류)는 툴팁에 둡니다. 색만으로 구분하지 않습니다.
- [범위] 왕 · 동료 본체(스킬 목록 없음)의 기본 공격 버튼 경로는 그대로입니다.
- [확정 · CJ 후속 지시] 싸우기 창 머리줄은 가방과 같은 모양입니다: 기존 머리줄 글자 `⚔️ 싸우기` + 오른쪽 위 `↺ 돌아가기`(2장). 기술표 · 잠긴 소개는 위 그대로입니다.

## 2. 네 하위 창의 '돌아가기'

- [확정 · CJ 그림 2~5] 도망 · 포획 · 가방은 바깥 전체 폭 '← 뒤로'를 지우고 **각 하위 창 안의 `↺ 돌아가기`만** 둡니다(가방은 오른쪽 위, 포획 · 도망은 실행 버튼 옆).
- [확정 · CJ 2026-10-03 후속 지시 '싸우기도 내부 복귀 버튼으로 통일해주세요'] **싸우기도 안쪽 `↺ 돌아가기`만 둡니다** — 가방처럼 머리줄(`subHead`) 오른쪽 위에 같은 버튼(`subBack`)을 쓰고, 바깥 전체 폭 '← 뒤로'(`#bmenuBack`)는 화면에서 없앱니다. 네 창(싸우기 · 가방 · 포획 · 도망) 모두 바깥 '뒤로'가 없고 같은 자리에 두 개가 겹쳐 보이지 않습니다. 새 글자 · 새 스타일 · 새 동작은 없습니다.
- ~~[확정 · CJ 그림 6/7 · Mercury 최종 선택] 싸우기는 현행 바깥 전체 폭 '← 뒤로'(`#bmenuBack`)를 그대로 둡니다. 싸우기에는 안쪽 돌아가기를 새로 만들지 않습니다.~~ — 이 계약 첫 판(2026-10-03 · `ctx_0622feb4288c`)의 기록이며 위 후속 지시로 **대체**됐습니다.
- [확정 · 현행 보존] 네 창의 돌아가기는 기존 `window.__menu(null)` 하나를 부릅니다. **통신 프레임 0 · 게임 행동 0** · 규칙 상태 무변경 · 행동 미소모입니다.
- [추론 · 구현 확인 대상] 재생 · 비활성 화면에서 `#bmenuBack`만 눌리게 남겨 두던 예외(`network.js`의 버튼 잠금 제외)는 싸우기의 안쪽 돌아가기에도 같은 결과(메뉴 복귀만 가능 · 전송 0)가 나와야 합니다. 방법은 Mars가 정합니다.
- 비활성 사유는 긴 글 대신 아이콘 + 접근성 이름/툴팁으로 둡니다.

## 3. 바뀌지 않는 것

전투 · 피해 · 쿨타임 · 확률(도망 30/70% · 포획 70%) · 라운드 · 60초 시계 · 아이템/버프 제한 · 포획 조건 · 서버 프로토콜 · 공개 범위(GDD-23 7.9 · GDD-24 00.7). 새 의존성 · 프레임워크 · 밸런스 · 서버 변경은 없습니다. 서버 데이터가 실제로 모자라면 Mars는 서버를 건드리기 전에 PD에게 묻습니다.

## 4. 수용 기준

1. **메인 칸**: 320 · 390 폭에서 상대 차례 / 내 차례(선택 없음 · 하수인 선택 · 하수인 아닌 말 선택)의 말판 · 시너지 열 · '하수인 정보' 칸 · 행동 줄 위치와 크기가 같다. 칸 글자는 늘 `하수인 정보`이고 종 이름이 보이지 않는다. `#turnBar`에 정보 버튼이 없다. 상대 차례 탭은 바로 정보 창, 내 차례는 칸으로 연다. 열기는 통신 0.
2. **전투 위치**: 전투 창의 상단 한 줄이 프레임 위 끝에 붙고 그 위에 말판이 보이지 않는다. 상단 한 줄은 하나이고 감정표현 · 설정이 동작하며 차례 줄이 가려지지 않는다.
3. **선수 카드**: 두 카드가 같은 줄 구성이다(이름 + 아이콘 배지 2개 / `현재/최대(+방어막)` / 6스탯 3×2 / 상태 칩). 숫자는 실제 HP · 방어막 · 6스탯이며 상대 쪽에 `?` · 지어낸 0 · 스킬이 없다. 피해 · 방어막 연출 뒤에 `hptxt-` · `shtxt-` · `bst-` 값이 맞게 바뀐다.
4. **도망**: 질문 한 줄 + 도망(성공%) + 돌아가기만 보이고 설명 문단이 없다. 확률 · 비활성 조건은 현행과 같다.
5. **포획**: 가능/불가 두 화면이 그림 3/4와 같은 구성이다. 칩 색이 실제 HP 조건 · 볼 수와 맞다. 각 `ballWhy` 사유가 잠긴 버튼의 접근성 이름/툴팁으로 읽히고 확률은 권위 값이다.
6. **가방**: 3열 타일 · 두 묶음 · 실제 `×N`. 묶인 타일이 실제 인덱스로 `__useItem`을 부른다(같은 종류 여러 개 · 서로 다른 종류 섞인 경우). `itemRound` · 버프 제한이 비활성으로 보인다. 상대 차례/상대 화면에 개수가 없다.
7. **싸우기**: 전투 기술 목록과 정보 창 기술표가 같은 함수에서 나온 같은 마크업(`ol.uhSkills` · `span.uhSk` · 칩 · `small`)이다. 잠긴 소개가 보이고 누를 수 없다. `dmgRange` 호출 · `a~b` · `0~0`이 없다. 불가 · 쿨 · 봉인 줄은 눌러도 전송 0, 사용 가능 줄만 기존 행동을 보낸다.
8. **돌아가기**: 싸우기 · 도망 · 포획 · 가방 네 창 모두 안쪽 돌아가기만 있고 바깥 '← 뒤로'가 보이지 않는다(싸우기는 가방처럼 머리줄 오른쪽 위). 누르면 통신 프레임 0 · 게임 행동 0.
9. **보존**: 같은 입력의 전투 결과가 같다. 표시 문자열 · 선택자 외 기대값을 낮추지 않는다. `#bmenuBack`을 보던 기존 회귀(싸우기 포함)와 도망 · 포획 · 가방 경로 · 행동 줄 정보 버튼을 보던 회귀는 새 위치(안쪽 돌아가기 · 고정 칸)로 **옮기되** 검사 강도를 줄이지 않는다.
10. **모바일**: 320 · 390 · PC 프레임에서 가로 넘침 없음 · 겹침 없음 · 누르는 곳 44px 이상을 대표 화면 1회씩 대조한다. CJ 그림 7장과 실제 렌더를 화면별로 나란히 본다(QA_MINIMUM_POLICY의 시각 REVISE 규칙).

검증은 [QA_MINIMUM_POLICY](../../../../../creat2ve/QA_MINIMUM_POLICY.md)를 따릅니다: 기존 검사에 좁은 단언 추가 · 관련 회귀와 필수 CI 6개는 변경 뒤 각 1회 · 네트워크 반복 수동 검사 없음.
