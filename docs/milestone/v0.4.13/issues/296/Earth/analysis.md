## Boundaries, differences, and verification

1. **Narrow battle disclosure.** The latest CJ sketch explicitly annotates `상대도 공개` and points to the opponent panel. Read it as a combat-only disclosure of six current combatant stat fields—attack, defense, speed, dodge, critical rate, and status-application chance—in 3×2, for both currently revealed combatants. This narrowly supersedes the older GDD opponent-stat privacy rule for those six displayed values; it does not authorize hidden board-piece identities, grades, unused skills, inventory, exact/raw synergy internals, or the opponent's action timer. Values not supplied by the approved combat view remain `?`; do not infer them from hidden/default data. Jupiter is independently reviewing transport/Core evidence, so this art pass adds no server fields or changes.

2. **Battle panel vs #294 detail.** The battle sketch places six cells (3×2) below the live HP/current-shield line. #294's owner detail remains eight cells (4×2), including HP and **starting** shield percentage. Keep the contexts separate: no duplicate HP cell or confusion between live and starting shield in the battle panel; do not change the eight-cell help view.

3. **Timer and synergy ownership.** `44초` is a sketch example. Current battle action time is 60 seconds for the acting owner; the other player sees neutral waiting, not that clock. Do not expose or create an opponent timer from the board-clock exception. Current battle synergy chips are owner-only; the opponent's exact synergy stays hidden and active effects remain visible through statuses/log. The first-line personal synergy request should reuse an approved owner-visible effect; it must not reveal raw synergy internals.

4. **`0~0` report — static cause, not a rule change.** Read-only path inspection matches the existing Mars analysis: server `_serializeBattle()` omits `atk`; `netSynthFighter()` cannot reconstruct it for some online legendary/replacement combatants; `effAtk()` can turn missing `atk` into zero, and `dmgRange(0)` formats `0~0`. This is a candidate online display-data defect, not evidence of changed server damage. Preserve the distinctions between a missing value (`?`), a skill with no power range, and an actual zero-damage result; do not label every `0~0` intrinsically erroneous without reproduction. This has not been reproduced in a running product here, so mode/actor reproduction and actual-hit comparison remain implementation/QA evidence. Keep all balance, witch stats, skill effects, cooldowns, turn and damage rules unchanged.
