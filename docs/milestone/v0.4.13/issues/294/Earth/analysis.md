## 확정 — 보존해야 할 것

- CJ 승인된 목표는 메인 흐름과 #293 shop/place/done의 공통 identity다. 최대 12자 이름을 표시하고 충돌 없이 전체 이름에 접근할 수 있어야 한다. 잘못된 대표 ID를 `lobbyRepHtml`에 그대로 넘기면 기본 로스터 외형으로 대체되므로, identity 미확인 시에는 중립 표시를 먼저 적용해야 한다.
- 준비는 공통 서버 마감 **180초** 한 개다. 상점→배치→완료에 시계를 재시작하지 않는다. 일반 보드의 단절 정지와 준비 시계의 계속 진행을 혼동하지 않는다.
- 로스터·가격·등급·HP·경제·입력 잠금은 현행값. #293의 등급 배경, 왕/동료 무등급·무아키타입, 사망 표시, 준비 취소 위치를 보존한다.
- `synCount`는 배치된 필드 하수인 6+왕1+동료2를 집계하며 사망 칸도 기여한다. 일반 가방은 왕국/아키타입에 기여하지 않는다. 가방 전설은 기존 아키타입 예외만 적용된다. 개인 전설 칩은 `synExtraView`의 살아 있는 필드 전설·실제 활성 효과 조건을 따른다; 가방 전설의 아키타입 기여와 개인 효과 활성은 다른 의미다.
- 왕관은 죽은 동료 수 0–2와 기존 추가 기술(동료의 복수/왕의 분노)의 표시다. 계정 대표/전체 사망 수/새 보상/새 시너지로 바꾸지 않는다. `synView.dead`는 사신용 하수인+동료 사망 수이므로 왕관 숫자에 쓰지 않는다.
- 전투 중 시너지는 참전 확정 순간 스냅샷. 목록과 현재 보드 계산을 섞어 전투 중 수치가 바뀐 것처럼 보이지 않게 해야 한다. 적 시너지 총계·가방·개별 상점/선택·미공개 외형은 표시 대상이 아니다.

## 제안 — 화면 구현자에게 전달할 시각 선택

- identity 한 줄과 도구/상태 줄을 분리해 320px에서도 얼굴 두 개와 VS를 유지한다. 내/상대는 좌석 번호가 아닌 뷰어 상대 관계이며 파랑/빨강과 텍스트를 함께 쓴다.
- 세로 rail은 왕국5+아키타입6+왕관+조건부 개인 전설 전체를 읽을 수 있는 독립 스크롤. 작은 화면에서도 44px 터치 영역을 확보한다.
- dock을 모바일 3열×2행으로 재배치한다. 상점에는 `N턴 후 열림`, 최종 상점 이후에는 `예정 없음`을 직접 표시한다. 기존 계산 `다음 ECO.shopTurns - S.turnCount`를 그대로 사용한다.
- 가방 3카드, 실제 아이템 8종 목록, 상세와 명령의 명시적 분리. 긴 이름·설명과 단계 목록은 팝업 내부 스크롤로 처리한다.
- 본 SVG의 숫자/명칭은 시각 샘플이다. 서로 다른 상태 패널은 하나의 실제 경기 스냅샷을 주장하지 않는다.

## 미확정 / Venus·Jupiter에 필요한 계약

1. **상대 보드 시간 공개**: 공개 clock의 허용 단계, 주체, 정지·만료·재연결 시 표시 필드와 값이 필요하다. `_clockView`에 상대 상점/전투 입력 시간까지 통째로 공개하면 안 된다. 계약 전 시안은 `상대 차례 · 시간 확인 중` 중립 상태를 사용한다. 새 클라이언트 30초 타이머를 만들지 않는다.
2. **상세의 공개 범위**: 준비/상점/보드/전투 각 맥락에서 읽을 수 있는 상대 이름·종·등급·HP·기술의 필드별 계약을 Venus가 확정해야 한다. `revealed`만으로 HP나 기술 전체 공개를 추정하지 않는다. 전투 대리인의 외형과 본체 HP도 구별한다.
3. **기여 목록 일치**: 현재 UI `synContrib`와 `synView`는 상점 미리보기/보드/전투 스냅샷의 선택 근거가 다르다. Mars/Jupiter가 현재 표시 수치와 같은 승인된 데이터 원천으로 기여 명단·사망/가방 표시를 맞춰야 한다. Earth는 새 집계 규칙을 정하지 않는다.

이 세 계약은 최종 구현 승인 입력이다. 첫 시안 작성 자체는 코디네이터 GO 범위이며 Venus 확정 전에 제품/QA 완료로 표시하지 않는다.
