# #294 main + #293 shared identity — visual proposal

2026-10-02 · Earth · **제안 납품, 제품/QA PASS 아님.** [분석](analysis.md)을 먼저 완료했다. [편집 SVG](main-flow.svg)와 [미리보기](main-flow-preview.png)는 수치 예시를 담은 정적 디자인 보드다. 확정 규칙은 CJ 원본·#293 계약·현행 데이터에 따르며 아래 규격은 표시 계층 제안이다.

## 1. 치수와 화면 골격

SVG의 320/390 프레임은 CSS px와 1:1이다. 데스크톱 예시는 1100×1000 viewport 안에 432px 게임 프레임을 중앙 배치한다. 보드를 가로로 늘려 7열 구조를 바꾸지 않는다.

| 항목 | 320px | 390px | desktop 1100px |
|---|---:|---:|---:|
| 게임 프레임 | 320 | 390 | 432 (중앙) |
| 바깥 좌우 패딩 | 8 | 8 | 8 |
| identity 행 / 도구 행 | 52 / 44 | 52 / 44 | 52 / 44 |
| 상태 네 칸 | 각 73×48, gap4 | 각 90.5×48, gap4 | 각 101×48, gap4 |
| 보드 / rail / 간격 | 254 / 44 / 6 | 324 / 44 / 6 | 364 / 44 / 8 |
| 보드 셀 / 높이 | 36.286 / 471.714 | 46.286 / 601.714 | 52 / 676 |
| 하단 dock | 3열×2행, 각 98.67×48, gap4 | 3열×2행, 각122×48 | 3열×2행, 각136×48 |
| 일반 팝업 최대 폭 | 304 | 374 | 560 |

- 상단 identity/상태와 dock은 게임 프레임 기준으로 붙고, 중앙 보드 영역은 세로 스크롤할 수 있다. 작은 높이에서 13행을 숨기거나 폰트를 축소해 맞추지 않는다. dock 높이+safe-area만큼 스크롤 끝 여백을 확보한다. rail은 중앙 영역 높이 이내에서 별도 세로 스크롤, 마지막 항목까지 도달 가능해야 한다. 스크롤바/하단 더 보기 표시를 둔다.
- 320 보드 셀은 44px보다 작으므로 셀 터치 영역을 겹치게 늘리지 않는다. 기존 선택 강조·키보드 탐색과 선택 상세(44px)를 보존하고, 확대가 필요한 접근성 모드에서는 같은 셀 크기 비율로 보드를 확대·스크롤한다. **버튼/카드/칩/닫기/설명 진입은 최소 44×44**. 모바일 보드 셀의 물리적 제약은 구현 검수 대상으로 명시한다.
- 4–5/9–10행 수풀, 진영과 중앙 구역, 좌석별 보드 반사·숨은 말 `?`/추측 메모를 그대로 유지한다. 시안에는 구조 확인을 위해 빈 보드를 표시했다. 실제 말은 #293의 왕국 좌상·아키타입/역할 우상·기존 초상 중앙·현재 HP 하단 구성, 등급 불투명 배경을 유지한다.
- 글꼴 `Malgun Gothic, Apple SD Gothic Neo, sans-serif`. 본문14/줄높이20, 보조12/18, 헤더16/22, HUD 숫자18/22. 숫자 tabular-nums. 이름은13/18, 작은 단계 표식 라벨12. 11px 이하에 필수 의미를 맡기지 않는다.

## 2. 양측 계정 identity (메인 + #293 전 구간)

identity 행은 `[내 대표 32×32][나·이름] [VS 24px] [상대 대표 32×32][상대·이름]`. 좌우는 같은 가변 폭, 내부 gap4, 바깥8. 초상·VS는 줄어들지 않으며 이름만 min-width0 한 줄 말줄임. 툴바는 다음 행: 왼쪽 현재 단계/주체, 오른쪽 기존 감정표현과 설정 44px씩. 긴 이름 두 개+12자 한글, 한쪽 누락, 중립 fallback에서도 영역이 겹치지 않는다.

- 이름은 검증된 공개 `NET.players`/기존 오프라인 이름 원천. 최대12자 정책은 계정 계약 그대로; 시각 때문에 원본 값을 잘라 저장하지 않는다. 전체 이름은 각 identity의 접근성 이름과 44px 정보 트리거로 열리는 읽기 전용 표식에 노출한다(hover에만 의존하지 않음). 마크업은 텍스트로 이스케이프하며 secret ID/토큰을 fallback으로 쓰지 않는다.
- 대표는 검증된 `NET.reps`/공개 계정 대표 선택. `lobbyRepOk` 같은 허용목록 검증 후 `lobbyRepHtml`/`artDirOf` 자산 매핑을 재사용한다. 작은 헤더는 해당 종 `icon.png`, 큰 대표 표식은 같은 종 `portrait.webp`를 쓸 수 있다. **대표 하수인을 왕/동료로 대체하지 않는다.** 초상 주위 왕관/HP/등급 표식도 붙이지 않는다.
- missing/malformed 대표: 중립 profile 아이콘 또는 `?`, 회색 선. missing/malformed 이름: `나`/`상대` 또는 `플레이어`처럼 관계만 표시. 잘못된 ID에 임의 기본 하수인을 그려 실제 선택인 것처럼 보이지 않는다. 정상 identity의 self/opponent 테두리는 항상 뷰어 상대 기준; 좌석0=내 색으로 하드코딩 금지.
- 내 테두리2px `#5b8cff`, 상대2px `#ff5b6e`, 중립2px `#8a93a8`. `나`/`상대` 텍스트를 함께 표시해 색에만 의존하지 않는다. 초상 바탕 `#0b1a3c`, radius6.
- #293 shop/place/done 모두 같은 identity 행을 사용한다. 툴바에 준비 남은 시간과 내 코인, 설정 진입을 보존하고, 그 아래 `01 상점 / 02 배치 / 03 완료`와 기존 진행/준비 취소 버튼(최소44×44)을 둔다. 추가 높이는 콘텐츠 스크롤에서 흡수한다.
- 단계 표식도 동일 대표 종과 관계 색을 사용 가능: 20px 그림+`나/상대`, 터치가 필요한 경우44px 표적. 같은 단계의 두 표식은 2칸으로 나란히 배치(겹침 금지). 단계는 `NET.steps/seats.step` 등 승인 원천만; 상대 미확인은 해당 단계에 추정 배치하지 않는다.
- 완료 상태의 불투명 `준비 완료 · 상대 기다리는 중…` 팝업은 준비 시간/단계/우상단 준비 취소를 가리지 않는다. 공통180초는 완료 뒤에도 유지하고 단계 변경으로 재시작하지 않는다.

## 3. 공용 팔레트·상태

| 토큰 | 값 / 사용 |
|---|---|
| 배경 / 패널 / 내부 패널 / 선 | `#12151c / #1c2130 / #242b3d / #333c52` |
| 프레임 / 경계 | `#0b1a3c / #2f7fe0`, 기존 남색 UI |
| 본문 / 보조 / 성공 / 위험 | `#e8ecf5 / #8a93a8 / #4fd88a / #ff5b6e` |
| 보드 진영A / B / 수풀 / 중앙 | `#2a3350 / #502a33 / #1f3a2a / #2a2f3d` |
| 등급1–5 불투명 배경 | `#ffffff / #bce2cf / #376bce / #7651a8 / #c89c3c` (#293 그대로) |
| 시너지 미달 / 단계1–5 | `#d7d2c9 / #b8754a / #9ea9b7 / #c99b39 / #376bce / #7651a8` |
| 선택 / 포커스 | 기존 `--pick #e8907a` 2px+`선택`; focus-visible 흰색3px |

시너지 색은 **집계 칸 수가 아닌 달성 단계 순위**. 본문은 밝은 잉크와 어두운 불투명 패널로 표시한다. 등급1/2의 HP 글자는 어두운 잉크(`#12151c`), 등급3/4는 흰색, 등급5는 어두운 잉크를 쓴다. 사망은 등급색을 덮지 않고 `사망` 불투명 배지와 실제 HP; 비활성 행동은 회색 경계+비활성 사유, 필수 글자 전체 opacity를 낮추지 않는다. 선택·포커스·활성 시너지·사망은 별개의 상태다.

## 4. HUD와 행동 dock

- HUD 순서: **남은 시간 / 현재 턴 / 내 코인 / 전투 사용 횟수**. 작은 아이콘+명칭12px+값18px. 마지막은 `사용/2`; 상대 경제값을 가져오지 않는다. 상태 주체는 위 도구 행에 `내 차례`/`상대 차례` 등 텍스트로 구분한다.
- 공개 보드 시간은 Venus/Jupiter 계약 대기. 제안 상태: 정상=`23초` 같은 승인값, 정지=`정지 · 23초`, 만료=`0초 · 처리 중`, 미수신=`확인 중`, 종료=`종료`. 부가 문구는 HUD 아래 상태줄에 두어 숫자칸을 깨지 않는다. 준비는 공통 서버180초; 일반 단절 정지와 다른 정책을 유지한다. 클라이언트가 상대의 새 타이머나 만료 액션을 생성하지 않는다.
- 미래 Sound/환경설정은 회색 gear 위치만. 기존 감정표현은 기존 기능 그대로, 나가기/로비 복귀는 기존 확인 경로 유지. gear 안 기존 나가기까지 비활성으로 만들지 않는다. 미래 옵션은 `추후 제공` 비활성 행으로 구별한다.
- dock 순서: 탐색 / 텔레포트 / 회복, 다음 행 상점 / 가방 / 기권. 동작 가능 여부는 기존 `renderTurnBar`의 주체·선택·주행동·강제선택·시한·단절 조건. 특수 도망 교환/선택 전투 상태의 기존 전용 제어는 이 기본 dock을 대체하며 허위 행동 여지를 남기지 않는다.
- 상점 닫힘은 상점 그림과 `상점`+`N턴 후 열림` 두 줄(최소12px). N은 `ECO.shopTurns.find(t > S.turnCount) - S.turnCount`; 표시 턴 `S.turnCount+1`과 혼합하지 않는다. 예: 내부17이면 다음20까지3턴(표시18턴). 더 없으면 `예정 없음`. 비활성 상태를 선/표식으로 주고 남은 턴 글자는 선명하게 유지한다. 재화/가격 뱃지 모양을 쓰지 않는다.
- 가방은 `가방 n/3` 정보 열기; 일반 읽기 전용 창 열기는 턴 명령이 아니다. 상대 차례에도 내 정보만 조회. 기권은 현재 허용/확인 경로 그대로, 단절 중 예외로 활성화하지 않는다.

## 5. 우측 시너지 rail 및 설명

모든 왕국5 → 아키타입6 → 왕관 → 조건이 맞는 개인 전설을 표시한다. 기본칩 순서는 현행 데이터의 `V2_ELEM_ORDER`, `Object.keys(V2_ARCH_SYN)`을 따른다. 표시 개수나 scrollHeight를12로 자르지 않는다. rail 제목 `내 시너지`; chip44×44, gap2, 아이콘18–20, 숫자12, 단계 점 또는 단계 텍스트. 긴 이름/정확한 효과는 팝업으로 읽는다.

| 상태 | 칩·상세 표현 |
|---|---|
| 미달 | 무채색 선, 실제 수0 포함, `미달` 접근성 이름. 클릭하여 요구 단계 설명 가능 |
| 활성 | 단계 색 선+실제 숫자+단계 점; 상세에 `적용 중`·실제 단계/효과 |
| 기여 생존 | 목록 카드에 이름·왕국/아키타입·`필드 / 생존`·허용 HP |
| 기여 사망 | 이름과 속성 보존, `사망 · 기여 유지` 배지·실제 HP. 목록에서 제거하지 않음 |
| 가방 일반 / 전설 | 일반은 기여 목록 제외; 예외 전설은 해당 아키타입 목록에 `가방 · 기여`로 구분 |
| 왕관 | `죽은 동료 n/2`, 기존 추가 기술 설명. 대표 외형과 무관 |
| 개인 전설 | 소유·활성 효과가 원천에서 확인될 때만 존재. 이름/효과 명시; 가방 전설이라는 이유만으로 생성 금지 |
| 전투 스냅샷 | `이번 전투 기준` 명시, 수치와 기여 목록 모두 같은 스냅샷 원천; 미확인 목록은 현재값으로 꾸미지 말고 확인 대기 |

본문 팝업은 이름 → 현재 칸/단계 → 단계별 실제 효과 → 기여 목록. 상대 비공개 총계/기여자 추출 금지. 제안된 main rail은 기존 main의 활성 요약을 대체하지만 계산 함수/효과 표를 대체하지 않는다.

## 6. 가방과 하수인·스킬 설명

가방은 불투명 기존 남색 팝업(모바일 viewport−16px, desktop max560px), radius14, padding12. 머리줄 `가방 n/3`, 오른쪽44px X, 내부만 스크롤(max-height viewport−32px). 3열 카드 gap6, 320에서 각약89px, 390에서약112px. 각 카드≥116px 높이, 그림40px, 이름12px, grade/HP/속성은 #293 카드 규격. 빈칸은 +와 `빈칸` 중립 패널, tabindex/클릭 없음. capacity는3 유지.

아이템은 `내 보유 아이템` 아래 **실제 inventory 원천** `goodOwned`: potion/cool/cure는 `S.inv[p]`, ball은 `S.balls[p]`, ticket은 `S.eco.tickets[p]`, power/time/escape는 `S.eco.buffInv[p]`. 수량은 `×n` (분모/보유 상한 없음). 최소44px 셀의4열×2행에 기존 goods 아이콘과 이름·수량; 좁은 폭에서3열도 허용. 0은 `×0`+없음, 미수신은 `—`로 구별. 실제 수량 확인 없이 시작값/예시값으로 채우지 않는다. 시안은 실제 게임 캡처가 아니므로 예시 수량을 표시한다.

- 카드 얼굴/이름의 **설명**은 읽기 전용. 본 가방 팝업에 새 구매/확장/판매/교체/사용 명령을 추가하지 않는다. 해당 기능이 허용되는 기존 상점·전투의 명시 버튼에서만 실행한다. 정보 열기와 판매/교체 등 형제 버튼 이벤트가 겹치지 않아야 한다.
- 보드의 기존 탭 선택/이동은 보존한다. 선택 말 요약의 별도 `설명`44px 버튼으로 상세 열기; 상대 읽기 가능한 대상만 별도 정보 진입 제공. 미공개 `?`의 기존 추측 메모를 진짜 상세로 치환하지 않는다.
- 상세: 머리 이름+X, 기존 portrait, 허용된 등급/왕국/아키타입/HP, `하수인`/`스킬`44px 정보 탭. 스킬 탭은 이름·설명·현재 허용된 수치만 읽으며 기술 사용 버튼이 아니다. 수치/쿨다운/피해계산을 아트 문구로 새로 정의하지 않는다.
- 자기 데이터와 서버가 이미 공개한 상대 필드만 표시. 정체 공개≠HP/스킬 전체 공개; 숨은 종을 roster ID/asset URL/alt/title/DOM에도 넣지 않는다. 모르는 값은 `비공개`/`확인 중`. secret IDs를 사용자 문구로 쓰지 않는다. 상대 코인·가방·상점 진열·선택 정보는 공통 상세의 데이터 입력으로 받지 않는다.
- X/Esc/외부 닫기는 안내만 닫고 트리거로 포커스 복귀. 배경 입력과 이벤트 전파를 차단해 닫는 탭이 이동/판매를 실행하지 않게 한다. 읽기 전용 설명의 열기/닫기는 시계를 초기화하지 않는다. 팝업 내부 키보드 순환·보이는 focus ring, 스크롤 마지막 내용 접근 보장.
- 단계/턴 문맥 변경·만료·선택 무효·새 경기·공개 범위 변경 시 기존 안내를 닫거나 승인된 최신 표시만 갱신. 새 경기에는 무조건 이전 identity/상세 스냅샷 폐기. 단절 중 표시 가능한 내 마지막 정보는 `연결 대기`로 구분하고 게임 명령은 잠근다. 준비 시간 정책은 유지한다.
