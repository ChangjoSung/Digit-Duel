# #217/#218 Earth — 최소 공개 로비 UI 가이드

## 목적과 경계

Mars는 현재 `demo/index.html`의 어두운 패널·카드 체계와 기존 말/보드 자산을 그대로 사용해, **계정·초대 코드·자동 매칭·관전 없이** 공개 방을 만들고 목록에서 참가하고 준비하는 흐름을 완성한다. 기본 진입은 `공개 방`이며, 비공개 코드 탭을 기본값 또는 동등한 진입점으로 되돌리지 않는다. 서버 주소·호스팅·TLS·운영 구성은 플레이어 흐름에 노출하거나 설명하지 않는다.

공개 방의 게임 개시는 클라이언트의 ready 조합이 아니라 서버가 보낸 권위 있는 시작 상태에만 따른다. 따라서 로비는 준비 완료 뒤에도 “서버가 대국을 준비 중” 상태를 정직하게 보여 주며, 로컬 매치 시작·상대 배치 교환·카운트다운을 먼저 실행하지 않는다.

## 화면 구조와 문구

온라인 카드는 기존 `.lobbyCard.net` 한 장 안에 두고, 제목은 `공개 대전`으로 쓴다. 기존 PVE/핫시트 카드보다 온라인 카드가 먼저 보이도록 하되, 타이틀·게임 모드 전체를 새로 디자인하지 않는다.

| 상태 | 카드 안의 순서 | 고정 문구 / 행동 |
| --- | --- | --- |
| 목록 | 제목, 짧은 설명, `새 방 만들기`, `새로고침`, 방 목록 | 설명: `열린 방을 골라 바로 참가하세요. 초대 코드는 필요하지 않습니다.` 빈 목록: `열려 있는 방이 없습니다. 새 방을 만들어 보세요.` |
| 각 방 | 서버 레이블, 좌석, 생성 경과, `참가` | 예: `방 #A7K2 · 1/2 · 방금 전`; 식별자는 서버 레이블만 보이고, 사용자 이름·채팅·전적은 넣지 않는다. |
| 생성/참가 중 | 동일한 카드와 목록을 유지, 해당 주 행동만 비활성 | `방에 참가하는 중…` 또는 `방을 만드는 중…`; 중복 탭을 막되 취소 버튼을 새로 만들지 않는다. |
| 준비 | `방 #…`, 내 상태, 상대 상태, `준비 완료`/`준비 취소`, `방 나가기` | `내 준비: 준비 전/완료`, `상대: 입장 대기/준비 중/준비 완료`. 준비는 배치 완료 뒤에만 가능하며, 배치를 바꾸면 내 준비만 `준비 전`으로 돌아간다. |
| 양측 ready | 두 상태와 작은 진행 표식 | `두 참가자가 준비했습니다. 서버가 대국을 시작하는 중…` 서버 시작 상태 전에는 이 문구와 현재 화면을 유지한다. |

목록 상단의 `새 방 만들기`은 강조 버튼(`.primary`) 하나만 사용하고, `새로고침`과 각 `참가`는 기본 버튼으로 둔다. 방이 하나 이상이면 `새 방 만들기`가 첫 포커스, 이어서 `새로고침`, 목록의 `참가` 순서가 된다. 방에 들어간 뒤에는 화면 제목(예: `공개 방 #A7K2`)을 먼저 읽고, 내 준비 제어, 나가기 순으로 탭 이동한다.

## 시각 규칙과 반응형

- 색상은 이미 정의된 `--bg`, `--panel`, `--panel2`, `--line`, `--txt`, `--dim`, `--accentFill`, `--ok`, `--danger`만 사용한다. 온라인 카드의 기존 navy 계열과 태그 pill을 유지하고, 방마다 새 일러스트·아바타·배경·래스터 자산을 추가하지 않는다.
- `준비 완료`는 기존 파란 채움 강조, 준비 완료 상태는 텍스트와 `--ok` 점/배지로 함께 구분한다. 오류는 `--danger` 테두리/문구를 쓰되 색만으로 의미를 전달하지 않는다.
- 320–432px에서는 카드 좌우 여백을 유지하고 가로 스크롤을 만들지 않는다. 목록 행은 방 정보가 먼저 줄바꿈되고 `참가`는 다음 줄에서 전폭이 될 수 있으며, 모든 주요 버튼은 최소 44px 높이를 유지한다. `새 방 만들기`와 `새로고침`은 320px에서 세로로 쌓여도 되고, 390–432px에서는 같은 행을 우선한다.
- 키보드 포커스는 기존의 밝은 2px 외곽선과 충분한 여백을 재사용한다. 현재 포커스/선택을 흐릿한 hover만으로 표시하지 않으며, 방 목록 갱신 뒤에는 사용자가 누른 제어에 포커스를 돌려준다.
- `prefers-reduced-motion: reduce`에서는 새로고침·생성·참가·ready 전환을 즉시 바꾸고, 회전 스피너·펄스·카드 이동을 사용하지 않는다. 진행은 움직임 대신 문구와 `aria-live="polite"` 상태 영역으로 알린다.

## 오류, 단절, 대기

오류와 단절은 토스트만으로 끝내지 말고 온라인 카드 안에 지속 상태를 남긴다. 서버가 반환한 안전한 짧은 메시지를 우선하고, 내부 코드·주소·재시도 정책은 플레이어에게 노출하지 않는다.

| 상황 | 카드 문구 | 가능한 행동 |
| --- | --- | --- |
| 목록 조회/생성/참가 실패 | `공개 방을 불러오지 못했습니다.` | `다시 시도`; 목록에 있던 마지막 성공 데이터는 희미하게 남기지 말고 최신 성공 상태만 표시 |
| 방이 이미 찼거나 사라짐 | `이 방은 더 이상 참가할 수 없습니다.` | 목록으로 돌아가 자동 새로고침 후 `다른 방 보기`에 포커스 |
| 준비 전 연결 단절 | `연결이 끊겼습니다. 방 목록으로 돌아가 다시 참가해 주세요.` | `방 목록으로`; 준비 완료처럼 보이는 낡은 상태를 남기지 않음 |
| 준비 뒤/시작 대기 중 단절 | `연결이 끊겼습니다. 대국 시작 여부를 확인할 수 없습니다.` | 재연결 계약이 확정되기 전에는 재개를 약속하지 말고 `방 목록으로`만 제공 |
| 서버 시작 상태 수신 | `대국을 시작합니다.` | 입력을 잠시 잠그고, 서버가 보낸 좌석별 스냅샷을 렌더한 뒤 게임 화면으로 전환 |

대기 중에는 `상대 입장 대기`와 `상대 준비 대기`를 구별한다. 1인 방은 `상대를 기다리는 중…`, 2인 방에서 내 준비만 끝난 경우는 `상대의 준비를 기다리는 중…`, 양측 준비 후에는 위의 서버 시작 대기 문구를 쓴다. `방 나가기`는 OPEN/SETUP에서만 노출하며, IN_PROGRESS 이후에는 기존 기권 흐름만 사용한다.

## 선택 사항 (이번 최소안 밖)

- 방 수가 많아진 뒤에만 생성 경과를 `방금 전/1분 전`처럼 더 짧게 정리하거나, 빈 목록에 기존 선/패널만 활용한 정적 구분선을 추가할 수 있다.
- 서버가 재접속 계약과 재개 상태를 확정한 뒤에만 `다시 연결` 행동과 남은 유예 시간 표기를 추가할 수 있다. 그 전에는 낙관적 재개 UI를 만들지 않는다.
