# #217 — CJ 구현 승인: 서버 권위 전환 + 최소 공개 로비 (2026-09-13, Venus_Plan)

## 분류
**[결정]** CJ가 Mercury의 취합 보고([public-lobby-review.md](../Mercury/public-lobby-review.md) — 공개 룸 실현 가능성/서버 권위/호스팅 사실관계)에 이어 **구현 승인**을 냈다. 이 문서는 그 승인의 범위를 확정하고, Jupiter가 이미 제시한 [권고]/(제안) 최소안을 "구현 시 따를 선택"으로 재정리한다. **아래 "구현 선택" 항목은 CJ가 문장 그대로 지시한 것이 아니다** — 승인된 방향 위에서 Jupiter/Mars가 이미 제안했던 초기 기본값이며, 통상적 구현 파라미터라 개별 CJ 승인 없이 조정 가능한 성격이다(근거: [public-rooms-analysis.md](../Jupiter/public-rooms-analysis.md) §5 결론, [analysis.md](../Jupiter/analysis.md) §5).

## 승인된 것 [확정 — CJ 결정]
1. **서버 권위 전환의 구현 착수.** 서버가 룸 상태를 소유하고 규칙을 판정하며, 좌석별로 화이트리스트를 통과한 뷰만 전송한다(analysis.md §2.2·§2.6).
2. **최소 공개 로비의 구현 착수.** 계정 없이 방 목록을 보고 자유롭게 방을 만들고·고르고·참가하고·준비할 수 있다(public-rooms-analysis.md §1·§4). 1회용 비공개 초대 코드 모델(analysis.md §2.3의 "초대 코드" 절, GDD-22 §2.2-A)은 이 승인으로 **SUPERSEDED** — 삭제하지 않고 검토 옵션으로 보존한다.

## 승인 범위가 아닌 것 [확정 — 이번 CJ 지시가 요청하지 않음]
- 계정 시스템
- 채팅
- 랭킹/전적
- 자동 매칭(퀵매치) — 방 목록 브라우징과는 다른 기능이다(public-rooms-analysis.md §1)
- 관전

위 다섯은 CJ가 이번에 새로 요청하지 않았다. 필요해지면 별도 CJ Comment로 승인 범위를 넓혀야 하며, 이번 승인에 포함된 것으로 보고하지 않는다.

## 함의하지 않는 것 [확정]
- 호스팅 사업자 선정, 도메인 구매, 월 비용 상한, TLS 종단 책임 주체 결정 — 전부 여전히 **[기획 필요]**다. 이번 구현 승인은 이 넷 중 어느 것도 구매·계약·선택을 뜻하지 않는다(analysis.md §4, public-rooms-analysis.md §6).
- **기존 게임 규칙은 변경되지 않는다.** 이동·상성·전투·폭탄·함정·밀어내기·판정, 그리고 등급 A/B/C 노출 규칙(GDD-13 4장)은 그대로다. 이번 승인은 온라인 인프라(서버 권위·룸 생명주기·공개 로비)에 한정된다.

## 구현 수용 기준·생명주기 계약 (구현 선택 — 이미 제안된 최소안 재정리)

**표기:** [승인 전제]는 위 승인 없이는 성립하지 않는 조건, [구현 선택]은 통상 파라미터라 조정 가능한 초기 기본값.

### 룸 상태 기계 [승인 전제 — analysis.md §2.3]
```
OPEN ──(참가)──> SETUP ──(양측 ready)──> IN_PROGRESS ──(승패/기권)──> FINISHED ──(정리)──> CLOSED
  └───────────────── CANCELED (결과 없음) ─────────────────┘
  └───────────────── VOID (서버 재시작) ───────────────────┘
```
- READY는 상태가 아니라 좌석별 불리언 두 개다. 자기 배치를 바꿀 때만 자기 ready가 꺼지고, 재접속은 어느 쪽 ready도 건드리지 않는다.
- 명시적 `leave`(의사 표시)와 소켓 단절(비의사)은 분리한다. `OPEN`·`SETUP`의 `leave`는 유예 없이 즉시 `CANCELED`. 소켓 단절은 유예 타이머([구현 선택] 60초)가 돌고 만료 전 재개하면 그대로 잇는다. `IN_PROGRESS`에는 `leave`가 없다 — 유일한 이탈은 `resign`(상대 승리).
- `IN_PROGRESS`에서 두 좌석이 모두 끊기면 **먼저 만료된 좌석에 대해서만 한 번** 판정한다(상대 승리, FORFEIT). 같은 틱 동시 만료는 `NO_CONTEST`. 이중 승리 경로는 없다.
- 서버 재시작/크래시는 살아있던 모든 룸을 `VOID`로 만든다(몰수패 아님). 계획된 재시작은 사전 예고([구현 선택] 5분)를 방송한다.

### 공개 로비 최소 필드 [승인 전제 — public-rooms-analysis.md §4]
- 목록에는 **`OPEN` 상태이며 좌석이 1개 빈 룸만** 노출한다. `SETUP`·`IN_PROGRESS`·`FINISHED` 룸은 목록에서 뺀다(관전 미승인과 일치).
- 룸 식별자(불투명 `roomId`) 자체가 참가 키이며, 별도 초대 코드는 없다.
- 호스트 표시명은 [구현 선택] 닉네임을 받지 않고 서버 자동 레이블("방 #<roomId>")을 쓴다 — 닉네임은 승인 범위 밖 확장이지 막힌 선결 조건이 아니다.
- [구현 선택] 채팅·랭킹/전적 필드는 최소안에 넣지 않는다(승인 범위 밖과 별개로, 이미 Jupiter가 제시한 초기 기본값).
- 좌석 인가는 `(roomId, seat)` 정체에 붙는다. 참가 시 발급하는 좌석 토큰이 그 세션의 인증이며, 좌석에 앉은 뒤의 행동 인가(소유권·행위자 검사)는 공개 참가 여부와 무관하게 동일하게 적용된다(analysis.md §2.5.4).

### 남용 방지 [구현 선택 — public-rooms-analysis.md §5]
- IP별 동시 `OPEN` 룸 수 상한, 전체 동시 룸 상한([구현 선택] 200), 목록 조회 전용 속도 제한. 구체 수치는 파일럿 실측으로 교정할 대상이며 CJ 개별 승인 없이 구현 단계에서 조정 가능하다.

### 회귀·QA
- 기존 `npm test` 5종, `CLAUDE.md`가 요구하는 헤드리스 스모크(이동·상성·폭탄·함정·밀어내기·판정 + AI vs AI 완주)가 분리된 규칙 모듈 기준으로 통과해야 한다(analysis.md H1~H3).
- Saturn 독립 QA는 구현 완료 후 별도 게이트다. 이 문서의 승인은 QA 통과를 대체하지 않는다.

## 남은 [기획 필요] — 실제 정책 결정이 필요한 것만
- 공개 로비 화면과 비공개 룸(있다면)의 병존 여부 — 이번 승인은 공개 로비를 채택했고 비공개 코드를 SUPERSEDED로 뒀으므로, 이 항목은 "필요하면 나중에 다시 여는 확장"이지 지금 막힌 결정이 아니다.
- 배포 호스트·도메인·월 비용 상한·TLS 종단 책임 주체 — **실제 외부 배포 전에만** 정해지면 된다. 코드 구현은 이미 승인되어 있으므로 이 결정을 기다리지 않는다.

위 외의 항목(룸 파라미터 수치, 자동 레이블 형식, 속도 제한값 등)은 구현 재량이며 코디네이터에게 재질문하지 않는다.
