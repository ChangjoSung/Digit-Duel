명시되지 않은 욕설 금칙어 사전은 임의로 만들지 않는 것을 권장한다. 이번 범위의 금칙 처리는 허용 문자·길이·태그/제어문자 검증과 텍스트 표시로 정의하고 ‘개인정보를 방 이름에 입력하지 마세요’ 안내를 제공한다. 별도 욕설 목록이나 개인정보 자동 판별을 요구하면 해당 정책부터 CJ가 정해야 한다. 허용 문자 검증만으로 모든 개인정보 입력을 막았다고 주장할 수는 없다.

CJ의 후속 “권장 순서로 구현 시작” 지시로 위 권장안을 채택한다. Venus가 현행 GDD 본문과 Decision Log에 동기화한 뒤 개발한다. 별도 욕설 사전/개인정보 자동 판별은 추가하지 않는다.

## 객관적 분석과 보존할 계약

- 현행 코드는 공개 참가 대기 방만 목록에 제공한다. 진행 중 방을 표시하려면 서버 목록 계약과 화면을 함께 바꿔야 하며, 버튼만 비활성화하는 것으로는 부족하다.
- 공개 응답은 방 이름/번호·표시 상태·인원·공개 닉네임/대표 하수인으로 제한한다. 계정 ID·이메일·인증 정보·초대 코드·IP·가방·배치·전투 내부 정보는 포함하지 않는다.
- 현재 서버의 WebSocket ping/pong은 연결 생존 확인에 사용한다. 사용자에게 보일 실제 RTT를 위한 요청/응답은 별도 최소 계약이 필요하다. 높은 핑이나 측정 실패로 게임 결과·타이머·60초 재접속 유예를 바꾸지 않는다.
- 서버가 같은 계정 중복 접속, 참가 경합, 시작된 방 참가 거부를 계속 보장해야 한다. 방 목록이 오래됐다는 이유로 이 검증을 완화하지 않는다.
- 현재 OPEN→SETUP과 시작 상점·배치/준비·재접속 흐름은 유지한다. 새 대기 화면이 추가 준비 버튼이나 별도 대기 제한을 만들지 않는다.
- 기존 공용 아트를 우선 사용한다. 채팅·자동 매치·서버 지역 선택·관전·신규 아트 제작은 이번 제안에 포함하지 않는다.

1. **선행 Git 정리**: CJ가 #260 커밋·PR 작성까지 별도 승인하면 현재 검수된 변경을 기능 브랜치 PR로 고정하고 필수 CI를 확인한다. milestone 병합은 별도 지시를 따른다.
2. **기획 확정**: CJ가 위 권장안을 검토하고 #261 실행을 지시하면 Venus가 화면/문구/세칙을 GDD에 동기화한다.
3. **구현**: Jupiter가 최소 공개 목록·이름·실측 핑 계약을 정리하고 Mars가 이를 소비하는 멀티 화면을 구현한다. 서버와 화면 계약이 맞은 뒤 통합한다.
4. **검증**: fresh Saturn이 공개 정보·입장 경합·실측/실패 핑·입력 방어·2클라이언트와 재접속을 독립 QA한다. 이후 CJ 플레이 QA 및 승인된 Git/필수 CI 단계로 진행한다.

현재는 실행 승인 단계다. #260 PR270 최신 HEAD a444d57의 필수 CI를 먼저 확인하고, 기존 QA 서버를 보존하는 별도 #261 트리에서 착수한다.
