## 3. 서버 · 화면 인계 (구현 메모 — CJ 결정 아님)

- **Jupiter(서버)** — 현행 `server/authoritative/lobby.js` `listPublicOpenRooms()`는 공개 **OPEN만** `{roomId, label:'방 #번호', ageSec, seats:'1/2'}`로 준다(`room.js` `isListable`/`lobbyRow`). 이를 OPEN · SETUP · IN_PROGRESS + 이름 · 상태 · 인원 · 공개 닉네임 · 대표 하수인으로 넓히고 비공개 항목은 응답에서 뺀다. 방 만들기 요청이 이름을 받아 서버에서 정리 · 검증 · 저장(불변). 참가 검증은 현행대로 서버 최종. 현행 WebSocket ping/pong(30초 생존 확인)은 그대로 두고, 화면 RTT용 가벼운 요청/응답을 따로 두며 빈도를 제한한다. 검색 위치(서버/화면)는 구현 선택.
- **호환(PD 지시 반영)** — 이름 필드가 없는 기존(legacy) 생성 요청은 기술적으로 '방 <roomId>' 기본값을 둘 수 있다. **이름을 명시했는데 비었거나 규칙 밖이면 거부**한다. 이것은 개발 호환 세부이지 새 UI 예외가 아니다(화면은 항상 이름을 보낸다).
- **Mars(화면)** — L02 · L03 전체 화면, 5초 목록 · 핑 측정은 L02가 보일 때만, 3초 시간 초과와 연결 끊김 분기, 입력 검사 · 개인정보 안내, 이름 · 닉네임은 텍스트로 표시, 참가 거부 뒤 목록 갱신.
- **Saturn(QA)** — GDD-24 'L02 · L03 멀티 방' 수용 기준 1~12가 확인 목록이다.
