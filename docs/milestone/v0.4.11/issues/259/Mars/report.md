## 2. 클라이언트 흐름 계약 (Unity 클라이언트가 그대로 따를 것)

서버 API·오류 코드의 원본은 [server/README.md](../../../../../../server/README.md) 계정 표다(Jupiter 갱신 대상).

1. **시작 시** `GET /api/auth/session` 한 번(file:// 은 요청 없이 계정 없는 경로). `200 {userId,nickname,hasEmail}` → 로그인 · `401 E_NO_SESSION` → 로그인 필요 · JSON `503 E_ACCOUNTS_DISABLED` 만 계정 없는 경로 · 그 밖 전부 닫힘(입장 차단 + [다시 시도]).
2. **입장 게이트**: 확인 중·로그인 필요·닫힘이면 어떤 게임도 시작하지 않고 소켓도 열지 않는다.
3. **세션 토큰** `dd_sid` 는 HttpOnly 쿠키 — 클라이언트는 읽거나 저장하지 않는다. **한 브라우저 프로필 = 쿠키 하나 = 계정 하나**.
4. **공개 방 생성·참가 소켓 직전** 세션 재확인(401 → 로그인 화면, 다른 계정 → 신원만 갱신하고 입장은 다시 누르게). `E_SAME_ACCOUNT` → 로비 안내.
5. **비밀번호·이메일 입력**은 HTTPS 또는 루프백에서만(서버 `403 E_INSECURE_TRANSPORT` 와 같은 경계).
6. **가입** `{userId,nickname,email,password}` — 이메일 필수, 앞뒤 공백만 제거, 서버 `EMAIL_RE`·254자와 같은 형식 검사. **이메일 중복은 오류가 아니다.** 409 는 `E_ID_TAKEN`/`E_NICKNAME_TAKEN` 만 안내. 성공 즉시 입장 가능.
7. **비밀번호 찾기**(아이디 전용): ① `password-reset/request {userId}` → **202 일 때만** "등록한 이메일로 보냈습니다" 안내(주소 비표시)와 6자리 칸 · 404 `E_ID_NOT_FOUND` = `존재하지 않는 아이디입니다` · 409 `E_EMAIL_REQUIRED` = 등록 이메일 없음 안내 · 503 `E_MAIL_UNAVAILABLE`·429·400·그 밖 = 1단계 유지 ② `verify {userId,code}` → **200 `{resetToken}` 뒤에만** 새 비밀번호 칸, 401 `E_CODE_INVALID` 는 2단계 유지·코드 칸 비움 · 재발송은 같은 `{userId}` 로 60초 뒤에만(그 전엔 남은 초 안내) ③ `complete {resetToken,newPassword}` → 200 은 **자동 로그인 없이** 로그인 화면 · 409 `E_SAME_PASSWORD` = 정확히 `직전 비밀번호와 같습니다`, 허가 유지 · 401 `E_RESET_INVALID` = 1단계(아이디 유지). 대상 아이디·허가는 메모리에만, 화면을 바꾸거나 [아이디 다시 입력]·끝나면 버린다. 코드·허가·비밀번호는 저장소·주소·로그·토스트에 쓰지 않는다.
8. **이메일 없는 기존 계정**(`hasEmail:false`): [이메일 등록] 안내만(입장 차단 없음). `POST /api/auth/email {password,email}` — 다른 계정과 같은 이메일도 등록된다. 200 또는 `E_EMAIL_ALREADY_SET` 이면 안내를 치운다.
9. **로그아웃**: 서버 200 일 때만 — 방·목록 소켓을 닫고(재접속 없음) 이 계정 좌석 기록을 지우고 다른 탭에 알린다.
10. **서버 세션 종료**: `E_SESSION_ENDED`(또는 close 4003) → 소켓 정리·로그인 화면·자동 재접속 없음·좌석 기록 유지. `reason:"login_replaced"` 면 다른 곳 새 로그인 안내. 그 뒤 세션을 한 번 다시 확인해 프로필의 실제 계정을 보인다(재접속 없음).
11. **좌석 재접속 기록**: 계정별 키 `dd_seat.<아이디>` `{u,epoch,roomId,seat,seatToken,tokenGen}`. 시작 시(그리고 로그인 직후) 그 계정 기록만 읽어 `r-<epoch>.<seatToken>` 재접속. 나가기·로비·재접속 실패·로그아웃에서 지운다.
12. **같은 프로필 다른 탭 알림**: 신원을 바꾼 탭은 `dd_acct={u,t}` 를 쓰고, 다른 탭은 storage 이벤트로 받아 자기 신원과 다르면 방 소켓·재접속을 끊고 프로필의 실제 계정을 다시 확인한다.
13. **방 소켓 없는 로그인 탭의 세션 대조**: 보이는 동안 5초마다 1회, 다시 보이거나 포커스를 얻는 즉시 `GET /session`. 401 → 자동 로그아웃 안내, 다른 계정 → 전환 안내, 같은 계정 → 아무것도 안 함, 네트워크·503·429 → 상태 유지.
14. **재접속 거절 원인 확인**: 업그레이드 401·`E_SEAT_TOKEN_INVALID` 면 세션을 한 번 확인해 로그아웃/계정 전환을 알린다.
15. **밀려난 탭**(`E_SUPERSEDED`): 되찾지 않고 로비로.
16. **늦은 응답**: 신원 세대 `gen`, 재설정 세대 `rgen`(+ reset 객체 동일성)이 요청 때와 다르면 버린다.
17. **공개 닉네임**: 서버 `players:[좌석0,좌석1]` 중 닉네임 규칙에 맞는 값만 `나(P1 · 앨리스)` / `상대(P2 · 밥돌이)` 로 표시.
