## 1. 분해 원칙

CJ Comment 운영 계약(#2)에 따라 **하나의 납품 목표 = Issue 1개 + 통합 PR 1개**가 기본이고, **독립 출시·독립 롤백이 필요한 범위만** 별도 Issue로 분리하며 부모 에픽에 sub-issue(깊이 1단계)로 연결한다. v0.4.11은 스탯·전투식·로스터·시너지·상점·서버 권위·UI가 서로 강하게 얽힌 대규모 패치이므로, **부서가 아니라 "따로 릴리스·롤백할 수 있는 단위"** 기준으로 쪼갰다. 부서 인력 배정은 각 Issue 안의 담당자 표로 처리한다.

  - 상점·가방 아이콘 진입, 닫힌 상점 Dim + 잔여 턴 수 표시.
  - 신규 구매 무확인+레드닷, 승급·판매·티켓 확인 팝업 1회.
  - 전투 화면 시너지 칩(내 전투원만, 상대 비공개), 연결 대기 Indicator.
  - 스킬 이펙트 공용 프리셋(타격/상태이상/방어막/회복) 속성·아키타입별 색상·실루엣 구분, 전설 3종만 전용 연출.
  - 연출 길이 1.2초 이하, reduced-motion 설정 시 색 강조로 대체.
  - UI/UX 흐름 문서의 화면 ID·전이표(S01~S05, M01~M07, B01~B08 등)와 실제 구현 화면 흐름 일치.
- **담당**: Earth(시각 설계) · Mars(실행 코드) · Venus(문구 확인) · Saturn.
- **의존**: **D 선행 권장**(로직 확정 없이 UI만 먼저 착수하면 재작업 위험 — Mercury 재량으로 병렬 착수 가능하나 통합은 D 이후).

## 3. 실제 의존 관계 요약

```
A (스탯·전투식)
 └─ B (로스터·스킬)
     └─ C (시너지)
         └─ D (상점·경제) ──── E (서버 권위, 데이터 모델 공유)
                             └─ F (UI, 로직 확정 후 통합 권장)
```

- A→B→C→D는 **엔진 순서상 실제 의존**(각 층이 아래 층의 산출물을 참조)이라 순차 착수가 필요하다.
- E는 D와 **데이터 모델만 공유**하고 서버 인프라 자체는 병렬 착수 가능하다.
- F는 **선행 권장이지 강제 의존은 아니다** — CJ가 원하면 목업 우선 착수도 가능하나, 로직 변경 시 재작업 비용을 감수해야 한다.
