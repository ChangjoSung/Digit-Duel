## 2. 무엇을 어떻게 쟀나

도구는 [`demo/test/reports/grade_compare.js`](../../../../../../demo/test/reports/grade_compare.js)다. 기존 헤드리스 하네스(`demo/test/shared/harness.js`)와 #95 비교 도구의 단독 전투 방식을 그대로 썼고 새 시뮬레이터를 만들지 않았다.

- 전투는 실제 엔진 경로다: `startRounds` → 5급 AI `aiBattleAction` → `execSlot` → `nextPhase` → `judge`.
- 표를 바꾸는 방법: `applySpecies` 뒤에 전투원의 **HP·공격력만** `round(⭐1 값 × 배율)`로 덮어쓴다. 방어·속도·회피·치명타·상태 가산·스킬 해금·선턴 규칙·경제는 엔진 그대로다.
- 현재 표는 엔진 식을 그대로 계산하고, 시작 자기검사가 "엔진 `gradeHp`/`gradeAtk` = 현재 표"를 6 아키타입 × 4 등급에서 확인한다(불일치면 던진다).
- 한 칸 = 개시자 2(높은 쪽이 접촉 개시자 / 수비자) × 시드 200개 = **400판**. 현재·후보는 같은 시드를 쓴다(짝 비교).
- 통제: 아이템 0, 볼 0, 도망 없음(양측에 엔진의 도망 불가 플래그). 그래서 모든 판이 처치 또는 판정으로 끝난다. 필드 시너지는 시나리오가 놓은 칸만 센다.
- 기본기만 = 스킬 칸을 1차 하나로 자른 것. 실제 스킬 = ⭐N이 1~N차를 가진 엔진 기본 상태.
- 3R = 전투 인스턴스의 `maxRounds`를 `BAL.buffTimeRounds`(3)로 둔 것. 시간의 수호자가 하는 일과 같다.

### 5.2 읽는 법
- 가운데 열이 "후보 ⭐4가 현행 전설을 넘는다"의 실측이다. 수치 비교(225/42 대 175/35)만이 아니라 실제 전투에서 위계가 뒤집힌다.
- 오른쪽 열은 현재 열과 ±2.5pt 안이다. 5단 AI도 같다(용 100 → 99.5, 마녀 100 → 99.5, 사신 90 → 93).
- 마녀 vs ⭐4 표준형은 현재도 73%다. 대응 아키타입이 아닌 상대에게는 전설 우위가 원래 작다.

### 5.3 "120%" 원칙의 근거
현행 전설은 대응 아키타입 현행 ⭐4의 약 120~123%다: 용 175/145 = 1.21 · 35/29 = 1.21, 마녀 165/138 = 1.20 · 32/26 = 1.23, 사신 158/131 = 1.21 · 40/33 = 1.21 [확정 · 산술]. 120%는 지금 간격을 그대로 옮기는 값이다.

### 5.4 사신 수치 단서
도구는 `round(⭐1 값 × ⭐4 배율 × 1.2)`로 계산해 사신을 **243 / 57**로 쟀다. Venus spec §3.2는 "⭐4 **정수값** × 1.20 반올림"이라 **244 / 58**이다(용 270/50·마녀 257/46은 두 방식이 같다). 차이는 HP 1·공격력 1이고 전설에 유리한 방향이라, 측정한 88.8%·92.0%는 spec 수치의 하한 쪽으로 읽으면 된다 [추론]. 실행 제한 지시에 따라 다시 돌리지 않았고, 도구의 계산식은 확정 표를 반영하는 후속 구현 Task에서 spec 방식으로 맞춘다.

## 6. Venus spec §3.5 적용

§3.5는 "같은 종·중립 상성·인접 등급·정상 스킬" 결과로 고르게 되어 있다. 해당 수치는 §4.2와 §4.3이다.

| §3.5 관찰 문구 | 실측 | 해당 여부 |
|---|---|---|
| 상위 등급 승률이 현행보다 뚜렷이 높다 | 평균 84.2% → 97.4%, 약한 칸 54.8~75.3% → 93.0~98.8% | 해당 |
| 상성 유리한 하위 등급이 일부 이긴다 | 낮은 쪽 승률 15.7 / 74.5 / 53.0% | 해당 |
| 중립에서 상위 등급이 사실상 전승 | 18칸 중 11칸이 97.5% 이상, 최저 93.0% | 경계선 |
| 상성 유리한 하위 등급이 전패에 가깝다 | 1v2만 15.7%, 2v3·3v4는 아니다 | 해당 안 됨 |
| 현행과 차이가 여전히 작다 | 아니다 | 해당 안 됨 |

- 둘째 줄(후보 B 추가 비교)은 두 조건이 함께 서야 하는데 뒤 조건이 서지 않는다. 그래서 문언대로는 **첫째 줄 = 후보 A**다. 후보 B는 측정하지 않았다.
- Venus·CJ가 판단할 지점 두 가지를 남긴다.
  1. 무상성 같은 종에서 한 등급 차는 후보에서 사실상 확정승(평균 97.4%)이다. §3.4의 의도("같은 조건이면 높은 등급이 분명히 이긴다")와 맞지만, "분명히"가 "거의 언제나"를 뜻하는지는 기획 결정이다.
  2. §3.4는 "한 등급 아래라도 상성이 유리하면 해볼 만"을 의도했는데, 실측은 쌍마다 갈린다. 2v3은 낮은 쪽이 오히려 우세(74.5%), 3v4는 반반(53.0%), **1v2는 15.7%**다. 경기 초반에 가장 흔한 1v2에서 역전 여지가 가장 작다.
- 후보 B를 보려면 같은 도구에 표 한 줄을 더해 B·C 절만 돌리면 된다(칸당 400판 기준 약 12,000판). 요청이 있을 때만 한다.

### §3.6 확인 항목
- AI 기대치 계산은 전투원의 `atk`·`hp`를 읽는다. `ai.js`에 등급 배율을 따로 적은 곳은 없다 [확정 · 코드 검색]. `gradeHp`/`gradeAtk`를 부르는 곳은 `data.js`(정의·`applySpecies`)와 `ui.js`(표시용 `unitHp`)뿐이고 `server/`에는 사본이 없다.
- `ai.js:832`의 가방 말 평가 `등급×100 + HP`는 후보 HP 범위(최대 270)에서도 만피 기준 등급 순서가 뒤집히지 않는다 [확정 · 산술].
- 현행 성장 기대값을 적어 둔 회귀: `smoke_issue233`·`smoke_issue234`·`smoke_issue236`·`smoke_issue293`. 표를 적용하는 Task에서 새 계약값으로 고쳐야 한다.

## 7. 주의와 한계

### 7.1 반올림 경계 [확정 · 실측]
- 현행 엔진 식 `round(값 × (1 + 0.15 × (등급 − 1)))`은 부동소수 때문에 .5 경계 두 칸을 내림한다: 공격형 ⭐2 HP 103.5 → **103**, 보호형 ⭐2 HP 126.5 → **126**. 화면 표시도 같은 함수를 쓰므로 표시와 전투는 서로 맞는다. 고치지 않았고 사실만 기록한다.
- 후보 표에는 .5 경계가 9칸 있다(표준 ⭐2 공격력 27.5, 공격형 HP 121.5·157.5·202.5와 ⭐4 공격력 47.5, 방어형 ⭐2 공격력 22.5, 보호형 HP 148.5·192.5·247.5). 배율을 소수 그대로 곱해도 지금은 9칸 모두 올림으로 나와 spec §3.1 정수표와 같다. 그래도 구현은 식이 아니라 **정수표 대조 검사**로 고정하는 편이 안전하다(spec §3.7-1과 같은 방향).

### 7.2 개시자 교환 [확정 · 실측]
- 등급이 다르면 접촉 개시자는 1라운드 선턴에 들어가지 않는다(속도 → 낮은 등급 → 개시자 순). 같은 시드를 두 개시자에 준 3번 실행에서 **72칸 전부** 개시·수비 승수가 같았다.
- 그래서 본 측정은 두 개시자에 서로 다른 시드를 줘 칸당 400판을 독립 표본으로 만들었다. 개시자가 결과를 바꾸는 경로는 판정 동률(수비자 승)뿐이다.
- 같은 종 미러에서 높은 등급의 1라운드 선턴 비율은 두 표 모두 0%다. 낮은 등급 선턴 규칙은 그대로이고, 후보에서는 그 보정 효과가 상대적으로 작아진다.

### 7.3 일반화 금지
- 승률은 고정 AI 정책(5급, 일부 5단) 아래의 모형 추정치다. 사람 플레이의 승률이 아니다.
- 🔥 속성 6종 미러와 표준형 상성 조합, M-G5·M-G6만 봤다. 30종 전체, 아키타입 교차 전수, 두 등급 차, 아키타입 시너지, 왕국 (2)·(6)·(9), 아이템·볼·도망·대리 출전은 **측정하지 않았다**.
- 전투 한 판만 봤다. 연승·보상·승급 쏠림 같은 경기 단위 효과는 이 도구로 알 수 없다.

## 8. 제안 (후보 유지 · Venus/Mercury 검토용)

1. **후보 A 표를 그대로 기획 검토에 올릴 만하다.** §3.5 문언에 맞고, 현재 표의 약한 칸(54.8~75.3%)이 모두 93% 이상이 된다.
2. **전설은 반드시 함께 올린다.** 올리지 않으면 위계가 뒤집히고(13~34%), 대응 ⭐4의 120%면 현재 위계가 ±3pt 안에서 유지된다.
3. **1v2 역상성(15.7%)과 무상성 전승에 가까운 결과(97.4%)를 CJ에게 수치로 보여 주고 고른다.** 더 완만한 표가 필요하다는 결정이 나면 후보 B를 같은 도구로 1회 본다.
4. **왕·동료는 수치만 넘긴다.** 후보에서 ⭐4가 왕을 평균 2.5라운드에 처치한다는 사실을 CJ 플레이 QA 판단 자료로 쓴다.
5. **구현 때 정수표 대조 검사를 둔다.** 반올림 경계 9칸이 있다.

## 부록 C. 정정 재검증 — 확정 계약 표 (2026-10-04 · 구현 뒤)

위 본문과 부록 A·B는 **구현 전 예비 측정**이고 그대로 보존한다. 이 부록은 #328을 제품에 적용한 뒤, 계약과 정확히 같은 표로 좁게 다시 잰 결과다.

### C.1 왜 다시 쟀나
- 예비 측정의 도구는 전설을 `round(⭐1 값 × ⭐4 배율 × 1.2)`(반올림 1회)로 계산해 사신을 **243 / 57**로 쟀다. 확정 계약(Venus spec §3.2)은 "⭐4 **정수값** × 120% 를 다시 반올림"이라 **244 / 58**이다. 예비 측정의 `candidate+L` 사신 줄은 계약표의 실측이 아니었다.
- 일반 하수인 ⭐1~4 정수표는 예비 측정 때도 정수 % 로 계산해 계약표와 같았다. 달라진 것은 사신 수치 하나다.
- 도구를 고쳤다: 전설 = `round(⭐4 정수 × 120 / 100)`. 시작 자기검사도 `LEGEND_BASE`까지 대조한다. 지금 엔진은 `candidate` 표와 일치한다고 보고한다(자기검사 통과).
- 표 이름이 바뀌었다: 예비의 `candidate`(성장만 · 옛 전설) → `candidate-L`, 예비의 `candidate+L` → `candidate`(= 제품에 적용된 확정 계약). 그래서 본문 §9의 재현 명령을 지금 돌리면 F 절의 표 이름과 사신 줄(243/57 → 244/58)이 예비 출력과 다르게 나온다. 나머지 절은 같은 값이 나와야 한다(다시 돌려 확인하지는 않았다 — 실행 상한).
