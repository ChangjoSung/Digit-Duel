## 1. #326 왕국 효과 발동률 (여섯 번째 전투 스텟)

### 1.1 뜻 [확정]
전투 카드 여섯 번째 칸은 **그 전투원의 왕국 효과 1회 판정의 발동 확률**이다. 종전 `+N%p`(가산치)를 대체한다.

```
p = min(1, f.synEl.p + f.statusPct + f.synStatusPct)
if (f.sandStormR > 0) p = p * 0.5        // 100% 상한을 먼저 자른 뒤 절반
```

- 이 식은 `v2Apply`(`demo/js/data.js:636`)가 왕국 판정(`v2KingdomProc` → `prob = f.synEl.p`)에 실제로 쓰는 식과 **같은 식**이다. 코드 확인 완료.
- `statusPct`가 곧 아키타입 기본값(`ARCHETYPE_BASE` · 지속형 10%, 마녀 25%)이다. 따로 "아키타입 기본"을 한 번 더 더하지 않는다. `synStatusPct` = 지속형 시너지 + 마녀의 집회(직접 참전 시).
- 예: 불 5칸(= (4) 단계 40%) + 지속형 시너지 2칸 5%p + 지속형 전투원 기본 10%p = **55%**, 모래 폭풍 중 **27.5%**. CJ Image 1의 동료(불 5칸 · 가산 0)는 `+0%p` → **40%**.

### 1.2 세 가지 "숫자 없음"을 구분 [확정]
| 상태 `state` | 조건(코드) | 칸 표시 | 접근성 이름 · title |
|---|---|---|---|
| `active` | `f.synEl`이 있다 | `💫 55%` | `왕국 효과 발동률 55% · 화상(상대)` |
| `inactive` | `f.synEl` 없음 + 왕국을 받을 수 있는 전투원(속성 있음, 또는 용) | `💫 미활성` | `왕국 효과 미활성 — 같은 속성 2칸부터` |
| `none` | `f.synEl` 없음 + 받을 수 없는 전투원(마녀 · 사신 = 무속성 전설) | `💫 없음` | `왕국 효과 없음` |
| (누락) | 공개방에서 서버 값이 없거나 형식이 틀림 | `💫 —` | `왕국 효과 발동률 정보 없음` |

- 0% · 미활성 · 없음 · 정보 없음을 서로 바꿔 쓰지 않는다. 클라이언트는 누락을 추정으로 메우지 않는다(기존 `—` 계약).
- 숫자 형식 [설계 보완]: 정수면 `55%`, 아니면 소수 첫째 자리까지(`27.5%`). 기본값이 모두 5% 단위라 `.5`만 생긴다.
- 효과 이름 · 대상 [확정]: `burn` 화상(상대) · `weaken` 약화(상대) · `shock` 감전(상대) · `harden` 경화(자신) · `absorb` 흡수(자신).
- 기술용 가산치 [설계 보완]: 종전 `+N%p`(= `effectiveStats.statusPct`)가 0보다 크면 title · 접근성 이름 끝에 ` · 기술 효과 +N%p`를 붙인다. 화면 글자는 늘리지 않는다.
- 아이콘은 기존 `💫` 그대로(#327 설명창 6행과 같은 아이콘). 새 아트 없음.

### 1.3 이 숫자가 뜻하지 않는 것 [확정]
- **기술 자체 효과 확률이 아니다.** 기술 확률은 따로 판정한다(예: 불 표준형 2차 화상 70%와 왕국 화상 40%는 별개 주사위).
- **일반 경로**: 피해 스킬이 **실제로 적중한 행동 1회당 1번** 판정한다(다단 타격도 1번). 적중이 없으면(전부 회피 등) `v2SkillSettle`이 `synHit` 없음으로 바로 끝나므로 **상대 효과도 자기 효과(경화 · 흡수)도 판정하지 않는다**(`data.js:978-981` 확인). 방어막이 전부 막은 타격은 적중이다.
- **확정 경로**(동료의 복수 · 왕의 분노 — `v2Revenge`): 이 숫자와 무관하게 판정 없이 발동한다. 이 경로에서만, 스킬이 회피돼도 **자기 효과(경화 · 흡수)는 걸리고** 상대 효과는 회피에 막힌다(`v2KingdomProc`의 `o.evaded && !self`).
- 감전 면역은 판정 성공 뒤에 따로 막는다. 이 칸은 "한 번 판정할 때의 확률"이지 위 조건을 모두 합친 확률이 아니다.

### 1.4 구현 계약
- **읽기 전용 파생값**이다. `statusPct` · `synStatusPct` · `synEl`에 써넣지 않는다. `v2Apply`의 난수 호출 횟수 · 순서 · 판정 결과를 바꾸지 않는다.
- 공용 헬퍼 1개(이름 제안 `kingdomProcView(f)` · `data.js`, `v2Apply` 옆)가 `{state, kind, p}`를 돌려준다. 확률식은 `v2Apply`와 **같은 식 한 곳**을 쓰도록 뽑아 쓰는 것을 권장한다(동작 불변 추출). 오프라인 화면과 서버가 이 헬퍼만 부른다.
- **회선(공개방)** — `server/authoritative/room.js` `_serializeBattle`의 `side()`에 `effectiveStats`와 **나란히** 한 칸 추가. 양 좌석 · 양 전투원 동일.
  ```
  kingdomProc: { state: "active" | "inactive" | "none",
                 kind:  "burn" | "weaken" | "shock" | "harden" | "absorb" | null,   // active일 때만
                 p:     number | null }                                             // active일 때만, 0~1 원값(반올림 없음)
  ```
  - `effectiveStats`는 **6칸 그대로**(기존 경계 테스트 `Object.keys(e).length === 6` 유지). `statusPct` 칸도 그대로 싣는다.
  - 계속 싣지 않는 것: `synEl` 원본(단계 · mag · rounds) · `synStatusPct` 등 가산칸 · 왕국/아키타입 칸 수 · 로스터 · 가방 · 미사용 스킬.
- **클라이언트** — `network.js`가 `kingdomProc`을 닫힌 값만 통과시킨다(`state` 3종 · `kind` 5종 · `p` 유한수 0~1). 하나라도 어긋나면 값 없음 → `—`. `ui.js` `battleStatHtml` 여섯 번째 칸만 바꾼다(`BSTAT` 앞 다섯 칸 불변).
- 갱신: 시너지는 참전 확정 때 고정, 모래 폭풍은 전투 중 바뀐다. 기존 전투 재렌더 때 값이 다시 그려지면 충분하다(새 타이머 · 구독 없음).

### 1.5 바꾸지 않는 것
말 정보 창(8칸)의 `상태 부여 +N%p` · 시너지 칩과 시너지 설명 · `SYN_STAT_KO.statusPct` 이름 · 락스텝 요약 · 전투 로그 문구.

### 1.6 다른 스텟의 시너지 반영 확인 [확정 범위 = 확인 · 오류만 수정]
코드 대조 결과 합산 경로는 이미 있다. 식 변경은 없다. 아래 값이 오프라인 `battleEff`와 서버 `effectiveStats`에서 같은지만 확인한다.

| 칸 | 적용값 |
|---|---|
| 공격 | `atk × (1 + synAtk)` 정수 반올림 표시(사신 죽음의 수확 포함) |
| 방어 | `def + synDef`(피해 감소 50% 상한은 타격 시점) |
| 속도 | `spd + spdBuff + synSpd` |
| 회피 | `dodge + synDodge + evadeBuff − evadeDown` → 0~40% |
| 치명타 | `min(50%, crit + synCrit)` |
| 보호형 시너지 | 시작 방어막으로 HP 바에 표시(스텟 칸 아님) |

### 1.7 수용 기준 (#326)
1. 고정 상태 표본에서 화면 값 = 헬퍼 값 = `v2Apply`가 왕국 판정에 쓰는 확률(같은 전투원 · 같은 순간). 표본: 가산 0 / 지속형 기본+시너지 / 합계 100% 초과(상한) / 상한 뒤 모래 폭풍 절반 / 마녀 직접 참전.
2. `inactive` · `none` · 누락이 서로 다른 표시와 접근성 이름으로 나온다. 용은 달성 왕국이 있으면 `active`(그 왕국 효과), 없으면 `inactive`.
3. 양 좌석 뷰에 두 전투원의 `kingdomProc`이 같고, 상대 쪽 직렬화에 `synEl` · `syn*` 원본 키가 없다(기존 #235 경계 테스트 유지).
4. 변경 전후 같은 시드의 전투 결과(난수 소비 · 로그)가 같다.
5. 전투 종료 뒤 다음 전투에 이전 값이 남지 않는다(`resetV2` 그대로).
6. 320 · 390 폭에서 여섯 칸이 잘리지 않는다(`미활성` 포함).

## 3. #328 등급 성장 (HP · 공격력)

### 3.1 바꾸는 것 [확정 — 후보 A 채택 · §3.5]
일반 하수인 ⭐1~4의 HP · 공격력 배율만 키운다. 계산은 **정수 %** 로 한다:

```
HP     = Math.round(base.hp  * HP_PCT[grade]  / 100)   // HP_PCT  = [100, 135, 175, 225]
공격력 = Math.round(base.atk * ATK_PCT[grade] / 100)   // ATK_PCT = [100, 125, 155, 190]
```

소수 배율(`×1.35`)을 직접 곱하지 않는다 — `.5` 경계(예: 90 × 135 ÷ 100 = 121.5 → 122)가 부동소수 오차에 흔들리지 않게 하기 위해서다. 반올림은 이 한 번뿐이다.

| 등급 | 종전 HP | 종전 공격력 | **채택 HP** | **채택 공격력** |
|---|---:|---:|---:|---:|
| ⭐1 | 100% | 100% | 100% | 100% |
| ⭐2 | 115% | 110% | 135% | 125% |
| ⭐3 | 130% | 120% | 175% | 155% |
| ⭐4 | 145% | 130% | 225% | 190% |

### 3.3 바꾸지 않는 것 [확정]
방어 · 속도 · 회피 · 치명타 · 💫 · 시작 방어막(등급 무관 유지) · 등급별 스킬 해금 · 1라운드 동속도 시 **낮은 등급 선턴** · 가격 · 승급 차액 · 승리 보상 · 포획 조건(HP 30% 미만 · 70%) · 승급 시 새 최대 HP까지 회복 · **왕 · 동료 스탯**. 이 항목들은 조용히 바꾸지 않는다 — 문제가 보이면 수치를 고치지 말고 보고한다.

### 3.4 왜 이 폭인가 [추론 — 설계 계산이며 실측은 §3.5]
- 상성 한 번의 차이는 피해 ×1.3 대 ×0.75 → 약 **1.73배**.
- 한 등급의 HP×공격력 차이는 종전 약 **1.27배**(상성에 묻힘), 채택표 약 **1.69배**(상성 한 번과 비슷).
- 그래서 채택표의 설계 의도는 "**한 등급 위 ≈ 상성 한 번**"이다: 같은 조건이면 높은 등급이 분명히 이기고, 한 등급 아래라도 상성이 유리하면 해볼 만하며, 두 등급 차(약 2.7배)는 상성으로 못 뒤집는다.
- 회복약(20%) · 방어막 · 화상 등 **최대 HP 비율 효과**는 HP와 함께 커지고, 라운드 종료 판정은 HP **비율**이다. 그래서 타격 수 계산만으로 확정하지 않는다.

### 3.5 수치 선택 기록 — 후보 A 채택
**선택 규칙 [설계 보완]**: 정상 스킬에서 상위 등급 우위가 종전보다 뚜렷하고 **상성이 유리한 하위 등급이 여전히 일부 이기면** A를 채택한다. 같은 종 대결이 거의 전승이라는 이유만으로는 약한 후보로 내려가지 않는다 — 상성 역전까지 사라질 때만 약한 후보를 다시 비교한다.

**근거 — Mars 실측 요약 (2026-10-04 · Mercury 전달 `msg_8206b4da464b`)**. Venus는 이 요약을 인용할 뿐 직접 실행하거나 보고서 파일을 대조하지 않았다(작성 시점에 `Mars/grade-comparison.md` 미도착).

| 조건 (조건당 400전 = 시드 200 × 선공 교대 2) | 종전 | 후보 A |
|---|---|---|
| 같은 종 · 정상 스킬 · 인접 등급 — 상위 등급 승률 | 54.8~100% | 93~100% |
| 상성이 불리한 상위 등급 승률(세 조건) | 20.8 / 6.0 / 14.5% | 84.3 / 25.5 / 47.0% |

**판단**: 등급 우위가 분명해졌고 상성 역전이 남아 있다 → **A 채택**. 약한 후보 B(HP 125 / 150 / 185% · 공격력 120 / 140 / 160%)는 비교하지 않았고 채택하지 않는다.

**한계 (그대로 기록)**
