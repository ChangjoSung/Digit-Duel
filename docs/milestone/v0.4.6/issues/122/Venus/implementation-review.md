## 3. 결과 연출 계약 (#126)

### 3.1 확정 — 하나의 종료 표현, 중복 직렬 금지

- **`resultBanner` 2500ms 유지.** 그 **안에서** 강한 효과 동작 구간 약 1.1–1.2초, 이후 읽을 수 있는 결과 글자를 홀드한다 ([Earth 스토리보드](../../126/Earth/effect-storyboard.md)와 같은 배분).
- **전투 연출 전체 + 경기 연출 전체를 직렬로 두 번 재생하지 않는다.** king·wipe 처럼 전투가 곧 경기 종료인 경우는 **하나의 종료 표현이 경기 결과로 분기**한다. 전투 결과 배너를 재생한 뒤 별도 경기 배너를 더 얹지 않는다.
- **전투를 거치지 않는 종료**(`edge`·`resign`·`opponent_left`·sim `draw`)도 **연출은 하나**다.
- 연출이 끝난 뒤 **최종 결과판은 유지된다** — 보드 복귀로 오인시키지 않는다.
- **도망·포획은 기존 1200ms 경로 그대로**이며 2500ms 로 연장하지 않는다.
- **모델 상태의 승패 규칙은 무변경.** 전투 판정 동률은 방어자 승이고 전투 무승부 화면을 만들지 않는다. 무승부는 경기 무승부(sim 턴 상한)에만 쓴다.
- 뷰어 문구는 `resultBannerOf` 규약을 따른다: PVE·온라인은 뷰어 기준, **핫시트는 중립**(`P1 승리!`) — 같은 기기의 두 사람에게 패배 화면을 씌우지 않는다.

### 3.2 구현 자유도

`gameOver` 를 **리팩터해도 좋다.** F3 의 비대칭 정리를 중앙화하고 종료 연출을 그 안에서 한 번만 발화시키는 편이, 6개 호출부에 각각 래퍼를 붙이는 것보다 누락 위험이 낮다. 1차 보고의 "6개 호출부 래퍼" 는 선택지 하나였을 뿐 강제 사항이 아니다. 구현이 지켜야 할 것은 결과뿐이다.

- 경기당 종료 연출 **정확히 1회**, 게임 세대가 아니라 **경기 기준** 플래그로 보장한다(`newGame` 이 새 상태를 만들 때 자연히 초기화되는 자리).
- 어떤 종료 경로에서도 **연출을 자기가 넣고 자기가 지우는 순서**가 생기지 않는다(F3).
- `fxLive()` false(sim·헤드리스)에서는 0ms 동기 처리 — 기존 회귀·AI vs AI 결과와 시드 스트림이 불변이다.
- 새 연출 경로에서 `rand()` 를 쓰지 않는다.
- 새 CSS 애니메이션은 유한(`forwards`)으로 둔다(F6).
- 연출 중 `over` 패널 버튼이 눌리지 않게 한다(F5).

## 4. 같은 문서 로비·재대전

- **선행 조건은 온라인 상태 해제다**(F8). ws 종료와 `NET.mode`/`started`/`me`/`syncModal`/`modalSeq`/`queue`/`mySetup`/`code`/`preparing`/`queued` 초기화 없이 로비로 돌아가면, 이어지는 오프라인 경기가 온라인 게이팅·보드 반전·인덱스 중계를 그대로 물고 간다.
- **#128 은 자동으로 지켜진다**(F9). `location.reload()` 를 부르지 않는 출구는 튜토리얼을 다시 띄우지 않는다. 새 저장 키·새 게이트가 필요 없다. 상황 도움말(`TUT.hints`)도 같은 이유로 초기화하지 않는다.
- 경기 상태 초기화는 `newGame()` 이 이미 `fxReleaseAll()` 포함으로 처리한다. 추가로 열린 오버레이를 닫고 `overlayBox` 를 비워 무한 버프 애니메이션 잔존을 막는다(F6).
- 온라인에서는 `재대전` 을 제공하지 않고 `로비로` 만 둔다(2장).

## 5. 온라인 불변식

- **I-1** 두 클라이언트가 `modal()` 에 넘기는 `buttons` 는 길이·순서가 같아야 한다. 마스킹은 표시에만 걸리므로 `buttons` 자체를 뷰어 조건으로 분기하면 인덱스가 어긋난다(F10).
- **I-2** 새로 만드는 **뷰어 전용 UI 모달(기록 서랍·설정 등)은 반드시 `netLocalModal()` 을 먼저 부른다.** 빠뜨리면 한쪽만 `modalSeq` 가 올라 이후 모든 동기 모달 중계가 깨진다. 선례: 로스터 정보 팝업 · 확인 모달 · 메모 피커 · 접속 코드 입력.
- **I-3** `disabled` 는 표시가 아니라 동기화 계약의 일부다. 문구로만 막으면 인덱스 중계로 눌린다.
- **I-4 (중요·보존)** **전투는 인덱스 모달이 아니라 시맨틱 액션을 쓴다**(F11). 세로 전투 화면을 다시 그려도 `buttons=[]` 와 `__act`/`__pass`/`__flee`/`__ball`/`__openPkg` 단일 경로를 유지한다. 두 통로를 겹치면 원격이 두 번 적용한다.
- 소유자 판정은 규칙 계층이다. 비공개 출전은 **말 소유자**(방어자 가능), 도망 교환은 `S.fleePick.owner`. 화면 위치가 바뀌어도 바꾸지 않는다.
- 핫시트 `🔄 기기를 넘기세요` 는 오버레이로 유지한다(온라인에서는 애초에 뜨지 않는다). 별도 씬으로 승격하면 레이어 순서 계약이 깨진다.

## 6. 아트 연결 (#122 · #124)

- **숲**: `.cell.forest` 의 표현만 바꾸면 된다(F12). `inForest`·행 판정을 건드리지 않는다. 숲 장식은 `.cell.fx-boom::after`·`.cell.fx-trap::after` 와 겹치지 않게 `::before`/배경으로 처리한다.
- **숲 속 말 표현 (2026-09-10 CJ 추가 피드백)** — 두 가지를 함께 지킨다.
  - **숨겨진 말은 `?` 조차 그리지 않는다.** `visibleTo` 가 false 인 숲 속 상대 말은 칸이 비어야 한다(F12b). 시안·구현 어디에서도 숲 칸에 미공개 상대의 위치나 물음표를 노출하지 않는다. 숲 **밖**의 미공개 상대는 종전대로 위치가 보이고 정체만 `?` 다.
  - **보이는 숲 속 말은 내 말과 상대 말 모두 살짝 반투명하게** 그려 수풀에 들어가 있는 느낌을 준다. 말 본체와 카드에 적용하되 **HP·속성 정보행과 선택·이동·공격 테두리의 가독성은 유지**한다.
  - **CJ 명확화로 `visibleTo`·정체·인접·`tempReveal`·메모 규칙 유지가 확정됐다.** `?` 미표시는 기존 완전 은폐를 뜻하며, 인접·충돌로 위치가 드러난 미확인 상대 표시는 그대로 남긴다. 추가 승인 대기는 없고 이번 항목은 **표시 계층 전용**이다.
- **왕·동료(#124)**: Earth 원본 2종 → Mars 파생 `demo/assets/leaders/{king,companion}/{icon64,battle256}.png`. 로스터 20종에서 파생되는 `ART_DIRS` 허용 목록에 끼워 넣지 않고 별도 조회 경로를 쓴다(F14). 프리로드는 정체와 무관한 고정 집합이므로 함께 받아도 상관관계가 생기지 않는다. **미공개 왕·동료 셀에는 `<img>`·src·alt 어디에도 정체 값을 만들지 않는다.**
- **보드 표시(AC-A5 정정)**: 새 왕·동료 아트는 **보드에서도 왕·동료라는 정체 역할로** 보여야 한다. 이모지 유지가 목표가 아니다. 다만 **포획 하수인을 앞세운 대리 출전은 여전히 그 하수인으로 보인다** — 보드의 왕·동료 표시가 대리 하수인 아트로 바뀌지 않는다(F14).
- **전투 화면**: 적 우상단·아군 좌하단, 반대편 HP 판, 하단 명령 4종(싸우기·가방·포획·도망가기)과 하위 메뉴·취소를 유지한다. `.bmenu` 4열을 2×2 로 바꾸는 것은 CSS 범위이며 버튼 집합·순서·핸들러를 건드리지 않아 I-1·I-4 를 자동으로 지킨다.
- **보드 말**: 소유자 프레임·32px 아이콘·속성/HP 정보행·미공개 `?` 를 보존한다. 정보행은 표시 장식이 아니라 규칙 정보다(폭탄·함정은 전체 공개에서도 HP 를 표시하지 않는다).
- **공개 기록**: 서랍화는 표시 선택이다. 미확인 표시는 공개 로그에서만 파생하고 새 집계 규격을 만들지 않는다(2장).
- **하단 액션바**: 보드 턴 종료와 전투 턴 종료를 하나로 합치지 않는다(F13). 전투 쪽은 소유자 화면 전용이라 비공개 계약이 걸려 있다.
