## 2. #146 — 도망 재계약

### 구현
- `BAL.fleeProb` 0.5 → **0.3**, `BAL.fleeProbGuard` **0.7** 신설. 표기·판정·AI가 모두 `fleeProbOf(f)` 한 함수를 본다 — 표시와 규칙이 갈라질 여지를 없앴다.
- HP 게이트(`canFlee`)와 사유 문구(`fleeWhy`)를 제거했다. 도망 버튼은 자기 전투 행동 차례이면 항상 활성이다.
- `fleeCounter()`(실패 반격)를 **삭제**했다. 실패는 `nextPhase()` 하나로 끝나고 상대는 정상 차례를 그대로 받는다.
- 버프 필드 `fleeFree` → **`fleeBoost`**로 개명했다. 의미가 "HP 조건 해제"에서 "이 전투 성공률 70%"로 바뀌었으므로 이름이 사실과 어긋나지 않게 했다. 초기화 지점(`resetBattleTemps`·`resetAfter`·말 생성·새 게임)은 그대로 전부 포함된다.
- 시도 상한은 신설하지 않았다.

### 관측 [확정]
- 경계 난수: 첫 `rand()`가 `r<0.3`이면 30%·70% 모두 성공, `0.3≤r<0.7`이면 30% 실패·70% 성공, `r≥0.7`이면 **70%도 실패**한다 — 1회 성공 보장이 아니다.
- 실패 시 양측 HP 불변·전투 로그에 반격 피해 없음·`battlesUsed`/`mainUsed`/`weaken` 불변.
- 성공 시 후방 교환(또는 생략) → 밀기 → 대기 중이던 강제 전투 큐 승격까지 실제로 이어진다.

## 3. #146 — 쓸 수 있는 행동이 없을 때

### 구현
- `noAtk = f.skills && 네 슬롯 모두 !slotUsable`. **폴백 기본 공격을 철회**하고 `NO_ATTACK_MSG`("공격할 것이 없습니다. 턴 종료할까요?") 안내 + 명시적 `window.__pass()` 버튼만 낸다.
- 버튼은 **루트 전투 메뉴와 싸우기 하위 패널 두 곳**에 있다. 안내가 뜬 화면에서 하위 메뉴를 열지 않고 바로 누를 수 있다 — 증빙 캡처(`i146-noattack-root.png`)에서 안내만 보이고 버튼은 싸우기 안에만 있던 것을 **PD 가 확인해 정리한 제안**(`msg_31b27e86d2e2`)이다. Saturn 은 독립 READ_ONLY 재검수를 맡았고 이 제안의 출처가 아니다.
- 비공개: 안내·버튼·도움말은 `noAtkShow = noAtk && viewerIsOwner(ownerP)` 로 **소유자 화면에만** 그린다. 상대의 미공개 기술 4칸이 전부 막혔다는 사실이 새지 않는다.
- 공개 로그는 중립 문구(`⏭ …는 이번 행동을 넘겼다.`)만 남긴다 — 사유는 남기지 않는다.
- `__passCore`는 `nextPhase()` 하나만 부른다. 주 행동·턴당 전투 횟수·약화 잔여 횟수·집중/취약/감쇠는 소모되지 않는다.
- AI 5급·5단 모두 `usable.length===0`에서 기본 공격이 아니라 패스로 진행한다.

### 실행 경로 차단 (계약 2.4)
- **단일 초크포인트**: `execSlot(side,slot)` 진입부에서 `slot<0 && f.skills`를 거부한다. 레거시 `basic` 별칭·사신 거부 폴백·늦은 콜백·수신 프레임·콘솔 직접 호출이 모두 이 한 곳을 지난다. 거부는 HP·상태·차례·난수를 바꾸지 않고 화면만 다시 그려 지금 합법인 메뉴로 되돌린다.
- 그 결과 `reaperFallback` 보조 함수를 없앴다 — 불법 사신 호출은 **다른 슬롯이 합법이어도** 피해·행동을 만들지 않는다.
- 왕·동료 본체(`f.skills` 없음)의 기본 공격은 그대로다.

### 행동 토큰 (Saturn REVISE P1 · PD `msg_04d2a4a470d5`·`msg_358a94d37af5`)
- `B.actSeq`를 **모든 전투 행동 전환**(`nextPhase()`)에서 증가시키고, 도망·패스 코어가 자기 행동을 확정할 때도 올린다. 각 모달 렌더가 그 시점의 `(actSeq, round, phase)`를 클로저에 가둔다.
- `actionFresh()` = 같은 전투 · 토큰·라운드·차례 스냅샷 일치 · `actorOfPhase()===side` · `msgQ` 비어 있음 · `fxLocked()` 아님.
- 이로써 **일반 공격·포획 실패로 차례가 넘어간 뒤 남아 있던 옛 도망/패스 콜백**도 거부된다(라운드 경계에서 같은 전투원이 연속 행동하는 경우 포함).
- 토큰은 표시 계층이 아니라 **공유 게임 상태**다 — 온라인 양측의 렌더 횟수가 달라도 값이 같다. 아이템·패키지 개봉 같은 **행동 내 무료 선택**은 차례를 넘기지 않으므로 같은 렌더의 행동이 계속 유효하다. 수신 재생은 `netReady`가 이미 잠금 해제·빈 `msgQ`를 기다리므로 이 가드에 걸리지 않는다.

## 4. #131 — 텔레포트 함정 차단

- 문구 3종을 상수로 두고 화면과 거부 안내가 같은 원천을 쓴다: `TELE_PICK1_MSG` / `TELE_PICK2_MSG` / `TELE_TRAP_MSG`.
- 함정에 걸린 말(`immobile>0`)을 1·2단계 어느 쪽으로 눌러도 **단계가 유지된 채** 거부된다. `trap` 유닛 자체는 막지 않는다.
- `teleportSwapValid(a,b)` 신설 — 실행 직전에 차례·주 행동·텔레포트 가용/횟수와 양끝의 owner·alive·placed·immobile·서로 다름을 다시 본다. **실물 대상 검사**(살아 있는 `S.pieces` 안에 그 id가 정확히 하나이고 그 객체가 인자와 동일 참조)로 복제·위조·중복 id를 거부한다 (Saturn REVISE P2).
- 거부 시 자원·좌표·HP·회복 자세·공개 상태·강제 전투 큐가 모두 불변이고 **난수 소비 0**이다.
- 거부 사유는 **소유자 토스트로만** 알린다. 함정 거부와 **접촉 전투 예산 거부**(`teleportSwapBlock`) 모두 공용 보드 로그에 남기지 않는다 — 남기면 온라인 재생에서 상대 화면에 그대로 뜬다 (Saturn `msg_8ccdd4f8b90e`·`msg_2b6a30b05bb1`).
- 도망 교환·강제 밀기에는 이 제한을 확장하지 않았다.

## 5. #130 — 보호막 합산

- 부여 세 경로를 전부 `f.shield = (f.shield||0) + Math.round(f.maxHp*pct)` 로 통일했다 — 보조기·시그니처 `sk.shieldPct`(종전 `Math.max`), 공격 부가 `sk.selfShieldPct`(종전 `Math.max`), 레거시 풀 경로 `sp.shieldPct`(종전 **직접 대입**).
- 새 수치·상한·지속기간은 만들지 않았다. 전투 종료·새 게임 초기화, 보호막 우선 흡수, 화상의 보호막 우회, `absorbCapPct`(유효 피해 집계 상한)는 그대로다.
- 누적이 최대 HP를 넘어도 수치를 깎지 않는다. 상태 표기 `🛡N`은 실제 값이고 방어막 바 폭만 100%에서 포화한다.
- AI는 새 증가량 기준으로 평가한다 — 기존 보유를 이유로 가치를 0.3배로 깎던 계수(`max` 갱신 전제)를 제거했다.

## 6. #128 — 튜토리얼 프로필 독립

- **제품 코드는 바꾸지 않았다.** 변경 전에 실제 브라우저로 3경로를 재현한 결과가 이미 계약대로였기 때문이다.
- **보존 증빙의 실제 순서 [확정]** (`artifacts/i146-browser-report.json` · 독립 Chrome `user-data-dir` 2개 · 같은 `http://127.0.0.1:PORT/index.html`):
  도구는 **A·B 두 탭을 먼저 함께 연 뒤** A 가 튜토리얼을 완주하고, **그다음 B 를 probe** 한다. 그래서 이 증빙으로 말할 수 있는 것은
  "A 완료 **후** B 가 처음으로 navigation 했다"가 **아니라** 아래다.
  1. A 최초 = 자동 표시 · `tutorialSeen` 없음
  2. A 완주 = `"1"` 저장 (A 프로필에만)
  3. **A 가 완주한 시점에 B 프로필의 저장소는 여전히 비어 있고 B 화면은 튜토리얼이 열린 상태다** — 두 프로필의 저장이 서로 넘어가지 않는다
  4. **A 완주 후에 실제로 일어난 B 의 재방문(navigation)** = 여전히 자동 표시 (B 는 아직 미완주)
  5. A 재방문 = 생략 · B 가 건너뛴 뒤 재방문 = 생략 — 각자 자기 프로필 기록대로만 생략된다
  6. `http://localhost:같은포트` = 다른 origin이라 저장 독립
- **[한계]** 변경 전에 별도로 돌린 최초 실측(A 완주 **후에** B 프로필을 새로 띄우는 순서)은 스크래치 스크립트로 수행했고 **보존된 산출물이 없다.** 그 순서를 뒷받침할 증거는 이 보고서에 없으므로 위 4·5번(보존 증빙으로 확인되는 사실)과 구분한다. 이번 후속에서는 PD 지시에 따라 #128 재검사·프로필 생성을 하지 않았다.
- **CJ 신고 증상은 재현되지 않았고 원인은 미확인이다.** 이 절은 "해결·PASS"가 아니라 **현재 검증 범위 정상 · 현상 미재현 · 원인 미확인**이다. [미확인] CJ 환경의 접속 주소(scheme·host·port)와 브라우저·프로필 구성 — 회신 전까지 원인을 단정하지 않는다.
- 추가한 것은 회귀 게이트(E절)와 실브라우저 증빙뿐이다. 서버 전역 seen·기기 지문·계정 공유는 추가하지 않았다.
