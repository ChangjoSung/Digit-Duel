## 0. 이 문서의 표기 규칙

기획 계약(CLAUDE.md)에 따라 모든 항목을 다음 다섯 가지로 구분한다.

| 표기 | 의미 |
|---|---|
| **[CJ 지시]** | CJ Comment로 내려온 방향성. 이 문서가 바꿀 수 없다. |
| **[CJ 결정]** | CJ가 선택지를 놓고 확정한 사항. 확정 항목은 더 이상 대안을 병기하지 않는다. |
| **[승계 원칙]** | 이전 초안에서 이어받은 아트·구현 원칙. CJ가 새로 말한 것이 아니다. |
| **[제안]** | Venus(기획)가 실측·계산으로 도출한 수치·구성안. CJ 승인 전이며 변경 가능하다. |
| **[미확정]** | 결정이 필요하지만 아직 근거가 부족한 항목. 임의 구현하지 않는다. |

수치가 적혀 있다는 사실이 승인을 뜻하지 않는다. 별도 표기가 없는 한 이 문서의 모든 px 값·장수·레이아웃은 **[제안]**이다.

## 2. 목적

현재 하수인은 전투 화면에서 속성별 색과 이모지 중심으로, 말판에서는 잘린 이름 텍스트로 표현되어 서로 다른 하수인의 외형 차이가 드러나지 않는다.

1. 하수인 20종에 서로 다른 고유 외형을 부여한다.
2. 하수인 선택 설명창에서 각 하수인의 외형을 충분한 크기로 보여준다.
3. 전투 화면의 단순 원형 표현을 캐릭터별 도트 이미지로 교체한다.
4. **말판 위의 말도 이름 텍스트가 아니라 캐릭터를 알아볼 수 있는 작은 아이콘으로 표현한다.** (2026-09-07 추가 — [CJ 지시])
5. 작은 이미지에서도 속성과 아키타입을 빠르게 구별할 수 있게 한다.

## 4. 용도별 규격 요약

| 용도 | 제작 그리드 | 납품 파일 | 화면 표시 | 형식 | 배율 관계 |
|---|---:|---:|---:|---|---|
| 하수인 선택 설명창 | — (일반 일러스트) | 512×512px | PC 192×192px | PNG 원본 + WebP 배포 | 축소 표시(정수 아님) |
| 전투 도트 | 64×64px | 128×128px | 128×128px | 투명 PNG | 그리드 → 파일 정수 2배 / 파일 → 화면 1:1 |
| **말판 인벤토리 아이콘** | **32×32px** | **32×32px** | **32×32px** | **투명 PNG** | **그리드 = 파일 = 화면 1:1** |

**선명도에 대한 정확한 서술**: 위 표의 크기 관계는 CSS px 기준이며, **CSS px가 정수로 맞는다는 사실만으로 흐림 없음을 보장하지 않는다.** 실제 래스터화는 장치 픽셀 비율(DPR)과 브라우저 확대율의 곱으로 결정되므로, DPR 1.25·1.5나 110%·125% 확대에서는 32 CSS px가 40·48 같은 비정수 배율의 장치 픽셀로 매핑되어 보간이 일어날 수 있다.

따라서 이 문서가 제안하는 것은 **보장이 아니라 렌더링 방식**이다.

- 도트 자산(전투 도트·말판 아이콘)에 `image-rendering: pixelated`를 적용해 보간 대신 최근접 확대를 요청한다.
- 설명창 일러스트는 도트가 아닌 일반 일러스트이며 512 원본을 192로 비정수 축소해 표시한다. 여기서는 브라우저 보간 축소가 정상 동작이므로 `pixelated`를 적용하지 않는다.
- **선명도는 검증 대상이다.** DPR 1 / 1.25 / 1.5 / 2와 브라우저 확대 100% / 125%에서 말판 아이콘과 전투 도트의 실제 표시를 확인한다(14.2 AC).

**이 표의 승인 상태 (rev7 갱신)**: 말판 아이콘 행의 **32×32 직납(그리드=파일=화면)** 은 2026-09-07 CJ 아트 승인의 제작 기준이며, 산출물이 이 기준을 충족했다(8.2.2). 설명창 512·전투 128은 이미 반입된 원본이 따르고 있는 실측값이다. **화면 표시 px(192·128·32)는 게임 화면 적용이 승인되었으므로 이제 구현 목표값이 아니라 구현 대상값이다**(3장 후속 Comment 3). 다만 이 값들은 **CJ가 개별로 지정한 수치가 아니라 이 문서가 계산한 엔지니어링 선택**이며, 실제 화면 실측에서 문제가 나오면 이 문서의 수치를 그 결과로 갱신한다(14.2.8 · 17장).

말판 아이콘의 64×64 2배 확대본은 **문서·시트 미리보기 용도로만 선택적으로** 만들 수 있다. 필수 납품물이 아니고 설계 수량에 포함하지 않으며, 확대본이 원본보다 정보를 더 담지도 않는다.

## 5. 하수인 선택 설명창

### 5.1 크기

- 원본 제작 크기: 512×512px
- PC 표시 크기: 192×192px
- 화면 높이가 부족한 환경의 표시 크기: 128~160px
- 캐릭터 주변 투명 안전 여백: 전체 캔버스의 약 8~10%

현재 설명창의 실제 콘텐츠 너비는 약 510px이다. 이미지를 240px 이상으로 표시하면 텍스트 영역이 좁아지고 설명창의 세로 길이가 늘어난다. 반대로 128px로 고정하면 새로 제작하는 고유 외형을 보여주기에 작다. 따라서 512 원본 · 192 표시가 균형이 가장 좋다.

### 5.2 배치·형식

- 상단: 이미지와 이름·속성·아키타입·핵심 능력 / 하단: 스탯과 스킬 상세
- 짧은 화면에서는 이미지 크기를 줄이고 필요 시 내부 스크롤 허용
- 모든 이미지의 발 위치와 캐릭터 기준선을 통일
- 보관 원본은 투명 PNG(또는 레이어 원본), HTML 배포본은 투명 WebP, Unity 이전을 위해 PNG 원본 별도 보존

### 5.3 연결 대상 — 어느 화면에 붙는가 (rev7 신설, 코드 실측 기준)

`portrait`가 붙는 곳은 **배치 단계의 하수인 설명창 하나**다. `rosterInfo(rid)`가 여는 모달이며, 적용 전에는 이름·속성·아키타입 배지·HP/공격·스킬 4행만 텍스트로 있었다. Issue #89에서 모달 상단에 `portrait.webp` 192×192를 연결했다(낮은 화면 128×128). 현재 검수 상태는 8.2.3을 따른다.

- 이 모달은 `ROSTER`의 종 정보를 보여주는 화면이므로 **20종 전부에 자산이 존재한다.** 누락 대상이 없다.
- 이 화면은 배치 단계에서 **자기 로스터를 고르는 화면**이므로 상대 정보 노출 문제가 없다(정보 은닉 대상이 아니다).
- 표시 크기 192px과 축소 방식(비정수 축소, `pixelated` 미적용)은 5.1·4장의 **엔지니어링 선택**이다.

## 6. 전투 도트 이미지

### 6.1 크기

- 도트 작업 그리드 64×64px → 최종 파일 128×128px(최근접 2배) → 화면 128×128px
- 권장 전투 영역 높이: 200px

적용 전 전투 말은 88×88px 원형이고 전투 영역 높이는 약 180px이었다. Issue #89에서 하수인 이미지를 128px, 전투 영역을 200px로 적용했다. 64 그리드는 20종의 얼굴·체형·아키타입 특징을 담기 위한 설계 기준이다. 220px 이상은 900px 높이의 PC 화면에서 팝업이 스크롤될 가능성이 커진다.

- **외형 정체 메타데이터**: 전투 규칙(`archOf`·`skillParamsOf`·`finishByCapture`)은 `rosterId`를 읽으므로 포획 객체에 `rosterId`를 직접 넣지 않고 **표시 전용 메타데이터**(예: `artRosterId`·`visualId` — 필드명은 Mars 구현 선택이며 이 문서가 강제하지 않는다)로 외형 정체를 보존한다.
- **불변**: 포획 하수인 스탯(공용 100/20/30/CD2, 적 포획 HP 70/100), RNG 소비 순서·상태 규칙·기술 구성, 라벨 `fighterName`("포획 하수인·속성"), 정보 패널·HP바·기술 목록·`revealedSkills`, 말판·설명창 표시, 왕·동료 본체 토큰. 표시는 **출전(전투 토큰) 때만** 바뀐다. 신규 아트 0장.
- **안전 폴백**: 외형 정체가 없거나 허용 목록(`ART_DIR_SET`) 밖이거나 이미지 로드 실패 시 기존 `artSpriteFail` 경로로 이모지 토큰 복귀. 예비→`cap` 이전(`useRes`) 후에도 외형 정체를 유지한다.
- **온라인**: 양쪽 클라이언트가 같은 lockstep 상태에서 `finishByCapture`를 실행하고 상대 `rosterId`는 기존 구조상 메모리에 있으므로 추가 동기화 없음. AI 무관.
- AC·검증 항목은 `docs/v0.4.4-gameplay-spec.md` 1장이 원본이다. 왕·동료 본체의 전투 이미지는 여전히 규격 없음·범위 밖이다.

### 7.2 현행 42px 컨테이너는 쓸 수 없다 — 계산

아이콘과 HP를 함께 보여주려면 현행 말 크기로는 공간이 모자란다.

- `.pc` 42px, 테두리 2px → 내부 가용 **38px**
- 아이콘 32px + HP 행 11px = **43px > 38px**
- 겹쳐서 43을 38에 밀어 넣으면 HP가 아이콘 하단 5px를 덮는다. 이는 캐릭터 발·하단 실루엣을 가리는 크기이고, 그 자리가 비어 있는지는 20종 아트가 나오기 전에 확인할 수 없다.

따라서 아이콘을 가리지 않는 배치는 **컨테이너 확대** 또는 **아이콘 축소** 둘 중 하나를 요구한다. 칸 크기 52px는 어느 안에서도 변경하지 않는다(말판 전체 폭·높이 불변).

### 7.3 배치 대안 — 겹침 없는 세 가지

세로 예산은 컨테이너 내부 높이이고, 요소는 **아이콘 / 정보 행(원소 기호 + HP)** 두 줄로 쌓는다. 겹침은 없다.

| 안 | 컨테이너 | 내부 | 아이콘 | 정보 행 | 원소 기호 병기 | 판정 |
|---|---|---|---|---|---|---|
| **A. 라운드 사각 48** | 48×48, 테두리 2px, 반경 12px | 44×44 | 32×32 | 11px, 폭 최대 44px | **가능** | **권장** |
| B. 원형 48 | 48×48 원형, 테두리 2px | 44×44 | 32×32 | 11px, 하단 폭이 좁아짐 | 불가 (아래 계산) | 차선 |
| C. 원형 42 유지 | 42×42 (현행) | 38×38 | **26×26** | 10px | 불가 | 최후 |

- **A안**은 세로 44 = 아이콘 32 + 간격 1 + 정보 행 11로 정확히 맞고, 가로도 44 전부를 정보 행에 쓸 수 있다.
- **B안**은 원의 하단이 좁아진다. 정보 행 글자 기준선 부근(컨테이너 상단 기준 y≈44.5)에서 원 안쪽 가용 폭은 약 19px이다. 원소 기호 10px + 간격 2px + 3자리 HP 19px = 31px가 들어가지 않는다. HP 숫자만이면 들어가므로, B안을 고르면 **말 위 원소 기호 병기를 포기**해야 한다.
- **C안**은 32 그리드를 26px로 표시하면 비정수 축소로 도트가 뭉개지므로, 아이콘을 26 그리드로 **따로 제작**해야 한다. Earth 기준(32 직납)에서 이탈하고 아트 재작업이 생긴다.

컨테이너 총 기하는 세 안 모두 **48px 이하**이며, 칸 52px 안에서 각 변 최소 1px 여백을 유지한다.

### 7.4 A안 상세 기하 — 좌표 검증

컨테이너: `.pc` 48×48, `box-sizing: border-box`, 테두리 2px, `border-radius: 12px`. 내부 콘텐츠 박스는 (2,2)–(46,46), 내부 모서리 반경 10px.

| 정보 행 글자 잉크 영역(근사) | 36.5 – 44.5 | 8.5 – 39.5 | 8 |

라운드 사각 모서리 안쪽 판정 (내부 반경 10, 좌상단 호 중심 (12,12), 좌하단 호 중심 (12,36)):

| 검사점 | 좌표 | 호 중심까지 거리 | 판정 |

### 7.6 아트 지침 — 작은 크기 가독성

CJ가 참고로 제시한 인벤토리 시트에서 가져오는 것은 **처리 방식**이다([CJ 지시] 3). 형태·색 조합은 가져오지 않는다([승계 원칙]).

- 큰 그림을 축소하는 것이 아니라 32px 전용으로 **다시 그린다**.
- 머리·얼굴 비중을 키운 2~2.5등신 압축 비례.
- 정면 또는 정면에 가까운 방향으로 고정.
- 색 단계를 줄이고 밝은 면·어두운 면 + 외곽선으로 형태를 만든다.
- 세부(무늬·장식·작은 무기)는 버리고 아키타입 특징 1~2개만 남긴다.

Earth 기준 제작 파라미터:

| 항목 | 값 |
|---|---|
| 그리드·파일·표시 | 32×32px 동일 (직납) |
| 배경 | 완전 투명 |
| 안전 여백 | 상하좌우 각 2px → 실제 아트 28×28px |
| 팔레트 | **8~12색 권장, 최대 16색 + 투명** |
| 접지선(발밑 기준) | **y = 29** (하단 경계 30) — 20종의 발 위치를 이 선에 맞춘다 |
| 시각 중심 | **x = 15.5** (32 그리드의 가로 중앙) |
| 외곽선 | **어두운 내부 외곽선**으로 형태를 잡되, 어두운 진영 배경(`#33406e`·`#6e3340`·`#3a4152`) 위에서 실루엣이 묻히는 구간에는 **밝은 1px 테두리를 필요한 곳에만** 덧댄다 |

**외곽선 규칙 보충 (Mars·Earth 확인)**: 말 배경이 어두운 색이므로 어두운 외곽선만으로는 실루엣 가장자리가 배경에 묻힌다. 전체를 밝은 테두리로 두르면 스티커처럼 보이므로, **내부는 어두운 외곽선 + 배경과 맞닿아 대비가 부족한 가장자리에만 밝은 1px 림**을 선택적으로 적용한다. 판정은 3종 배경색 위 실측으로 한다(14.1 AC).

파생 순서는 **원형 디자인 → 설명창 일러스트 → 전투 도트(64) → 말판 아이콘(32)** 이다([CJ 지시] 2). 말판 아이콘은 전투 도트를 기계적으로 반으로 줄인 결과가 아니라, 같은 실루엣을 32 그리드에서 다시 단순화한 결과여야 한다.

```css
.pc .icon { width:32px; height:32px; object-fit:contain; image-rendering:pixelated; }
```

### 7.7 기호 체계 — "같은 아이콘"이 성립하는 범위

CJ 지시 4번은 **지금 쓰는 메모 아이콘을 확정 표시에도 쓰라**는 것이다. 기준선은 **기존 이모지 8종을 그대로 재사용**하는 것이며, 새 기호 아트 제작은 필요 없다.

현재 `MEMO_OPTS` 8종 (코드 확인):

| 키 | 기호 | 뜻 | 확정 표시 재사용 |
|---|---|---|---|
| `king` | 👑 | 왕 | **같은 기호** |
| `ally` | 🤝 | 동료 | **같은 기호** |
| `bomb` | 💣 | 폭탄 | **같은 기호** |
| `trap` | 🪤 | 함정 | **같은 기호** |
| `minion_fire` | 🔥 | 불 하수인 | 확정 하수인의 **원소 기호**로 같은 기호 사용 |
| `minion_water` | 💧 | 물 하수인 | 〃 |
| `minion_grass` | 🌿 | 풀 하수인 | 〃 |
| `minion_lightning` | ⚡ | 번개 하수인 | 〃 |

**"같은 파일"이라고 말할 수 있는 범위와 없는 범위를 구분한다.**

- **성립**: 왕·동료·폭탄·함정 4종은 메모와 확정이 **완전히 같은 기호**다. 표시 대상이 곧 그 타입이기 때문이다.
- **성립**: 원소 기호 4종은 메모(속성 추측)와 확정(하수인의 속성 표시)에서 **같은 기호**다.
- **성립하지 않음**: 확정된 하수인은 **종 고유 아이콘(32px 래스터)** 을 함께 보여준다. 이 종 아이콘은 메모에 존재하지 않는다. 메모는 속성까지만 고를 수 있고, **숨겨진 실제 종을 메모가 표시해서는 안 되기 때문**이다. 따라서 "메모와 확정이 완전히 같은 그림"이라고 서술하면 사실이 아니다.

정리하면 표시 계층은 두 겹이다.

| 계층 | 메모(추측) | 확정(known) |
|---|---|---|
| 기호 계층 | 기존 이모지 1개 | **같은 이모지 1개** |
| 종 아트 계층 | 없음 | 종 고유 32px 아이콘 |

확정된 하수인 말에서는 종 아이콘과 원소 기호가 **서로 다른 영역**에 놓인다(7.4의 아이콘 영역 / 정보 행). 기호가 아이콘 위를 덮지 않는다.

**제작 수량에 대한 결론**: 기존 이모지를 재사용하므로 **말판 기호용 신규 래스터는 0장**이다. 전용 기호 세트(8종)를 별도 아트로 만드는 안은 **선택 사항이며 이번 필수 범위가 아니고 수량에 포함하지 않는다**.

**메모 선택지는 현행 8종을 유지한다 — 이유는 범위다.** 20종 단위 확장은 CJ 요청 범위 밖이므로 이번 개정에서 다루지 않는다. 플레이어가 손으로 고르는 종 단위 추측 자체는 정보 누출이 아니다. 추측은 플레이어의 판단이고 틀릴 수 있으며, 게임이 실제 정체를 알려 주는 것이 아니다.

지켜야 할 선은 **선택지 수가 아니라 값의 출처**다. 숨겨진 실제 종은 어떤 경우에도 **자동 선택되거나 추측 값으로 읽혀 들어가서는 안 된다.** 메모 값은 오로지 플레이어의 수동 입력에서만 나온다(7.8 규칙 3·4).

### 7.8 표시 상태 매트릭스

판정 근거는 코드에서 확인한 사실이다.

- 가시성 `visibleTo(viewer, e)`: `내 말` **또는** `숲 밖` **또는** `S.tempReveal`에 포함(일시 공개) **또는** 내 말과 인접
- 정체 인지 `known`: 내 말 **또는** `revealed` **또는** 전체 공개 시점(시뮬 관전 `viewer===2` · 종료 후)
- HP 텍스트: `known`이면서 `minion`·`ally`·`king`일 때만. **`bomb`·`trap`은 시뮬·종료 전체 공개에서도 HP를 표시하지 않는다.**

표시 규칙 **[CJ 지시 기반 계약 — rev7]**. 이 표는 "아이콘을 메모 형식으로 내 말·상대 말 모두 적용"(3장 후속 Comment 3 확정 3)을 행 단위로 푼 것이다. rev6까지 이 표는 승인 전 **[제안]** 이었고, 지금은 **구현 계약**이다. 각 행의 종 아이콘·기호·HP 유무는 **변경 없이 그대로** 계약이 되었다 — 지시가 표를 바꾼 것이 아니라 표의 지위를 바꿨다.

| 상태 | 종 아이콘 | 원소 기호 | HP | 테두리·투명도 |
|---|---|---|---|---|
| 내 말 — 하수인 | 종 고유 아이콘 | 표시 | 표시 | 실선 · 불투명 |
| 내 말 — 동료 / 왕 | 🤝 / 👑 | 없음(속성 없음) | 표시 | 실선 · 불투명 |
| 내 말 — 폭탄 / 함정 | 💣 / 🪤 | 없음 | **없음** | 실선 · 불투명 |
| 공개된 적 말(`revealed`) — 하수인 | 종 고유 아이콘 | 표시 | 표시 | 실선 · 불투명 |
| 공개된 적 말 — 동료 / 왕 | 🤝 / 👑 | 없음 | 표시 | 실선 · 불투명 |
| 공개된 적 말 — 폭탄 / 함정 | 💣 / 🪤 | 없음 | **없음** | 실선 · 불투명 |
| 미공개 적 말 + 메모 없음 | 없음 — `?` 텍스트 유지 | 없음 | 없음 | 실선 · 불투명 |
| 미공개 적 말 + 메모(속성 하수인) | **없음** | 추측한 원소 기호 1개 | 없음 | 점선 · 반투명 |
| 미공개 적 말 + 메모(왕·동료·폭탄·함정) | 해당 이모지 (확정과 같은 기호) | 없음 | 없음 | 점선 · 반투명 |
| 보이지 않는 말 (숲·비인접·tempReveal 아님) | 렌더 없음 | — | — | — |
| 시뮬 관전 / 종료 후 전체 공개 | 종 고유 아이콘 | 표시 | 하수인·동료·왕만 | 실선 · 불투명 |

**규칙 1 — 기호는 같다.** 메모와 확정은 같은 이모지를 쓴다([CJ 지시] 4). 종 아트는 확정에만 있다(7.7).

**규칙 2 — 추측 표식은 현행을 유지한다. [제안·연속성]** 메모는 플레이어의 추측이고 틀릴 수 있으므로, 현재 코드가 이미 쓰는 점선 테두리 + 불투명도 0.5를 그대로 둔다. 이는 새 결정이 아니라 **현행 동작 유지**다.

**규칙 3 — 미공개 정보가 어떤 경로로도 새지 않는다.** 아이콘 도입으로 새로 생기는 누출 경로가 있으므로 명시한다.

- 모르는 말에 대해 **종 아이콘 `<img>` 요소를 DOM에 만들지 않는다.** 숨긴 채 넣어 두면 개발자 도구로 읽힌다.
- **자산을 미리 요청하지 않는다.** 모르는 말의 종 아이콘 파일을 네트워크로 가져오면 요청 목록에서 정체가 드러난다. 프리로드가 필요하면 **게임 시작 시 20종 전체를 일괄** 받아 개별 말과 상관관계가 생기지 않게 한다.
- `alt`·`title`·`aria-label`에도 실제 종·속성·HP를 넣지 않는다. 미공개 말의 접근성 문구는 현행처럼 "정체 미공개 상대 말 — 내 추측: ○○" 수준으로 제한한다.
- `data-*` 속성, 클래스 이름, 파일 경로 문자열 어디에도 실제 종 키를 넣지 않는다.

**규칙 4 — 메모는 뷰어 전용이다.** 상대·AI·로그에 노출되지 않으며, AI의 공정 관측 원칙(CLAUDE.md)에 영향을 주지 않는다.

### 7.9 HP 표기 — 현재 HP 숫자 [CJ 결정]

> CJ Comment (2026-09-07): "HP 방식은 권장 방향으로 진행"

**확정: 아이콘 아래 별도 한 줄(정보 행)에 현재 HP 숫자를 표시한다.** 잔량 바 안과 숫자+바 혼합 안은 채택하지 않는다. 표시 대상은 `known` 판정을 통과한 **하수인·동료·왕**에 한하며, 폭탄·함정은 시뮬 관전·종료 후 전체 공개에서도 HP를 표시하지 않는다(7.8).

숫자를 택한 근거는 다음과 같다.

**규칙에서 비율이 쓰이는 곳 (코드 확인 사실)**: 적 포획 시도 조건 `상대 HP < 최대 HP x 0.3`, 도망 시도 조건 `자기 HP < 최대 HP x 0.5`, 전투 판정 `누적 피해 / 상대 최대 HP` 비교, 회복약·보호막·흡수 상한 모두 최대 HP 비율. 이 게임의 승패·행동 판단은 비율을 실제로 사용한다.

1. 위 임계값들은 **현재 HP와 최대 HP 두 값**이 있어야 계산된다. 숫자는 현재값을 정확히 주고 최대값은 로스터·정보 팝업에서 확인되므로 비율 환산이 가능하다. 바는 대략적인 비율만 주고 두 값 중 어느 것도 정확히 주지 않아 역방향 환산이 불가능하다.
2. 최대 HP가 85·90·95·100·120으로 달라 같은 바 길이가 서로 다른 절대값을 뜻한다.
3. 현행 말판·전투·로그·튜토리얼이 모두 숫자 기준으로 서술되어 있어, 숫자를 쓰면 이번 개정의 변경 범위가 아이콘 도입 하나로 좁아진다.
4. 세로 예산상으로도 숫자 한 줄이 유일하게 성립한다. 44px는 아이콘 32 + 간격 1 + 정보 행 11로 정확히 차 있어, 바를 더하려면 아이콘을 30px로 줄이거나(32 그리드 비정수 축소) 컨테이너를 48px 초과로 키워야 한다.

정보 행의 좌표와 폭 제약은 7.4에 있다. **이 결정은 HP 표기 방식에만 적용된다 — 이 점은 rev7에서도 그대로다.**

**rev7 갱신**: 아이콘을 말판에 표시하는 일 자체는 이제 승인되었다(3장 후속 Comment 3). 따라서 rev6까지 이 자리에 있던 "별도 게이트" 서술은 폐기한다. 그러나 **컨테이너 48px는 여전히 CJ가 지정한 수치가 아니라 이 문서의 기하 계산에서 나온 엔지니어링 선택**이며(3장 [추론] 표), 승인된 것은 "적용하라"이지 "48px로 하라"가 아니다. 이 구분을 유지한다.

### 7.10 "메모 형식 · 내 말과 상대 말 모두" — 게임 적용 계약 (rev7 신설)

CJ 지시 "아이콘은 메모 형식으로 내 말, 상대 말 모두 적용"을 구현 계약으로 푼다. 새 규칙을 만드는 절이 아니라 **7.7·7.8에 이미 있던 것을 하나의 계약으로 모으는 절**이다.

#### 7.10.1 공통 기호 체계 — 이것이 "메모 형식"의 뜻

말의 소유자가 누구든, 표시가 확정이든 추측이든 **같은 기호 어휘 하나만 쓴다.** 기존 `MEMO_OPTS` 8종(👑 🤝 💣 🪤 🔥 💧 🌿 ⚡)이 그 어휘이며 신규 래스터는 0장이다(7.7).

| 대상 | 종 아이콘 | 기호 | 표식 |
|---|---|---|---|
| **내 말 — 하수인** | 종 고유 `icon.png` 32px | 원소 이모지(🔥💧🌿⚡) | **실선 · 불투명** |
| **내 말 — 왕·동료·폭탄·함정** | 없음 | 기존 메모 이모지 그대로(👑🤝💣🪤) | **실선 · 불투명** |
| **공개된 상대 말(`revealed`) — 하수인** | 종 고유 `icon.png` 32px | 원소 이모지 | **실선 · 불투명** |
| **공개된 상대 말 — 왕·동료·폭탄·함정** | 없음 | 기존 메모 이모지 그대로 | **실선 · 불투명** |
| **미공개 상대 말 — 메모 없음** | **없음** | 없음 — 현행 `?` 텍스트 유지 | 실선 · 불투명 |
| **미공개 상대 말 — 뷰어가 메모를 지정함** | **없음** | 뷰어가 고른 8종 이모지 1개 | **점선 · 반투명(0.5)** |
| **보이지 않는 말** | 렌더 자체가 없음 | — | — |

**"확정은 불투명, 추측은 점선·반투명"이 확정 여부를 읽는 유일한 시각 신호다.** 이 두 표식은 현행 코드에 이미 있는 동작이며(`memo-guess` 클래스), 새로 만드는 것이 아니다.

#### 7.10.2 이 계약이 하지 않는 것 — 경계 4개

1. **미공개 상대 말에 종 아이콘을 붙이지 않는다.** "상대 말도 적용"은 **공개된 상대 말**에 확정 표시를 적용하고, 미공개 상대 말에는 **뷰어 자신의 메모**를 적용한다는 뜻이다. 게임이 숨긴 정체를 그림으로 알려주는 것이 아니다.
2. **메모 선택지를 늘리지 않는다.** 8종 그대로다(7.7). 20종 확장은 범위 밖이다.
3. **HP 규칙을 바꾸지 않는다.** 기존 `known` 조건의 하수인·동료·왕만, 아이콘 아래 현재 HP 숫자 한 줄. 폭탄·함정은 전체 공개에서도 표시하지 않고, 미공개 말과 메모 말에는 표시하지 않는다(7.8·7.9).
4. **가시성 판정을 바꾸지 않는다.** `visibleTo()`·`revealed`·`tempReveal`의 동작은 그대로다. 아이콘은 **이미 보이기로 결정된 말을 어떻게 그리는가**의 문제다.

#### 7.10.3 정보 은닉 — 아이콘 도입이 새로 만드는 누출 경로

텍스트 표시에는 없고 이미지 표시에만 생기는 위험이다. **이 절은 완화 불가이며 14.4가 판정한다.**

| 경로 | 왜 새로 생기는가 | 계약 |
|---|---|---|
| **URL·경로 문자열** | `icon.png`의 경로에 종 폴더명(`fire_std` 등)이 들어간다 | 모르는 말에 대해 그 경로를 **어디에도 만들지 않는다** — `src`·`data-*`·클래스명·CSS 변수 포함 |
| **DOM 존재** | 숨긴 채 넣어 둔 `<img>`는 개발자 도구로 읽힌다 | 모르는 말의 종 아이콘 `<img>` 요소를 **DOM에 만들지 않는다** |
| **네트워크 요청** | 말 하나가 개별 파일을 요청하면 요청 목록이 정체와 상관관계를 만든다 | 개별 요청 금지. 프리로드가 필요하면 **게임 시작 시 20종 일괄**만 허용 |
| **접근성 텍스트** | `alt`·`title`·`aria-label`은 화면에 안 보여도 읽힌다 | 미공개 말에는 실제 종·속성·HP를 넣지 않는다. 현행 수준(`정체 미공개 상대 말 — 내 추측: ○○`)을 유지한다 |

현행 코드는 미공개 말에 `hiddenId` 클래스와 위 문구의 `aria-label`만 쓰고 있어 이 기준을 이미 만족한다. **아이콘을 넣으면서 이 수준을 낮추지 않는 것**이 구현의 요구사항이다.

**이 절의 범위 — 오해를 막기 위해 명시한다.** 온라인 PVP는 기존 lockstep 구조상 `applyNetSetup`이 양측 배치를 클라이언트에 적용하므로 **상대 `rosterId`가 이미 클라이언트 메모리에 들어 있다.** 이는 이번 변경이 만든 것이 아니라 기존 구조의 성질이다. 따라서 이번 AC가 요구하는 것은 **아이콘 도입이 새로 만드는 렌더링·DOM·접근성·이미지 요청·네트워크 노출을 막는 것**까지이며, **서버 권위형 보안 구조 개편은 이 문서의 범위가 아니다**(필요해지면 별도 안건).

#### 7.10.4 적용 지점 4곳 — 한 곳만 바뀌면 안 된다

같은 기준이 `renderBoard`(말판) · 배치 트레이(`renderSetup`) · 메모 선택 모달(`memoModal`) · `renderSide`의 메모 목록에 **함께** 적용된다. 한 곳은 아이콘, 다른 곳은 텍스트로 남는 불일치를 만들지 않는다(14.3.8).

## 8. 제작 방식

| 방식 | 장점 | 문제점 | 판정 |
|---|---|---|---|
| 설명창 이미지 하나를 모든 화면에서 축소 사용 | 제작량 최소 | 전투에서 외곽선·표정이 뭉개지고 32px 말판에서는 형체를 알 수 없음 | 비권장 |
| 용도 3종을 각각 독립 설계 | 용도별 품질 최고 | 세 이미지의 캐릭터 정체성이 어긋날 수 있음 | 조건부 |
| 원형 디자인 확정 후 일러스트 → 전투 도트 → 말판 아이콘 순차 파생 | 품질과 정체성 동시 확보 | 최초 원형 확정 과정 필요 | **권장** |

제작 순서:

1. 하수인 한 종의 원형 디자인을 확정한다.
2. 512×512 설명창 일러스트를 제작한다.
3. 같은 실루엣을 64 그리드로 단순화해 전투 도트를 만들고 최근접 2배로 128 PNG를 납품한다.
4. 같은 실루엣을 32 그리드에서 **다시** 단순화해 말판 아이콘 32×32 PNG를 직접 납품한다. (축소가 아니라 재작업)
5. 세 이미지를 나란히 놓고 같은 캐릭터로 인식되는지 검사한다.

### 8.1 아이콘 제작 방식 — native 32 직접 픽셀 제작 [CJ 결정]

**제작 방식은 확정되었다.** CJ "구현 승인"(2026-09-07)이 **직접 native 32px 아이콘 제작**을 승인했다. 32×32 RGBA 캔버스에서 셀 단위로 직접 설계하며 — 팔레트 선고정, 알파 0/255만, 여백·접지선·시각 중심 직접 배치 — **전투 도트 축소·이미지 생성 도구 출력의 후처리는 쓰지 않는다.** 이 방식에 대해 다시 승인을 요청하지 않는다.

생성 도구 시험 2건(`earth-1-fire-std-generated-reference.png` · `earth-2-lightning-std-generated-reference.png`)은 규격 미달로 실패했다. 두 파일 모두 **1254×1254 RGB**이며 ① 1254 ÷ 32 = 39.1875로 32 그리드의 정수 확대본이 아니고 ② 알파 채널이 없어 배경 체크무늬가 실제 RGB 픽셀이며 ③ 고유색 103,697 / 81,249로 최대 16색을 크게 벗어난다. 두 파일은 **참고 이력**이며 납품물도 수량도 아니다.

**제작 파이프라인 (역할 분리)**

| 단계 | 담당 | 산출물 |
|---|---|---|

### 검수 기준

- 색을 빼고 흑백 실루엣으로 보아도 20종이 서로 구별된다.
- 128×128 전투 크기에서 얼굴 방향과 핵심 특징이 보인다.
- **32×32 말판 크기에서 20종이 서로 다른 아이콘으로 식별되고, 이름과 아이콘의 1:1 대응을 플레이어가 학습할 수 있다.** 속성·아키타입만 구별되면 된다는 완화 기준은 적용하지 않는다 — 20종 각각에 전용 아이콘을 만드는 이상, 32px에서 종이 뭉개지면 제작 목적 자체가 사라진다.
- 같은 하수인의 설명창·전투·말판 이미지가 동일 캐릭터로 인식된다.
- 캐릭터별 크기 차이가 있어도 발 위치와 시각적 중심은 일관된다.
- 기존 상용 캐릭터의 실루엣·색 배치를 연상시키는 디자인은 제외한다. ([승계 원칙])

- 아이콘의 **픽셀 원고**는 `docs/art/minions-v0.4.3/pixel-sources/<id>.json`, 전투 보정 패치는 같은 폴더의 `battle-patches/<id>.json`에 있다. 원고는 아트 소스이고 런타임 자산이 아니다 — 런타임에 놓이는 것은 Mars 도구가 출력한 `icon.png`뿐이다.
- 검수 시트는 `docs/art/minions-v0.4.3/review/`에 있다(대조 시트 · 3종 배경 시트 · 실루엣 시트 · 전투 보정 대조 4장). 검수 **근거 자료**이며 게임에 쓰지 않는다.
- 이 디렉터리의 원본·파생 아트는 Apache-2.0 적용 대상이 아니다 — `ASSET-LICENSE.md`의 자산 조건을 따른다.
- **자산 로딩 방식 [rev7 — 엔지니어링 선택]**: 하수인 이미지는 `demo/assets/minions/` **상대경로**로 로드한다. 결과로 **`index.html` 한 파일만 복사하면 되는 완전 단일 파일 구조는 유지되지 않는다.**
  - **대안이 없어서가 아니다.** 자산을 data URI로 HTML에 인라인하는 방법은 실제로 가능하다. 상대경로를 고른 근거는 **로컬 오프라인 실행 · 정적 호스팅 · 버전 관리 비용** 세 가지를 견준 판단이다 — 인라인은 `index.html`을 크게 부풀리고 이미지 한 장만 바꿔도 HTML 전체가 diff에 잡힌다.
  - 오프라인 실행은 여전히 서버 없이 가능하다 — `index.html`과 `assets/` 폴더를 **함께** 둔 채 브라우저로 열면 된다. 달라지는 것은 "한 파일"이 "한 폴더"가 되는 것이다.
  - **CJ는 이미지 적용을 승인했을 뿐 배포 방식을 지시하지 않았다.** 이 선택은 구현자 판단이며, 근거가 달라지면 바꿀 수 있다(3장 [추론] 표). 저장소 운영 계약(CLAUDE.md "HTML 데모" 절)에 현재 방식이 기록되어 있다.
  - rev6까지 이 자리에 있던 "이 원칙 완화는 CJ 결정 대기 사항"이라는 서술은 **폐기한다**(15장).

## 13. 뷰포트 — 있는 그대로

**말판에는 반응형 규칙이 없다.** `@media` 3개는 모두 튜토리얼 오버레이 전용이고, `#board`는 `repeat(7, 52px)` 고정이다. 따라서 화면이 좁아져도 말판은 줄지 않는다.

현재(변경 전) 최소 요구 폭:

| 범위 | 계산 | 폭 |
|---|---|---:|
| 말판만 | 7×52 + 6×2 | 376px |
| 왼쪽 패널 (`.panel` 좌우 padding 10 + border 1) | 376 + 22 | 398px |
| 전체 레이아웃 (`#app` flex, 줄바꿈 없음, `#right` `min-width:300px`, gap 12, padding 24) | 398 + 12 + 300 + 24 | **734px** |

이 값이 뜻하는 것:

- **360px 뷰포트**: 현재도 가로 스크롤이 발생한다. 말판 한 열도 잘린다.
- **394px 뷰포트**: 현재도 가로 스크롤이 발생한다. 말판(376px)만 놓고 보면 들어가지만 패널 여백(398px)과 2열 레이아웃(734px) 때문에 실제로는 스크롤된다.
- **데스크톱(≥734px)**: 스크롤 없이 표시된다.

이번 변경은 칸 52px와 말판 376×700px를 **그대로 두므로**, 위 상황을 나쁘게도 좋게도 만들지 않는다. 말(42→48px)은 칸 안에서만 커진다.

따라서 이 문서는 **"모바일에서 정상 표시된다"고 주장하지 않는다.** 모바일 대응은 별도 안건이며 이 문서의 범위가 아니다. 수용 기준은 "동작한다"가 아니라 "변경 전과 동일하다(회귀 없음)"로 기술한다.

## 14. 수용 기준 (AC)

판정 기준 자체는 rev3에서 하나도 완화·변경하지 않았다. **rev7에서도 AC 문구는 한 글자도 바꾸지 않았다.** 달라진 것은 **적용 시점**뿐이다.

- **14.1 아트 납품**: 산출물이 나왔고 Saturn ART 최종 검수와 CJ 디자인 확인이 끝났다. 항목별 충족 현황은 아래 상태 표에 적는다.
- **14.2~14.6 (말판 표시 기하·표시 규칙·정보 은닉·뷰포트·회귀)**: 게임 화면 적용의 현행 판정 기준이다. Mars 구현·실측과 **Saturn 독립 QA PASS**를 확인했다. 실제 기기·비Chrome 등 미검증 영역을 포함한 판정 범위는 8.2.3 및 독립 보고서에 기록한다.

**게이트가 열렸다고 기준이 낮아지는 것이 아니다.** 14.2~14.6은 통과해야 할 항목이 되었을 뿐, 어느 항목도 삭제·완화되지 않았다.

### 14.1 아트 납품

1. 하수인 20종 각각에 `portrait`(512×512) · `battle.png`(128×128) · `icon.png`(32×32)가 존재한다.
2. `icon.png`는 32×32 그리드에서 직접 제작되고 배경이 완전 투명이다. 확대·축소본이 아니다.
3. `icon.png`의 실제 아트가 상하좌우 2px 여백 안(28×28)에 들어간다.
4. `icon.png` 팔레트가 투명 제외 16색 이하이며, 권장 범위는 8~12색이다.
5. `battle.png`는 64 그리드의 최근접 2배 확대 결과와 픽셀 단위로 일치한다.
6. 같은 종의 세 이미지를 나란히 놓았을 때 동일 캐릭터로 인식된다.
7. 흑백 실루엣 변환 후에도 20종이 서로 구별된다.
8. 기존 상용 캐릭터의 실루엣·색 배치를 연상시키는 디자인이 없다.
9. 말판 기호용 신규 래스터 파일은 납품물에 포함되지 않는다(기존 이모지 재사용).
10. **실제 배경색 위 대비 판정**: `#33406e`(0번)·`#6e3340`(1번)·`#3a4152`(정체 미공개) 세 배경 위에 아이콘을 얹어 실루엣 가장자리가 배경에 묻히지 않는다. 어두운 내부 외곽선만으로 부족한 구간에 밝은 1px 림이 들어갔는지, 그리고 그 림이 전체를 두르지 않고 필요한 곳에만 있는지 확인한다.
11. 20종의 발 위치가 접지선 y=29(하단 경계 30)에, 시각 중심이 x=15.5에 정렬된다.

**14.1 현재 충족 현황 (2026-09-07 rev6 — 기준 완화 아님. 수량·QA의 원본은 8.2)**

AC 문구는 rev3 이후 하나도 바뀌지 않았다. 아래는 각 AC가 **어떤 종류의 판정을 요구하는지**와 그 판정이 지금 어디 있는지를 가리키는 표다.

### 14.2 말판 표시 기하

1. 칸 `.cell` 52×52px, 말판 376×700px가 변경 전과 동일하다.
2. 말 컨테이너가 48×48px 이하이며 칸 안에서 각 변 최소 1px 여백을 유지한다.
3. 아이콘이 32×32px, `image-rendering: pixelated`로 1:1 표시된다.
4. **HP·원소 기호·강조 효과 중 어느 것도 아이콘 영역(32×32 박스)을 덮지 않는다.** 정보 행은 아이콘 아래 별도 행이다.
5. 실제 렌더에서 아이콘 아트(28×28)와 정보 행 글자가 컨테이너 모서리에 잘리지 않는다 — 7.4 검사점 6개를 실제 브라우저에서 확인한다.
6. `.pc.own` 강조가 칸 경계를 넘지 않는다.
7. 배치 단계 트레이의 말도 같은 규격으로 표시되고 트레이가 의도치 않게 줄바꿈되지 않는다.
8. **선명도 실측**: DPR 1 / 1.25 / 1.5 / 2와 브라우저 확대 100% / 125%에서 말판 아이콘과 전투 도트를 확인한다. CSS px가 정수라는 이유만으로 통과 처리하지 않는다(4장). 특정 조합에서 보간이 보이면 그 조합을 기록하고 허용 여부를 판단한다.

### 14.3 표시 규칙

1. 내 하수인은 종 아이콘 + 원소 기호 + HP를 함께 보여준다.
2. 내 동료·왕은 기존 이모지 + HP를 보여준다.
3. 폭탄·함정에는 HP가 표시되지 않는다. **시뮬 관전·종료 후 전체 공개에서도 마찬가지다.**
4. 미공개 적 말에는 HP가 표시되지 않는다. 메모가 설정된 말도 마찬가지다.
5. 메모 표시는 기존 이모지 8종만 쓰고, 종 고유 아이콘을 절대 쓰지 않는다.
6. 메모 추측 말은 현행과 같이 점선 테두리 + 불투명도 0.5로 확정과 구별된다.
7. 메모 선택지가 현행 8종에서 늘거나 줄지 않는다.
8. **적용 범위 (Mars 읽기 전용 분석 결과)**: 아이콘·기호·표시 규칙이 `renderBoard`(말판), `renderSetup` 트레이(배치 단계), 메모 선택 모달(`memoModal` 피커), `renderSide`의 메모 목록 **네 곳에 같은 기준으로 적용**된다. 한 곳만 아이콘으로 바뀌고 다른 곳이 텍스트로 남는 불일치가 없다.

### 14.4 정보 은닉

1. `visibleTo()`가 거짓인 말은 여전히 렌더되지 않는다. `tempReveal`에 의한 일시 공개 동작도 변경 전과 동일하다.
2. 모르는 말에 대해 종 아이콘 `<img>` 요소가 DOM에 존재하지 않는다.
3. 모르는 말의 종 아이콘 파일이 네트워크로 요청되지 않는다. 프리로드를 쓴다면 게임 시작 시 20종 일괄 방식이어서 개별 말과 상관관계가 생기지 않는다.
4. 미공개 말의 `alt`·`title`·`aria-label`·`data-*`·클래스명에 실제 종·속성·HP가 들어가지 않는다.
5. AI가 참조하는 관측 정보가 변하지 않는다. 아이콘은 표시 계층에만 영향을 준다.

### 14.5 뷰포트 (13장 기준 — 회귀 없음 판정)

1. **360px**: 변경 전과 동일하게 가로 스크롤이 발생하며, 스크롤 시 말판 전체를 볼 수 있다. 변경으로 스크롤 폭이 늘지 않는다.
2. **394px**: 위와 동일.
3. **데스크톱(≥734px)**: 가로 스크롤 없이 말판 전체와 오른쪽 패널이 표시된다.
4. 세 조건 모두 **"정상 표시"가 아니라 "변경 전 대비 동일"** 을 판정한다.

### 14.6 회귀

1. **게임 규칙 스모크 테스트와 AI vs AI 완주는 그대로 통과해야 한다** — 이동·상성·폭탄·함정·밀어내기·왕 불가침·판정. 표시 계층 변경이 규칙을 건드리면 안 된다.
2. **`smoke_memo.js`는 예외다.** 이 테스트는 현재 말 내부의 텍스트·DOM 구조를 하드코딩해 검사하므로, 표시가 텍스트에서 아이콘으로 바뀌면 그대로는 통과하지 않는다. 구현 PR에서 **Mars가 새 DOM 구조에 맞게 테스트를 갱신**하고, 그 뒤 Saturn이 READ_ONLY로 QA한다. "기존 DOM 단언이 하나도 바뀌지 않고 전부 통과해야 한다"는 기준은 적용하지 않는다.
3. 테스트 갱신은 검사 대상을 약화시키지 않아야 한다 — 메모 설정·삭제·뷰어 격리·미공개 말 정보 비노출은 새 구조에서도 동일하게 검사된다.
4. 아이콘 파일이 없거나 로드에 실패해도 게임이 진행된다 — 대체 표시는 현행 텍스트 방식으로 복귀한다(15장 엔지니어링 제안).

## 17. 결론

**원본 20종 반입은 PR #86으로 끝났고, 아이콘 20종은 CJ가 승인한 native 32 직접 제작 방식으로 전량 출력되어 기술 규격을 충족했으며, Saturn 최종 20종 ART 검수와 CJ 디자인 확인까지 완료되었다. 게임 화면 적용은 2026-09-07 CJ Comment로 승인되어 구현 단계에 들어간다 — 더 이상 승인 게이트가 아니다.** 수량·기술 실측·QA 판정의 유일한 원본은 **8.2**다.

**지금 사실인 것과 아직 사실이 아닌 것을 먼저 구분한다.**

| 완료 | 아직 아님 |
|---|---|
| 아트 산출물 100파일 · 기술 규격 20/20 | 게임 화면 적용 코드 |
| Saturn ART 20/20 PASS · Technical PASS | 그 코드의 Saturn READ_ONLY QA |
| **CJ 디자인 확인** | 실제 화면의 로딩·HP·DPR·선명도·모바일 회귀 실측 |
| 게임 적용 **승인** | **CJ 플레이 QA** · AC 8(권리 체인·유사성 검증) |

- 설명창: 512×512 제작, PC 192×192 표시 (비정수 축소, 일반 일러스트)
- 전투: 64 그리드 작업 → 128 파일(최근접 2배) → 128 표시, 전투 영역 높이 200px
- 말판 아이콘: **32 그리드 = 32 파일 = 32 표시** 직납, 투명 배경, 팔레트 8~12색(최대 16), 여백 2px, 접지선 y=29 · 시각 중심 x=15.5
- 말판 기하: 칸 **52px 불변**, 말 컨테이너 **48px 이하**, 아이콘 32 + 간격 1 + 정보 행 11 = 44 (겹침 없음). 권장은 라운드 사각(A안)이며 원형 유지 시 원소 기호 병기를 포기해야 한다(B안)
- **HP 표기: 현재 HP 숫자, 아이콘 아래 한 줄 — [CJ 결정] 확정.** 대상은 `known` 판정을 통과한 하수인·동료·왕
- 기호: **기존 메모 이모지 8종을 확정 표시에 그대로 재사용** — 신규 래스터 0장. 확정 하수인만 종 고유 아이콘을 추가로 가지며, 메모 값은 플레이어 수동 입력에서만 나온다
- 필수 설계: **하수인 20종 × 3용도 = 논리 60** (물리 100파일). 산출물은 전량 존재하고 기술 규격을 충족했으며 **사람 시각 판정(AC 6·7·10·11)은 Saturn 최종 ART PASS와 CJ 디자인 확인으로 충족되었다.** 다만 이는 **정적 검수 기준**이며 실제 게임 화면·권리 검증(AC 8)은 별개다 (8.2 · 14.1)
- 연결 대상: **portrait 192px → 배치 단계 하수인 설명창**(`rosterInfo` 모달, Issue #89에서 연결) · **battle 128px → 하수인 전투 토큰**. **왕·동료 본체는 종 자산이 없어 현행 이모지 표현을 유지한다.** 포획 하수인은 rev8(Issue #91 계약, 진행 여부는 Issue·PR 참조)부터 숲 공용 포획 = 속성 표준형 스탠드인, 적 포획 = 원래 종 외형 정체 보존·원래 종 그림으로 연결한다 — 표시 전용 메타데이터, 신규 아트 없음 (5.3 · 6.3)
- 적용 계약: **메모 형식 공통 기호 체계를 내 말·상대 말 양쪽에 적용.** 확정(내 말·공개된 상대 말)은 실선·불투명, 추측은 점선·반투명 0.5, 미공개·메모 없음은 현행 `?`. **미공개 말에는 종 아이콘·경로·DOM·네트워크 요청·접근성 텍스트 어디에도 정체가 남지 않는다** (7.10)
- 아이콘 제작 방식: **native 32 직접 픽셀 제작 — [CJ 결정] 확정.** 축소·생성 후처리는 쓰지 않는다. 재승인을 요청하지 않는다 (8.1)
- 납품 파이프라인: Earth 원고(`pixel-sources/`·`battle-patches/`) → Mars 도구 PNG 출력·검증 → Saturn 읽기 전용 검수. Earth_1 불·물 / Earth_2 풀·번개, 파일럿 4종 → QA → 나머지 16종. 단일 Issue #87 + 통합 PR 1개
- 보존 사실: PR #86 기준선 80파일 중 **72장이 바이트 무변경**이고, 바뀐 것은 **CJ가 승인한 4종의 전투 8장**뿐이다. 신규는 `icon.png` 20장이다 (8.2.1)
- 적용 범위: `renderBoard` · 배치 트레이 · 메모 선택 모달 · `renderSide` 메모 목록 네 곳에 같은 기준을 **함께** 적용 (7.10.4)
- 구현 구조: `demo/assets/minions/` **상대경로 로딩을 채택한다.** 단일 HTML 원칙은 이 범위에서 완화된다(한 파일 → 한 폴더). 이는 로컬 오프라인·정적 호스팅·버전 관리 비용을 견준 **엔지니어링 선택**이며 인라인 등 대안은 존재한다 — CJ는 이미지 적용을 승인했을 뿐 배포 방식을 지시하지 않았다 (11장)
- 뷰포트: 말판은 고정 크기이며 360·394px에서는 현재도 가로 스크롤이 발생한다. 이번 변경은 이를 악화시키지도 개선하지도 않는다 — 판정 기준은 "정상 표시"가 아니라 **"변경 전 대비 동일"** 이다 (13장·14.5)
- **CJ가 지정하지 않은 것**: 48px 컨테이너·라운드 사각·정보 행 11px·52px 칸·상대경로·`pixelated`는 이 문서의 계산과 코드 실측에서 나온 **엔지니어링 선택**이다. 승인된 것은 "적용하라"이지 개별 px가 아니다 (3장 [추론] 표)

7.4의 좌표 기하는 CSS 값 계산 결과다. Mars 구현 단계에서 3자리 HP의 실제 폰트 렌더링 폭, 브라우저별 라운드 사각 클리핑, DPR·확대율별 선명도를 실측하고 차이가 나오면 이 문서의 수치를 그 결과로 갱신한다. `smoke_memo.js`는 구현 PR에서 Mars가 새 DOM 구조에 맞게 갱신하고 Saturn이 READ_ONLY로 QA한다.

**착수 조건 — 충족되었다.** 아트 납품·CJ 디자인 확인·2026-09-07 게임 적용 승인에 따라 **Mars 구현·실측 및 Saturn 독립 QA를 완료했다**. [PR #90](https://github.com/ChangjoSung/Digit-Duel/pull/90)에 취합했으며 남은 절차는 CJ 플레이 QA다. 같은 구현 승인을 다시 묻지 않는다.

**역할 경계 (변경 없음)**: 이 문서는 기획 계약이다. `demo/index.html`·테스트·도구 구현은 **Mars**, 구현 결과의 QA는 **Saturn(READ_ONLY)**, GitHub·Notion·Git 쓰기는 **Mercury(PD)** 소관이다. 아트 100파일·픽셀 원고·출력 도구는 검수 완료본이므로 **이번 구현에서 변경하지 않는다.**
