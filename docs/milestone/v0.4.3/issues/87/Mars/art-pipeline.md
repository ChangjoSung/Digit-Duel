## 2. 명령

```bash
# 파일럿 부분집합 — 나열한 종의 소스·패치가 모두 있어야 한다
python tools/minion_art.py --ids fire_sustain,water_swift,grass_atk,lightning_atk

# 납품 게이트 — 20종 소스 + 허용 4종 패치가 모두 있어야 하며 하나라도 없으면 실패(exit 1)
python tools/minion_art.py --all

# 기존 산출물 검증 — 어떤 파일도 다시 쓰지 않는다
python tools/minion_art.py --all --check

# 미리보기 시트 생략
python tools/minion_art.py --ids fire_sustain,water_swift,grass_atk,lightning_atk --no-preview
```

| 플래그 | 뜻 |
|---|---|
| `--ids a,b,c` | 종 부분집합. 요청한 종의 소스가 없으면 **건너뛰지 않고 실패한다** — 조용히 아무것도 만들지 않고 성공을 주장하지 않는다 |
| `--all` | 로스터 20종 전량 (납품 게이트). 소스 20개 + 허용 4종 패치가 모두 있어야 한다 |
| `--check` | 산출물을 덮어쓰지 않고 바이트 일치만 검사한다. 불일치·누락이면 exit 1 |
| `--no-preview` | 검토용 시트를 만들지 않는다 |
| `--repo-root PATH` | 저장소 루트 지정 (테스트·검증용). 기본값은 도구 파일의 상위 디렉터리 |

종료 코드: `0` 정상 · `1` 데이터/규격 위반 또는 검사 불일치 · `2` 인자 오류(안전하지 않은 id 포함).

Windows에서 stdout/stderr을 UTF-8로 재설정하므로 cp949 콘솔에서도 한글 메시지가 깨지지 않는다.

## 3. 아이콘 소스 계약 — `pixel-sources/<id>.json`

```json
{
  "id": "fire_sustain",
  "width": 32,
  "height": 32,
  "palette": { "k": "#1a1020", "r": "#d2673a", "y": "#f2a154" },
  "pixels": ["................................", "... 32행 x 32자 ..."],
  "notes": "설계 의도 메모 (한글 가능)"
}
```

| 필드 | 규칙 |
|---|---|
| `id` | 로스터 20종 폴더명과 정확히 일치. 파일 이름(stem)과도 일치해야 한다 |
| `width`·`height` | **32 고정** |
| `palette` | 공백이 아닌 ASCII **한 글자** 기호 → `#RRGGBB` 또는 `#RRGGBBAA`. 불투명 색 **최대 16개** |
| `pixels` | 정확히 **32개 문자열**, 각 문자열 정확히 **32자** |
| `notes` | 자유 서술 (검증에 쓰지 않음) |

- `.` 은 투명 예약 기호이며 값은 `#00000000` 뿐이다. 다른 기호는 투명색을 가질 수 없다.
- 알파는 **0 또는 255만** 허용한다. 중간 알파(`#RRGGBB80` 등)는 거부한다.
- 행 0·1·30·31과 열 0·1·30·31은 전부 `.` 이어야 한다 (여백 2px, AC 14.1.3).
- 아트의 가장 아래 불투명 픽셀 y는 **정확히 29** 여야 한다 (접지선, AC 14.1.11).
- 불투명 외접상자의 가로 **중점**은 **15.5 ± 1.0** 이어야 한다.
  **이것은 AC 14.1.11 시각 중심의 기하 대리 지표(proxy)이지 시각 중심 판정이 아니다.**
  외접상자 중점은 사람이 느끼는 무게중심을 측정하지 않는다 — 질량이 한쪽에 쏠려도 양끝만 대칭이면 통과하고,
  반대로 뻗은 무기 하나 때문에 중점이 밀려도 그림은 중앙에 보일 수 있다.
  **이 검사를 통과한 것은 AC 14.1.11 통과가 아니다.** 시각 중심의 실제 판정은 Saturn의 독립 지각 QA가 하며,
  이 도구는 그 판정을 대체하지도 완화하지도 않는다. AC 자체는 승인된 그대로다.
  1.0px 허용 오차는 좌우 비대칭 포즈(뻗은 팔·꼬리)를 위한 대리 지표의 여유값이다. 초과하면 거부한다.
- 실제 사용 색이 권장 8~12색 밖이면 **경고**만 남긴다(최대 16색은 하드 거부).
  선언만 하고 쓰지 않은 팔레트 기호도 경고 대상이다.

## 4. 전투 보정 계약 — `battle-patches/<id>.json`

```json
{
  "id": "fire_sustain",
  "baseline": "202edf3c23e65453bd7db8dd9fed5fdf0587fd0d",
  "pixels": [[28, 34, "#ff8c2a"], [29, 34, "#ffd27a"], [30, 40, "#00000000"]],
  "notes": "손끝 불꽃과 주황 균열 복원 — 전체 재설계 아님"
}
```

- 허용 대상은 Saturn 원본 QA가 128px 가독성 REVISE 의견을 낸 **4종뿐**이다:
  `fire_sustain` · `water_swift` · `grass_atk` · `lightning_atk`. 그 외 id는 거부한다.
- `baseline`은 고정 커밋 `202edf3c23e65453bd7db8dd9fed5fdf0587fd0d` 이어야 한다.
  도구는 **작업 트리가 아니라 이 git 객체**에서 `battle-grid.png`를 읽으므로,
  같은 패치를 몇 번 실행해도 결과가 같고(멱등) 이전 실행 결과가 다음 실행의 입력이 되지 않는다.
- `pixels`는 기존 64 그리드 위의 좌표 덮어쓰기다. `x`·`y`는 정수 0~63, **좌표 중복 금지**.
- 색은 `#RRGGBB`(불투명) 또는 알파 `00`/`FF`. 중간 알파 거부.
- 보정 결과가 캔버스 경계(행·열 0 또는 63)에 불투명 픽셀을 만들면 거부한다.
- 도구는 보정된 64 그리드를 저장하고 `battle.png`를 **최근접 정확한 2배**로 다시 만든다 (AC 14.1.5).

## 5. 도구가 하는 검사 (거부 = exit 1)

| 분류 | 검사 |
|---|---|
| 경로 안전 | id는 `^[a-z]+_[a-z]+$` 이면서 로스터 20종에 실재해야 한다. `../`·`/`·대문자·확장자·후행 공백 전부 거부 |
| 스키마 | 행 수·행 길이·캔버스 크기·팔레트 기호 길이·JSON 파싱 |
| 색 | 미지 기호, 중간 알파, 비 `.` 기호의 투명색, `.` 재정의, 팔레트/실사용 16색 초과 |
| 기하 | 2px 여백 침범, 접지선 y≠29, 외접상자 중점 대리 지표 이탈, 불투명 픽셀 0개 |
| 패치 | 허용 목록 밖 id, baseline 불일치, 좌표 범위 초과·비정수·중복, 빈 패치, 경계 잘림 |
| 보존 | 저장소의 모든 원본·전투 자산이 **합법적인 값**인지 매 실행마다 확인 (5.1) |
| 납품 축소 | 이미 매니페스트에 등록된 종을 빼고 부분집합으로 실행하는 것 (5.3) |

### 5.1 보존 — 면제가 아니라 검증

보존 검사는 **어떤 파일도 면제하지 않는다.** 파일마다 허용되는 값을 정해 놓고 실제 바이트를 그 값과 대조한다.

| 파일 | 합법적인 값 |
|---|---|
| `portrait.png`·`portrait.webp` (40장) | 기준 커밋 바이트 **하나뿐** |
| 전투 파일 — 보정 데이터 없음 | 기준 커밋 바이트 **하나뿐** |
| 전투 파일 — 보정 데이터 있음 | 기준 커밋 원본 **또는** 그 패치를 기준에 적용한 결과, 둘 중 하나 |

그래서 `--ids`로 한두 종만 다시 내보내도 **이번 대상이 아닌 이미 보정된 허용 종**이 "원본 위반"으로
오판되지 않는다. 동시에 허용 목록에 있다는 이유로 검사를 건너뛰지도 않는다 — 그 파일이 정말 그 패치의
결과인지 다시 계산해 대조한다. 파이프라인 밖에서 손댄 파일은 어느 쪽과도 맞지 않으므로 잡힌다.
보정 데이터를 읽을 수 없으면 "검증 불가"를 위반으로 보고한다. 조용히 통과시키지 않는다.

**보존 검사는 이 파이프라인의 안전벨트다.** 도구가 원본을 건드리지 않았다는 주장을 매 실행이 스스로 증명한다.

### 5.2 순서가 계약이다 — 실패하면 한 개도 쓰지 않는다

```text
1) 계획   요청한 입력을 전부 읽고 검증해 산출물 바이트를 메모리에 완성
2) 검증   저장소 자산 보존 + 납품 축소 여부 확인 (이번 실행이 덮어쓸 경로는 제외)
3) 기록   그제서야 파일을 쓴다. 바이트가 같으면 다시 쓰지 않는다
4) 재확인 기록 후 제외 없이 전수 보존 확인
```

1·2단계에서 실패하면 **자산·매니페스트·미리보기가 한 개도 바뀌지 않는다.** 20종 중 16종의 소스가
아직 없거나, 네 번째 종의 데이터가 규격 위반이어도, 먼저 처리된 종의 아이콘이 반쯤 기록되는 상태가 없다.
CLI는 이때 `NOTE 검증 실패 — 이번 실행은 파일을 하나도 쓰지 않았습니다`를 함께 출력한다.

### 5.3 납품 기록은 줄어들지 않는다

집계 산출물(대조 시트 3장·매니페스트)은 그 실행의 id 집합만 담는다. 따라서 이미 등록된 종을 빼고
부분집합으로 실행하면 납품 기록이 조용히 줄어든다. 도구는 그것을 실패로 만든다 —
빠진 종을 `--ids`에 포함하거나 `--all`로 실행하라고 알리고, 아무것도 쓰지 않는다.

스키마는 나쁜 아트를 숨기려고 완화하지 않는다. 데이터가 규격을 못 맞추면 도구를 고치는 것이 아니라 데이터를 고친다.

## 7. 테스트

```bash
python -m unittest discover -s tests
```

68개 테스트. **저장소에 픽스처 파일을 남기지 않는다.** 데이터 검증 테스트는 임시 디렉터리를 쓰고,
드라이버 테스트는 임시 폴더에 저장소를 복제해(clone) 그 복제본 안에서만 쓰고 지운다.
실제 저장소를 쓰는 테스트는 읽기 전용이다 — 기준 커밋 blob 읽기, `--check` 실행, 자산 합법성 확인.

주요 커버리지:

- 소스→PNG 왕복 픽셀 일치 · 결정적 인코딩 · 5장 거부 항목 전수 · 패치 적용의 비대상 픽셀 불변 · 최근접 2배 정확성
- **원자성**: 뒤쪽 종의 데이터가 규격 위반일 때 앞쪽 종의 아이콘·매니페스트·미리보기가 하나도 쓰이지 않음 ·
  `--all`의 16종 누락이 준비된 4종을 부분 기록하지 않음 · 보존 위반이 모든 기록을 막음 (mtime·바이트 지문 대조)
- **보존**: 부분집합 실행이 이미 보정된 다른 허용 종을 오판하지 않음 · 허용 종이라도 패치와 무관한 내용이면 잡힘 ·
  패치 없는 허용 종의 원본 상태가 합법 · 기록된 전투 파일이 재계산 값과 일치
- **라벨**: 실루엣 시트가 실제 배율(2×)을 말함 · 대조/배경 시트는 실제 4× · 외접상자 중점이 코드·오류문구에서 대리 지표로 표기됨
- **입력 누락**: 명시 요청한 종의 소스 누락이 실패로 처리됨 · 허용 종은 패치도 요구됨 · 부분집합이 매니페스트를 줄이지 못함
- **CLI**: UTF-8 출력(cp949 콘솔에서 한글 유지) · 안전하지 않은 id 인자 거부(exit 2) · 선택자 없음 거부 · `--check`가 자산 mtime을 바꾸지 않음

## 8. 범위 밖

- `demo/index.html` 등 제품 코드 연결은 **미승인**이다. 이 파이프라인은 자산만 만든다.
- 32px 사람 식별성·상용 캐릭터 유사성·권리 체인은 도구가 판정할 수 없다. Saturn·CJ 판단 영역이다.
- DPR·브라우저 확대율 선명도(AC 14.2.8)는 실제 렌더 환경에서만 확인할 수 있다.
