## 1. 시간 — 이번 제작 선택이지 과거 승인 수치가 아니다

`BAL.fx` 를 **한 값도 바꾸지 않았다.** `resultBanner` 는 종전 그대로 **2500ms** 이고 #125 가 1.2초로 줄인 12키에도 손대지 않았다.
새 연출은 그 2500ms **안에서** 재생된다. 실제 브라우저에서 `getComputedStyle` 로 읽은 값은 다음과 같다 (확정 — 실측).

아래 값은 **실제 브라우저에서 애니메이션이 걸린 요소·의사요소를 전부 훑어** `getComputedStyle` 의
`animationDelay + animationDuration` 최댓값을 읽은 것이다. 스태거 개수·간격을 코드에서 베껴 쓰지 않는다.

| 갈래 | 배너 임팩트 | 섬광/빛줄기/균열/링 | 파편 (마지막 = 지연 + 지속) | **동작 구간 (실측 최댓값)** |
|---|---|---|---|---|
| 승리·중립 | `fxWinIn` 620 | `fxFlash` 550 · `fxRays` 860 | `fxBurst` 880 + 지연 180 = 1060 | **1060ms** |
| 패배 | `fxLoseIn` 720 | `fxDark` 800 · `fxCrack` 860 | `fxFall` 900 + 지연 180 = 1080 | **1080ms** |
| 포획 | `fxCapIn` 500 | `fxRing` 700 | `fxConverge` 780 + 지연 150 = 930 | **930ms** |
| 경기 무승부 | `fxCapIn` 500 | `fxDrawL`·`fxDrawR` 800 | (파편 없음) | **800ms** |

**정정 (Saturn REVISE):** 1차 보고의 승리 1174ms · 패배 1338ms 는 **틀린 값이다.** 그때는 검사 코드가
스태거를 `16 × 14ms` · `16 × 18ms` 로 하드코딩했는데 실제 CSS 는 16개(index 0~15)에 12ms 간격이었다.
지금은 실제 computed 값을 읽으므로 위 표가 유효한 측정이고, 앞의 두 숫자는 최종 증거로 재사용하지 않는다.

**약 0.8~1.1초가 강한 동작 구간이고, 남은 시간은 결과 문구가 정지 상태로 읽히는 홀드 구간이다.**
이 배분은 **이번 제작 선택**이다. #125 는 `resultBanner` 2500ms 를 단축 대상에 넣지 않았으므로, 이 숫자를 과거 승인 고정값이라고 주장하지 않는다.
**추가 대기를 만들지 않았다** — 새 연출 키·새 상수·새 클릭을 하나도 추가하지 않았고, 잠금 해제 시각은 종전 `resultBanner` 와 같다.
반복 점멸이 없고 모든 CSS 애니메이션이 유한(`forwards`)이라 배너가 닫힌 뒤 도는 것이 남지 않는다.

## 2. 시각 어휘 (확정)

- **승리 / 중립(핫시트)** — 흰 섬광 → 회전하는 금빛 빛줄기 → 방사 파편 16개, 배너는 과잉 스케일로 튀어 들어온다. 결과 문구는 금색.
- **포획 성공** — Earth 스토리보드대로 **경기 승리처럼 화면 전체를 축하하지 않는다.** 금빛 섬광·빛줄기·방사 파편·승리 상자를 쓰지 않고, 작은 중립색 링이 **수렴**하고 파편이 가운데로 모이는 어휘만 쓴다. 결과 문구는 중립 아이보리. (초기 구현은 포획이 승리 갈래를 공유했고 Saturn REVISE 로 분리했다.)
- **패배** — 어두운 붉은 충격이 화면을 덮고 두 방향 균열선이 갈라진 뒤, 파편이 좌우로 흩어진 자리에서 **아래로 떨어진다**. 배너는 위에서 떨어져 기울었다가 자리를 잡는다. 결과 문구는 붉은색.
- **도망 성공** — 결과 배너가 아니라 기존 1200ms `fleeFx` 배너다. 청회색 가로 바람이 한 번 스치고 금빛 축포가 없다.
- **경기 무승부** — 청회색 두 선이 가운데에서 만나 멈춘다. 패배 균열·승리 폭발을 쓰지 않는다. 전투에는 이 갈래를 쓰지 않는다.
- 전부 **CSS/DOM 생성**이다. 새 이미지·폰트·라이브러리·외부 리소스가 0이다.

## 3. 난수 — 시드 스트림 불변 (확정)

파편의 각도·거리·가로 자리·지연은 전부 **인덱스 계산**이다. `rand()` 도 `Math.random` 도 부르지 않는다.
따라서 온라인 락스텝·시드 재현·AI vs AI 완주 결과에 영향이 0이다. `sim`·헤드리스에서는 `fxLive()` 가 false 라 **0ms 동기 처리**이고 기존 회귀 결과가 그대로다.

## 4. 종료 표현은 경기당 정확히 1회 (확정)

`gameOver` 안에서 중앙 발화한다(Venus 3.2). 전투 종료 시퀀스(`finishBattle`·`finishByCapture`)만 `ENDING_BATTLE` 로 그 발화를 잠시 막고, **남은 전투 메시지 재생 뒤에 붙일 배너를 자기가 고른다**.

| 종료 경로 | 재생되는 것 |
|---|---|
| 전투 KO·판정 (경기는 계속) | 전투 결과 배너 1회 (뷰어 기준 승/패 · 핫시트 중립) |
| **적 포획으로 전투만 끝남** (상대 말 생존) | 포획 갈래 배너 **정확히 1회**, 경기 종료 연출 0회, `S.phase` 는 `play` 유지 — 실제 `finishByCapture` 종점에서 확인 |
| **왕 제거·전멸로 전투가 곧 경기 종료** | **경기 결과 배너 1회만** — 전투 배너 + 경기 배너 직렬 중복 없음 |
| 왕 끝줄 도달 · 기권 · 상대 이탈 · sim 턴 상한 | 경기 결과 배너 1회 |
| 도망 성공 | 전투 중 **`fleeFx` 1200ms 단계는 그대로**이고 그 뒤 교환 선택으로 이어진다. 결과 배너 단계가 따로 붙지 않는다 |
| 적 포획 | 전투 중 **`captureFx` 1200ms 메시지 단계는 그대로**이고, 그 뒤 전투가 끝나며 **기존 `resultBanner` 2500ms 결과 단계**가 한 번 재생된다 (포획 갈래). 두 단계는 원래부터 별개이며 어느 쪽 상수도 바꾸지 않았다 |
| 도망 실패 | 결과 연출 0회 (전투 계속) |

경기 기준 플래그 `S.matchFxDone` 이 보장한다 — 게임 세대가 아니라 **경기**라서 `newGame` 이 새 상태를 만들 때 자연히 초기화되고, 재대전한 다음 경기에서도 다시 정확히 1회다.
경기 종료 배너는 **넣기 전에** 남아 있던 표시 큐를 걷는다(`fxReleaseAll`) — 연출이 자기를 넣고 자기를 지우는 순서가 생기지 않고, 끝난 경기의 턴 배너·접촉 배너가 뒤늦게 끼어들지 않는다.

## 5. 승패 규칙 무변경 (확정)

- **전투 판정 동률은 종전대로 방어자 승이다.** 전투 무승부 화면·문구·클래스를 만들지 않았다.
- 무승부 표기는 **경기 무승부(sim 턴 상한)** 에만 쓴다.
- 뷰어 문구 규약은 `resultBannerOf` 그대로다 — PVE·온라인은 뷰어 기준, **핫시트는 중립**(`P1 승리!`). 같은 기기의 두 사람에게 패배 화면을 씌우지 않는다. 관전(sim)도 중립이다.
- 승패 판정·수치·난수·상태 전이 코드는 손대지 않았다. 바뀐 것은 배너의 `cls` 갈래와 CSS 뿐이다.

## 6. 입력·접근성 (확정)

- **입력 해제와 경기 종료의 동기화**: 잠금은 종전과 같이 `fxLocked()`(`FX.cur ‖ FX.q ‖ MSGPLAYING`) 가 참인 동안이고, 결과 배너 하나가 끝나는 `resultBanner`(2500ms) 시점에 풀린다. 안쪽 효과를 1.1~1.2초로 잡아도 **잠금 길이는 바뀌지 않는다** — 추가 대기가 0인 이유가 이것이다. 경기 종료 배너는 큐를 먼저 비우고 자기 하나만 남기므로, 잠금이 풀리는 시각 = 그 배너가 끝나는 시각이고 그때 화면은 이미 `over` 결과판이다.
- 연출 중 입력 차단은 종전 `body.fx-lock` 계약 그대로다. **여기에 `#sidePanel`·`#boardInfo` 버튼을 추가로 넣었다** — 종전에는 결과 패널이 잠금 밖이라 종료 연출 중에도 `[로비로]`·`[다시 대전]` 이 눌렸다 (Venus F5·R10).
- `prefers-reduced-motion: reduce` 에서는 **움직임만** 끈다. 배너·파편·섬광 애니메이션이 멈추고 파편은 퍼진 위치에 정지하며, **결과 문구·부제·승패 색은 그대로 남는다** (실제 Chrome 에뮬레이션으로 확인 — 제목 색이 일반 렌더와 동일).
- 배너는 종전대로 `role="status" aria-live="polite"` 이고 파편 레이어는 `aria-hidden="true"` 다.
