S.phase 리터럴은 정확히 4개: menu(L4426) / setup(L685) / play(L1213) / over(L1642).

=== 3. Earth 러프용 화면 흐름안 (제안) ===
S0 타이틀 [신규 제안] — 현재 없음. 로고+[시작]. 러프에 넣어도 되나 "신규"로 표기 필요.
S1 로비(=현행 menu) [확정 존재] — 6개 진입점. 세로에서는 PVE/PVP/온라인/관전 4카드 + 난이도·접속코드는 카드 탭 후 2단계로 여는 것을 제안.
S2 로스터 선택 [확정 존재, setup 전반] — 20종(속성 4행 x 5) 카드 그리드, 6종 선택. 카드 탭 → 정보 팝업(192px 일러스트) → 선택.
S3 비공개 배치 [확정 존재, setup 후반] — 하단 트레이 14개 + 보드 자기 진영 탭. [무작위 배치]/[전체 회수]/[배치 완료].
S3a 핫시트 배치 교대 [확정 존재] — handoff() "🔄 기기를 넘기세요" 전체 차단 모달 (P0→P1, L1280).
S3b 온라인 매칭 대기 [확정 존재] — 배치 완료 후 사이드 패널 전체가 "🌐 매칭 대기 중…" + netStatus 배지 + [매칭 취소(배치 유지)]로 교체됨. 배지 문구 5단계: 서버 접속 중 → 매칭 요청 → 상대 대기 중 → 매칭 완료·상대 배치 수신 대기 → 시작 대기. 상대 배치 중에는 내 화면이 "🌐 상대 배치 중…"으로 마스킹됨.
S4 보드(play) [확정 존재] — 7x13 + 상단 phaseLabel + 하단 turnBar(탐색 / 🌀텔레포트 / 🌿회복 / [싸우지 않고 종료 — 조건부] / 기권 + 상태 배지).
S4a 턴 시작 배너 [확정 존재] — fxBanner. 핫시트는 handoff 확인 후 재생.
S5 전투 [확정 존재 — 단, 별도 화면이 아니라 #overlay 모달] — 이미 4카테고리 그리드 메뉴(⚔️싸우기/🎒가방/🔴포획/🏃도망가기) + 각 하위 패널(.bsub) + [← 뒤로] 구조다. 전투 이력은 <details>로 접혀 있다. 제안하신 "의도적 정보 오버레이/서랍"과 사실상 동일한 패턴이 이미 구현돼 있다.
S5a 비공개 출전 선택 [확정 존재] — "🔒 OO만 확인 (상대는 시선 회피)" 모달 (왕·동료 본체 vs 포획/예비 하수인).

=== 4. 핵심 함정 8건 ===
P1. 타이틀·재대전·로비복귀 화면이 아예 없다 (확정). over의 유일한 버튼 [처음으로]는 location.reload()다(L1098). 러프에 [재대전]/[로비로]를 그리면 그건 신규 구현 요구지 리스킨이 아니다 — 상태 초기화 경로가 따로 없다.
P2. #128 튜토리얼 정책과 재대전 루프가 충돌한다 (확정). 자동 표시는 **문서 로드당 1회**이고 저장소를 읽지 않는다(L4429). 즉 [처음으로](reload)는 튜토리얼을 1단계부터 다시 띄우고, 같은 페이지 안의 [재대전]은 띄우지 않는다. 겉보기 같은 두 출구가 다르게 동작하므로 러프에서 하나의 버튼처럼 그리면 안 된다.
P3. 보드 실측이 390x844를 거의 다 먹는다 (확정). 셀 52px·gap 2px → 보드만 **376 x 700 CSS px**. #board에는 반응형 규칙이 전혀 없다(존재하는 미디어쿼리는 max-width:480px의 전투 버튼 축소, max-height:700px의 로스터 일러스트 축소뿐). 세로 러프는 셀 44~46px(→334x622)을 전제하거나 보드 자체 스크롤을 전제해야 현실적이다. 말은 48px 안에 32px 아이콘 + 11px 정보행(속성 기호+현재 HP)이며, 정보행은 규칙 정보라 셀을 더 줄이면 재설계 대상이 된다.
P4. 진짜 세로 병목은 보드가 아니라 배치 화면이다 (확정). 로스터 20카드 + 트레이 14개 + 버튼 3개 + 보드가 동시에 필요하다. 배치는 "트레이 말 탭 → 보드 칸 탭"이라 트레이를 서랍에 숨기면 조작이 끊긴다. 러프는 S2/S3를 별도 2단계 화면으로 그리는 편이 안전하다.
P5. 전투는 이미 공용 오버레이다 — 별도 씬으로 그리면 안 된다 (확정). #overlay(z50) 하나를 handoff·비공개 출전·패키지 개봉·메모 피커·로스터 정보·온라인 "상대 선택 대기 중"이 전부 공유한다. 게다가 온라인은 모달 버튼을 **인덱스로 중계**하므로 버튼 구성·순서를 임의로 바꾸면 동기화가 깨진다. 레이어 순서도 고정이다: toasts 40 < tutHint 45 < overlay 50 < fxBanner 55 < tutorial 60, 그리고 body.fx-lock은 [기권]만 남기고 입력을 막는다. 보드 위에 상시 HUD를 올리면 fxBanner의 .nodim(보드를 보여주며 입력만 차단) 연출과 충돌한다.
P6. 상시 로그를 없애면 대체 없는 정보가 사라진다 (확정). #log는 최근 60줄을 보여주고 강제 전투·밀어내기·폭탄/함정 발동·정체 공개·AI 행동을 기록한다. 토스트는 2.2초, fxBanner는 일시적이며 addLog만 하고 토스트를 띄우지 않는 경로가 다수다. 서랍으로 옮기는 것 자체는 가능하지만 러프에 **미확인 표시(뱃지)** 가 없으면 규칙이 전제하는 정보가 조용히 사라진다.
P7. 은닉 정보는 레이아웃 선택이 아니라 렌더링 불변식이다 (확정). humanViewer()/visibleTo()로 상대 말은 ?, 숲 속 말은 인접해야 보이고, 추측 메모는 뷰어 전용 점선 표시이며, 온라인은 상대 가방·패키지·로스터·배치를 마스킹한다. 핫시트는 매 턴 handoff 전체 차단 모달과 "🔒 …만 확인"·도망 교환 후보 소유자 전용 강조로 정보를 격리한다. 따라서 러프에 **양측 말을 함께 보여주는 전역 HUD·트레이·로스터 바**를 그리면 미공개 하수인을 노출하는 규칙 변경이 된다. 전체 공개는 over(viewer=2)와 sim에만 존재한다.
P8. 이름이 같은 "턴 종료"가 두 개, 서로 다른 계층이다 (확정). (a) 보드 턴: 상시 종료 버튼이 없고(#114 CJ 선택 A) 할 일이 없으면 자동 종료된다. "싸우지 않고 종료"는 mainUsed && 강제전투 없음 && 텔레포트 중 아님 && 연출 잠금 아님 && 오버레이 닫힘 && 선택 전투 잔존일 때만 나타난다. (b) 전투 모달 안의 [턴 종료]는 4슬롯 전부 불가일 때만 뜨고 **전투 행동 1회만** 넘긴다(주 행동·턴당 전투 횟수 미소모). 세로 러프에서 하단 액션바를 하나로 통합하면 이 둘이 합쳐져 규칙이 바뀐다.
