# Digit Dual v0.4.3 하수인 외형 이미지 규격 분석

- 기준 버전: `v0.4.3`
- 문서 상태: 구현 전 분석안
- 작성일: 2026-09-07
- 대상: 하수인 20종(속성 4종 × 아키타입 5종)

## 1. 목적

현재 하수인은 전투 화면에서 속성별 색과 이모지 중심으로 표현되어, 같은 속성 안에 있는 서로 다른 하수인의 외형 차이가 충분히 드러나지 않는다.

이번 업데이트의 목적은 다음과 같다.

1. 하수인 20종에 서로 다른 고유 외형을 부여한다.
2. 하수인 선택 설명창에서 각 하수인의 외형을 충분한 크기로 보여준다.
3. 전투 화면의 단순 원형 표현을 캐릭터별 도트 이미지로 교체한다.
4. 작은 전투 이미지에서도 속성과 아키타입을 빠르게 구별할 수 있게 한다.

> 포켓몬스터는 각 캐릭터가 서로 다른 실루엣을 가지고 전투 화면에서 대치하는 구성의 참고 사례로만 사용한다. 기존 캐릭터의 외형, 색 조합, 이름이나 특징적인 요소를 복제하지 않고 Digit Dual의 독자적인 디자인을 제작한다.

## 2. 최종 권장 규격

| 용도 | 제작·납품 크기 | HTML 표시 크기 | 권장 형식 |
|---|---:|---:|---|
| 하수인 선택 설명창 | 512×512px | PC 192×192px | 원본 PNG + 웹용 WebP |
| 전투 도트 이미지 | 128×128px | 128×128px | 투명 PNG |
| 전투 도트 작업 그리드 | 64×64px | 2배 정수 확대 | PNG-8 권장 |

제작자에게 전달할 핵심 규격은 다음 두 가지다.

- 설명창용 일러스트: **512×512px**
- 전투용 도트 이미지: **128×128px**

전투용 이미지는 64×64 도트 그리드에서 제작한 후 최근접 보간 방식으로 2배 확대하여 128×128px로 납품한다.

## 3. 하수인 선택 설명창

### 3.1 권장 크기

- 원본 제작 크기: 512×512px
- PC 표시 크기: 192×192px
- 화면 높이가 부족한 환경의 표시 크기: 128~160px
- 캐릭터 주변 투명 안전 여백: 전체 캔버스의 약 8~10%

현재 설명창의 실제 콘텐츠 너비는 약 510px이다. 이미지를 240px 이상으로 표시하면 텍스트 영역이 좁아지고 설명창의 세로 길이가 늘어난다. 반대로 128px로 고정하면 새로 제작하는 고유 외형을 보여주기에 작다.

따라서 512×512px 원본을 제작하고 PC 화면에서 192×192px로 표시하는 구성이 이미지와 설명의 균형이 가장 좋다.

### 3.2 권장 배치

- 설명창 상단: 이미지와 이름·속성·아키타입·핵심 능력
- 설명창 하단: 스탯과 스킬 상세 설명
- 짧은 화면에서는 이미지 크기를 줄이고 필요한 경우 내부 스크롤 허용
- 모든 이미지의 발 위치와 캐릭터 기준선을 통일

### 3.3 파일 형식

- 보관 원본: 투명 배경 PNG 또는 레이어가 유지된 제작 원본
- HTML 배포본: 투명 WebP
- Unity 이전을 고려해 PNG 원본은 별도로 보존

## 4. 전투 도트 이미지

### 4.1 권장 크기

- 도트 작업 그리드: 64×64px
- 최종 파일 크기: 128×128px
- HTML 표시 크기: 128×128px
- 권장 전투 영역 높이: 200px

현재 전투 말은 88×88px 원형이고 전투 영역 높이는 약 180px이다. 하수인 20종의 얼굴, 체형과 아키타입 특징을 구별하려면 기존 크기보다 큰 표현이 필요하다.

64×64 작업 그리드는 20종의 차이를 표현할 수 있는 세부 묘사 공간을 제공한다. 이를 2배로 확대해 128×128px로 표시하면 도트 형태를 유지하면서 현재 전투 팝업에도 무리 없이 배치할 수 있다.

전투 영역은 200px로 확장하는 것을 권장한다. 220px 이상은 900px 높이의 PC 화면에서도 전투 팝업 전체가 길어지거나 스크롤될 가능성이 커진다.

### 4.2 HTML 표시 조건

```css
.battle-sprite {
  width: 128px;
  height: 128px;
  object-fit: contain;
  image-rendering: pixelated;
}
```

- 기존 원형 테두리와 원형 배경은 제거한다.
- 캐릭터 아래에는 작은 타원형 그림자만 적용해 위치를 표시한다.
- 확대·축소 시 흐려지지 않도록 정수 배율을 우선한다.
- 흔들림 등 전투 연출은 레이아웃 값을 변경하지 않고 `transform` 기반으로 처리한다.

## 5. 제작 방식 비교

| 방식 | 이미지 수 | 장점 | 문제점 | 판정 |
|---|---:|---|---|---|
| 설명창 이미지 하나를 모든 화면에서 축소 사용 | 20장 | 제작량이 가장 적음 | 전투 화면에서 외곽선과 표정이 뭉개지고 도트 감성이 약함 | 비권장 |
| 설명창 일러스트와 전투 도트를 각각 별도 설계 | 40장 | 용도별 품질이 가장 높음 | 두 이미지의 캐릭터 정체성이 달라질 수 있음 | 조건부 |
| 캐릭터 원형 디자인을 확정한 뒤 일러스트와 도트를 파생 | 40장 | 품질과 정체성을 함께 유지 | 최초 원형 디자인 확정 과정이 필요함 | **권장** |

권장 제작 순서는 다음과 같다.

1. 하수인 한 종의 원형 디자인을 확정한다.
2. 같은 디자인을 기반으로 512×512px 설명창 일러스트를 제작한다.
3. 같은 실루엣과 핵심 특징을 64×64 도트 그리드로 단순화한다.
4. 도트를 128×128px로 확대해 전투용 PNG로 납품한다.
5. 설명창 이미지와 전투 도트를 나란히 놓고 같은 캐릭터로 인식되는지 검사한다.

## 6. v0.4.3 권장 제작 범위

### 포함

- 설명창 일러스트 20장
- 전투용 정면 또는 3/4 방향 도트 20장
- 총 40개 이미지

### 보류

- 전투용 앞모습·뒷모습 동시 제작
- 전투 애니메이션 프레임
- 말판 위 모든 하수인의 개별 축소 이미지
- 로스터 카드용 별도 썸네일

앞모습과 뒷모습을 모두 제작하면 설명창 20장과 전투 이미지 40장으로 총 60장이 필요하다. 현재 HTML 전투에서는 화면 아래쪽 캐릭터가 항상 특정 플레이어의 하수인을 뜻하지 않으므로 뒷모습 적용 기준도 추가로 설계해야 한다.

따라서 v0.4.3에서는 정면 또는 3/4 방향 이미지 한 장으로 캐릭터 고유 외형을 먼저 확립하고, 뒷모습과 애니메이션은 Unity 전환 이후 재검토하는 것이 비용 대비 합리적이다.

## 7. 20종 외형 구별 원칙

색상만 바꾸는 방식은 현재의 속성별 표현 문제를 반복한다. 속성은 색상과 이펙트로, 아키타입은 실루엣과 체형으로 구별해야 한다.

| 아키타입 | 권장 실루엣 |
|---|---|
| 표준형 | 둥글고 균형 잡힌 체형 |
| 공격형 | 앞으로 뻗은 뿔·팔·무기형 기관, 공격적인 자세 |
| 방어형 | 낮고 넓은 체형, 갑옷·방패 같은 구조 |
| 속공형 | 가늘고 긴 체형, 날개·꼬리·다리 강조 |
| 지속형 | 부유형·망토형·촉수형, 지속 효과를 연상시키는 구조 |

### 검수 기준

- 색상을 제거하고 흑백 실루엣으로 보아도 20종이 구별되어야 한다.
- 128×128px 전투 크기에서도 얼굴 방향과 핵심 특징이 보여야 한다.
- 같은 하수인의 설명창 일러스트와 전투 도트가 동일한 캐릭터로 인식되어야 한다.
- 캐릭터별 크기 차이가 있더라도 발 위치와 시각적 중심은 일관되어야 한다.
- 기존 유명 캐릭터의 실루엣이나 특징적인 색 배치를 연상시키는 디자인은 제외한다.

## 8. 권장 파일 구조

```text
demo/
├─ index.html
└─ assets/
   └─ minions/
      ├─ fire_std/
      │  ├─ portrait.webp
      │  └─ battle.png
      ├─ fire_atk/
      │  ├─ portrait.webp
      │  └─ battle.png
      └─ ...
```

이미지 40장을 HTML 안에 직접 삽입하면 파일 크기가 크게 증가하고 이미지 교체와 버전 관리가 어려워진다. 외부 상대경로 에셋으로 분리하는 방식을 권장한다.

이 방식은 인터넷 서버 없이도 폴더 단위로 실행할 수 있다. 다만 `index.html` 파일 하나만 복사하는 완전 단일 파일 구조는 유지할 수 없으므로 구현 전 해당 원칙 변경을 명시적으로 확정해야 한다.

## 9. 구현 전 확정 사항

1. 단일 HTML 원칙을 완화하고 `demo/assets/` 폴더를 사용하는지 결정
2. v0.4.3에서는 전투 방향 한 종만 제작하는지 결정
3. 말판과 로스터 카드까지 개별 외형을 노출할지 범위 결정
4. 실제 아트 제작 담당과 제작 방식 결정
5. 캐릭터별 원형 디자인 승인 절차 결정

## 10. 최종 결론

v0.4.3의 최종 권장 규격은 다음과 같다.

- 설명창: **512×512px 제작, PC에서 192×192px 표시**
- 전투: **64×64px 도트 작업, 128×128px 파일로 납품 및 표시**
- 전투 영역: **높이 200px**
- 제작 범위: **설명창 20장 + 전투 방향 한 종 20장 = 총 40장**
- 제작 원칙: **캐릭터 원형 디자인 하나에서 설명창 일러스트와 전투 도트를 함께 파생**
- 구현 구조: **HTML 직접 삽입보다 `demo/assets/minions/` 외부 상대경로 사용 권장**

이 규격은 현재 HTML 팝업의 가로·세로 제약 안에서 외형의 구별 가능성, 가독성, 제작 비용과 추후 Unity 전환 가능성을 균형 있게 반영한 안이다.
