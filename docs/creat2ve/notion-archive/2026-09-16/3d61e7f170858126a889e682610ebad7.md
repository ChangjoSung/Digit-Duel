## 1. 기준과 분석 결론
현재 정식 버전은 [v0.4.5](https://github.com/ChangjoSung/Digit-Duel/releases/tag/v0.4.5)입니다. dev/origin/dev는 `39f022293008d352e4709762af07e42d63fb557e`, main/origin/main 및 v0.4.5 태그 대상은 `39a3af12a9b4dd5e8f82776f0f0d21994034387c`, 제품 blob은 `61a3ce3e5927697ea80ec8ebd379ffb98ebfdb92`입니다. 이번에는 제품·테스트·아트·배포를 변경하지 않았습니다.
- 기술은 23개 정의, 정상 배정·획득 가능한 고유 기술은 22개입니다. 회피 자세는 미배정 정의이며 삭제 여부는 미결정입니다.
- 공용 하수인은 독립 종 목록 없이 숲 포획 시 공통 수치와 속성별 표준형 기술/아트를 사용합니다. 선택 로스터 20종 확대와 구분해 기획해야 합니다.
- 하수인 탐색은 원천 이벤트 절반이 동일한 CD 초기화로 귀결됩니다. 말별 보상 손실과 사람 플레이 자료 없이 새 확률·밸런스를 확정할 수 없습니다.
- 튜토리얼 열람 상태가 서버에서 PC 간 공유된다는 원인은 입증되지 않았습니다. 코드에는 브라우저 localStorage와 현재 로드 플래그가 있습니다.
- 탐색 모달의 확인/유지/포기 후 자동 종료를 다시 평가하지 않는 정적 경로를 발견했습니다. 현장 재현으로 지연 구간과 원인을 확정해야 합니다.
- 보호막은 현재 합산 대신 큰 잔량을 유지합니다. CJ가 요청한 합산 방향을 신규 규칙 변경으로 등록했고 상한·지속 시간은 별도 세부 정책입니다.
- 함정에 걸린 하수인은 UI 선택에서 이미 제외되지만 안내 문구와 실행 함수의 공통 상태 재검사가 빠져 있습니다.
- 승패 배너/패자 KO 표현은 기존에 있습니다. 새 요청은 세로 UI와 연동한 승패 연출 강화로 등록합니다.

### #125 \[System\] 연출 템포 단축 — 2초 구간을 1.2초로

### #128 \[Bug\] 최초 튜토리얼 표시를 PC·브라우저별로 검증 및 수정
CJ 관찰: 한 PC가 튜토리얼을 넘기면 다른 PC에서도 최초 튜토리얼이 안 뜬다. 현재 구현은 localStorage의 tutorialSeen과 메모리 seenThisLoad를 사용한다. 서버 공유 여부를 단정할 근거는 현재 없으며 관찰된 현상의 원인을 재현해야 한다.
- 서로 다른 PC/새 프로필/같은 프로필 재방문으로 현재 현상을 재현하고 원인을 기록한다.
- A에서 완료해도 처음 접속한 B의 자동 튜토리얼 표시에 영향이 없다.
- B 완료 후 B 재방문은 생략하고 수동 다시 보기는 항상 가능하다.
- HTTP/HTTPS·호스트/포트 변경과 저장소 차단 상태를 구분해 검증한다.
### #129 \[Bug\] 수풀 탐색 행동 완료 후 불필요한 턴 종료 지연 제거
현재 자동 종료는 FX 잠금·모달·선택 전투·강제 접촉 등 상태를 확인한다. BAL.fx.autoEndGrace와 watchdog는 각각1000ms다. 어떤 지연이 실제 원인인지는 재현으로 구분해야 하며 탐색 보상 선택 중 턴을 넘겨서는 안 된다. 추가 정적 분석: close()는 모달만 숨기고 render/autoEndCheck를 호출하지 않는다(3015행). 탐색의 확인·유지·포기 경로가 close만 호출하면 모달 종료 후 자동 종료 재평가가 다음 입력까지 누락될 수 있다. 실행 재현 전에는 코드상 원인 후보로 기록한다.
- 확인·유지·포기·교체·포획 결과 모달을 닫은 뒤 추가 클릭 없이 턴 종료 조건이 재평가된다.
- 아이템/볼/버프/포획/기술 교체·유지/획득 불가 각각의 완료 시점을 정의한다.
- 완료 직후 추가 고정 유예 없이 종료하며 두 번 종료하거나 다음 턴 행동을 소비하지 않는다.
- 선택 전투·강제 접촉·보상 선택 모달은 끝나기 전에 자동 종료되지 않는다.
- 사람/AI/온라인 양측에서 동일 결과와 실제 기본 연출 시간의 지연을 검증한다.
### #130 \[Bug\] 연속 보호막 효과가 합산되도록 규칙 변경
현재 보호막 부여는 Math.max(기존 보호막, 새 보호막)를 사용하며 코드에 합산 금지 의도가 있다. 따라서 CJ의 합산 요청은 기존 규칙을 바꾸는 요청으로 관리한다. 전투 시작/종료 초기화, 흡수 후 남은 보호막, 유형별 보호막과 AI 판단이 영향받는다.
- 모든 보호막 생성·소모·초기화 경로와 표시/AI 평가를 목록화한다.
- 같은/다른 보호막 연속 사용과 부분 소모 후 재사용이 승인된 합산 규칙대로 동작한다.
- 상한·지속 시간·전투 종료 초기화의 세부 정책을 기획에서 명시한다.
- 보호막을 먼저 소모하고 HP가 감소하며 양측 온라인 수치·표시가 일치한다.
### #131 \[System\] 함정에 걸린 하수인의 텔레포트 선택 차단·안내
CJ 추가 요구: 함정에 걸린 하수인을 텔레포트 대상으로 선택할 수 없게 하고 지정 안내 문구를 표시한다. 현행 UI는 양 끝점 모두 immobile===0을 검사해 조용히 거부한다(1316·1318행). doTeleportSwap의 공통 실행부에는 상태 재검사가 없다(1432행). 안내 문구와 실행 직전 양 끝점 가드를 보완할 항목이며 정상 UI의 불법 교환을 실행 재현한 것은 아니다.
- 함정에 걸린 하수인은 텔레포트 첫/둘째 대상 선택과 실행 모두 거부된다.
- 거부 시 지정 문구가 보이며 선택/위치/주 행동/텔레포트 사용 지표가 잘못 소비되지 않는다.
- 정상 하수인과 상태 해제 후 하수인의 텔레포트는 기존대로 가능하다.
- AI·온라인 실행 경로에도 동일 제한을 적용하며 상대 비공개 정보를 노출하지 않는다.
#131의 정확한 안내 문구는 **함정에 걸린 하수인은 텔레포트를 사용할 수 없습니다** 입니다. 함정 말 자체의 텔레포트/밀기/도망 교환을 함께 금지하는 요청으로 넓히지 않습니다. 거부 시 좌표·HP·회복 자세·주 행동·사용 지표·강제 접촉·이벤트·난수 상태를 소비하지 않는 것이 후속 검증 기준입니다.
## 7. 외부망 후보: ChatGPT Sites와 ngrok
CJ가 말한 gpt Web 서버는 ChatGPT Sites입니다. 공식 문서는 웹사이트·웹앱·게임 호스팅과 HTTP/HTTPS/WebSocket, D1/R2 저장소를 지원한다고 명시합니다. 공식 주소 예시는 [goblin-tales.openai.chatgpt.site](http://goblin-tales.openai.chatgpt.site)입니다. 다만 일부 실행/호스팅 방식은 지원하지 않으므로 현재 Node ws 프로세스와 메모리 매칭 구조를 그대로 실행할 수 있는지는 별도 호환성 확인이 필요합니다. [Sites 공식 문서](https://learn.chatgpt.com/docs/sites)
ngrok 무료 플랜은 개발 도메인1개와 최대 온라인 endpoint3개를 구분합니다. 월 송신1GB·HTTP2만 요청 한도, 무료 HTML 경고 페이지가 있으며 HTTP endpoint에서 WebSocket을 지원합니다. 한 도메인이라는 뜻은 플레이어가1명이라는 뜻이 아닙니다. PC 서버와 에이전트가 계속 실행돼야 합니다. [무료 한도](https://ngrok.com/docs/pricing-limits/free-plan-limits), [WebSocket](https://ngrok.com/docs/using-ngrok-with/websockets)
현재 서버는 비권위 릴레이이며 Host/Origin·접속 코드·연결 제한을 적용합니다. 클라이언트에도 공개 주소 차단·기본8080 포트·페이지 스킴에 따른 WS 주소 생성이 있어 서버만 바꾸어서는 외부망 PVP가 동작하지 않습니다(demo/index.html 3491·3544\~3580·3620). 같은 PC의 프록시를 거치면 실제 원격 사용자가 같은 loopback 주소로 집계돼 IP별 제한을 공유할 수 있습니다. 터널 연결만으로 현행 보안 검사·매칭·재연결까지 검증됐다고 볼 수 없습니다. 외부망 후보 선택, 계정별 실제 한도, 코드 이식 필요 여부, 프록시 주소 신뢰/속도 제한, 서로 다른 외부망 두 기기 매칭을 #127 후속 확인으로 남깁니다. 이번에는 서버·터널을 열거나 Sites에 배포하지 않았습니다.
Claude Jupiter 최종 분석까지 수령했습니다. PD 대조에서 peer 검사→Host→Origin 순서를 확인했지만, Sites의 실제 peer 주소는 미검증이며 Host 허용이 임의 Origin 허용을 뜻하지 않는다고 한정했습니다. 프록시가 Host를 보존하는 같은 origin 구성과 Host 재작성/별도 프런트엔드 구성의 차이를 후속 검증합니다. extraHosts는 확장점이며 전체 외부망 전환이 설정 배선만으로 끝난다는 보장은 아닙니다. 세부 대조는 [Issue127](https://github.com/ChangjoSung/Digit-Duel/issues/127)의 최종 PD 기록을 따릅니다.
