# 필수 QA 운영 원칙 — 2026-09-16 CJ 지시

Saturn은 변경 범위의 필수 검증만 수행한다. v0.4.10 때처럼 네트워크 동기화를 브라우저에서 반복 조작하며 과도한 시간·토큰을 쓰지 않는다.

- 먼저 Issue 완료 조건과 변경 위험에 맞는 최소 검증 목록을 정한다.
- 기존 자동 테스트·헤드리스 회귀와 코드 대조를 우선한다. 같은 시나리오를 여러 도구로 중복 확인하지 않는다.
- Computer Use로 직접 클릭하는 브라우저 검증은 자동 검사로 확인할 수 없는 시각·입력 문제에만 제한한다. 필요한 대표 흐름만 한 번 확인한다.
- 네트워크 코드·동기화 계약 변경 또는 구체적 회귀 근거가 없으면 네트워크 수동 매트릭스를 반복하지 않는다. 필요한 경우에도 자동 프로토콜 검증과 대표 경계 사례를 우선한다.
- 통과한 검사는 관련 수정·실패·새 위험이 생겼을 때만 다시 실행한다. 이유 없는 전체 재실행·장시간 AI 시뮬레이션·기존 릴리스 전수 재검증은 하지 않는다.
- 필수 CI와 변경에 직접 필요한 회귀는 생략하지 않는다. 검사 수를 줄이려고 기대값을 구현에 맞춰 낮추지 않는다.
- Saturn은 읽기 전용이며 제품·테스트·보고서 파일을 수정하지 않는다. 판정과 근거는 메시지로 PD에게 전달하고 PD가 기록한다.
- 보고에는 실행한 검사·결과·미검증 한계를 간결히 적는다. 미검증 범위를 PASS로 주장하지 않는다.

#233 적용: 전투 계산·순서·상태·방어막·초기화의 결정론적 경계 검사와 영향받은 기존 헤드리스 회귀, Saturn의 독립 코드/AC 대조, PR 필수 CI. 수동 네트워크 플레이·전체 밸런스 시뮬레이션은 기본 검증 대상이 아니다.

## 토큰 절감 실행 계약 — 2026-09-16 CJ 승인

- 적용 대상은 PD·구현 부서·Saturn 모두다. 역할·독립 QA·필수 CI는 유지한다. PD 기본 모델은 Astra low를 유지한다.
- Dispatch에는 수정 파일 범위, 필요한 검사 명령, 명령별 최대 실행 횟수(기본 1회), 중단 조건을 명시한다. 작업 완료 보고는 판정·파일·검사·남은 문제·증거 링크 5항목, 기본 10줄 이내다.
- 검사는 출력과 종료 코드를 같은 실행에서 수집한다. 종료 코드 확인만을 위한 재실행, 통과 뒤 3회/5회 반복, 여러 시드 전수 실행은 금지한다.
- 실패를 수정한 경우 해당 검사만 다시 실행하고 이유·횟수를 기록한다. 검사 확대가 필요하면 근거를 PD에게 보고하고 범위를 조정한 뒤 진행한다. 정적 점검 지시는 실행 테스트 승인으로 해석하지 않는다.
- 반복 제한 위반은 발견 즉시 해당 작업을 interrupt하고 변경물·실행 횟수를 회수한다. 같은 Worker가 다시 위반하면 즉시 후속 작업에 재사용하지 않고 보고 후 종료한다.
- 정상 진행 중에는 완료 이벤트 대기 하나만 유지한다. 대기 중 별도의 worker-read·terminal-read·상태 조회를 겹치지 않는다. 오류·질문·시작 확인 실패 또는 연속 3회 빈 대기 때만 제한된 진단을 한다.
- PD는 구조화 응답에서 필요한 상태·판정·파일명만 추출한다. 전체 로그·전체 문서·전체 도구 설명을 다시 읽지 않고, 오류 주변과 변경 부분만 읽는다.
- 같은 원인의 CI 실패는 관련 호출부를 정적으로 함께 점검하고 수정분을 묶어 push한다. CI는 최신 커밋 결과를 재사용하며 수동 재실행은 실제 실패 근거가 있을 때만 한다.
- 운영 문서는 현재 상태를 치환하고 상세 이력은 링크로 남긴다. 이미 읽은 스킬·가이드는 버전 변경이나 새 기능 진입이 없으면 다시 읽지 않는다.
- 작업 시작·종료의 실제 사용량 차이를 기록한다. 입력·캐시 입력·출력·추론을 구분하고, Worker와 PD를 별도 집계한다. 측정 전 절감률이나 구독 한도 절감을 주장하지 않는다.
- 이 계약은 운영 절차다. 자동 실행 차단 기능을 구현했다는 뜻은 아니며, 범용 Creat2ve 원본·계정 전역 설정은 변경하지 않는다.
