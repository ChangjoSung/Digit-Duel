6. 두 플레이어 시점과 실제 Studio에서 검증하고 Saturn에 독립 QA를 요청합니다.

### 이미지 ID와 업로드

현행 [upload_assets.js](../../roblox/tools/upload_assets.js)는 루트 manifest를 전부 **PNG Decal**로 처리합니다.

- 읽기 전용 사전 확인 명령: `node roblox/tools/upload_assets.js --dry`
- 인계 시 결과: **기존60개 재사용 / 신규9개 대상**. 이후 다른 작업자가 올렸으면 현재 결과를 따르세요.
- 신규 키는 `token64_king`, `token128_king` 방식이며 ally/bomb/trap도 동일합니다. unknown은 `token64_unknown`만 있습니다.
- 기존 하수인 키 `icon_<el>_<arch>`, `battle_<el>_<arch>`, `portrait_<el>_<arch>`는 보존하세요.
- **FBX·OBJ·MTL이나 로비 혼합 manifest를 이 업로더에 그대로 넣지 마세요.** 로비 이미지도 현재 루트69행 자동 업로드 대상에는 없습니다.
- `roblox/assets/asset-ids.json`과 `roblox/src/shared/AssetIds.luau`는 기존 PNG 업로더의 출력입니다. 모델 ID를 여기에 수동으로 섞으면 다음 실행에서 덮일 수 있으므로 분리하거나 생성 도구와 소비자를 함께 정합성 있게 관리하세요.
- 외부 업로드는 기존 승인된 계정·경험·권한을 확인하고 진행하세요. 자격증명이 없으면 그 작업만 미완료로 보고하고 나머지 로컬 작업을 이어가세요.
- API 키를 MD·코드·Git·로그에 남기지 마세요. 경험의 공개 범위 변경·배포까지 자동으로 확장하지 마세요.
- 업로드/검수 지연/실패 때 기존 폴백이 동작해야 합니다. 가짜 rbxassetid를 발급 완료처럼 기록하지 마세요.

## 5. 2D 표시 계약

- 아이콘은 native32 최근접 출력입니다. `ResampleMode=Pixelated`와 정수 배율 표시를 유지하고, 흐림 보간·강제 비율 왜곡을 피하세요.
- 신규 토큰9장은 **흰 RGB255 + 알파**입니다. `ImageColor3`로 팀 색을 적용합니다.
- 기존 하수인60PNG는 **tint=no**입니다. 원소 색을 보존하고 팀 색은 칩/테두리 등 별도 표시부로 표현합니다.
- 왕·동료·폭탄·덫은 보드64 / 전투128을 쓰고, unknown64는 정체를 모르는 상태에 씁니다.
- 같은 기호를 확정 표시와 사용자가 직접 고른 추측 메모에 재사용합니다. 메모용 자산을 별도로 만들지 마세요.
- 추측은 점선·불투명도0.5, 확정은 실선·불투명입니다. **실제 정답으로 추측 메모를 자동 선택하지 마세요.**
- HP는 기존 known 판정을 통과한 하수인·동료·왕만 아이콘 아래 현재 숫자 한 줄. 폭탄·덫·미공개 말의 HP는 표시하지 않습니다.
- 텍스트는 런타임으로 렌더하고 그림에 굽지 않습니다.
- 메모 등의 미구현 기능 전체를 이번 표시 교체에 묶어 새로 만들지는 마세요. 구현된 화면의 기호를 통일하고 미구현 범위는 구분해 보고하세요.

## 6. 가장 중요한 부분 — 공통 가림 모델과 정보 은닉

**상대에게 보이되 무엇인지 모르는 말은 전부 같은 덮개여야 합니다.**

| 서버가 뷰어에게 허용한 상태 | 표시 |
|---|---|
| 존재 자체를 보지 못함 | 모델·덮개·아이콘·클릭 대상도 생성하지 않음 |
| 존재는 보이나 known=false | 동일 unknown 메시/unknown64만 사용 |
| 내 말 또는 공개된 상대 말 등 known=true | 그 뷰어에게 공개된 실제 외형 |
| 종료 후 전체 공개 등 기존 예외 | 현행 서버 공개 규칙에 따름. 아트 적용으로 공개 시점을 바꾸지 않음 |

- **서버의 공용 Workspace에 실제 숨은 유닛을 넣고 덮개로 가리는 방식은 안 됩니다.** 가린 본체도 상대에게 복제되면 정체가 드러납니다.
- 3D 말은 서버가 필터링한 뷰를 바탕으로 각 클라이언트에 필요한 표현만 구성해야 합니다. 이는 적용 방향이며 룰 엔진을 클라이언트로 옮기라는 뜻이 아닙니다.
- 다른 플레이어/관전자에게도 각각 허용된 정보만 주어야 합니다. 기존에 없는 관전 공개 정책을 새로 정하지 마세요.
- unknown에는 종별 크기·방향·이름·Attributes·HP·속성·무기·애니메이션·텍스처 경로 차이가 없어야 합니다.
- 숨은 실제 종류에 따라 이미지/모델 요청·툴팁·접근성 텍스트가 달라지지 않아야 합니다.
- 사용자 메모는 추측임을 분리 표시하고 공통 덮개를 정답 형태로 바꾸지 않습니다.

### 기존 순번 ID 누출 — 아직 수정되지 않음

인계 시 코드에서 다음을 확인했습니다:

1. Engine.nextId는1에서 시작합니다.
2. 소유자별로 하수인6 → 폭탄3 → 동료2 → 덫2 → 왕1의 고정 순서로 mkPiece를 호출합니다.
3. mkPiece는 순번 ID를 부여하고 Views는 known=false에도 원본 p.id를 전송합니다.
4. 따라서 type/rosterId/HP를 지워도 ID로 종류를 추정할 수 있습니다. 최초 왕 ID14/28이 예입니다.

**외형 교체만으로 정보 은닉 완료라고 보고하지 마세요.**
현재 코드에서 재확인하고, 종류와 연결할 수 없는 뷰어용 opaque ID 등 구체적 방안을 소관 구현자와 검토하세요.
단순히 숫자를 일정량 더하거나 이름만 바꾸는 것으로는 해결되지 않습니다.
ID를 바꾼다면 보드·전투·pending·행동 요청·메모·공개 전후의 참조 일관성과 서버 권한 검증까지 회귀 검수해야 합니다.
이 문서는 별도 대규모 서버 개편을 포괄 승인하지 않습니다. 소관/승인 확장이 필요하면 Mercury에 인계하고, 이 항목은 미해결로 분명히 남기세요.

### 가림 메시 배치 규격

- 파일: `roblox/assets/tokens/meshes/unknown.fbx` (OBJ는 대안, 중복 배치 금지)
- X×Y×Z **0.44×0.42×0.44stud**, Y-up, **132정점 / 260tri**
- 피벗 바닥 중앙(0,0,0). 보드 윗면 Y3.2에 바닥을 두면 윗끝 Y3.62.
- 0.6셀에서 좌우 여백0.08. 중심 재정렬 임포트라면 바닥 대비 중심 Y0.21을 확인.
- 흰색 불투명 단일 재질. 별도 이미지 텍스처 없이 `MeshPart.Color`에 Color3 팀 색 적용.
- [보드 적합성 프리뷰](../art/roblox-v0.5.0/review/unknown-board-fit.png)는 크기 비교용입니다. 내 말까지 가리는 게임 규칙이 아닙니다.
